## 1. Basics & Type System

### Q1. What is the difference between `let` and `var`? `[Fundamental]`
`let` declares a constant that can't be changed after it is set, while `var` declares a variable that can change. For a class instance, `let` only locks the reference, so the object's own `var` properties can still be modified.

```swift
let maxUsers = 10
// maxUsers = 20        // ❌ error: cannot assign to a 'let' constant

var score = 0
score += 5              // ✅ fine
```

**Follow-ups:**
- **Can a `let` constant be declared without a value?** Yes, as long as it is assigned exactly once before it is used, for example in each branch of an `if`.
- **If a class instance is stored in a `let`, can you change its properties?** Yes, its `var` properties can still change; you just can't make the constant point to a different instance.
- **Why prefer `let` by default?** It shows intent, prevents accidental changes, and helps the compiler optimize; Xcode even warns when a `var` is never changed.

### Q2. What are value types and reference types? Give examples. `[Fundamental]`
A value type is copied when you assign it or pass it, so each variable has its own independent copy; a reference type is shared, so all variables point to the same single instance. Structs, enums, tuples, `Int`, `String`, `Array`, and `Dictionary` are value types, while classes, actors, and closures are reference types.

```swift
var a = [1, 2]          // Array is a value type
var b = a
b.append(3)
print(a)                // [1, 2]  (a is unchanged)
```

**Follow-ups:**
- **Is `String` a value type or a reference type?** It's a value type (a struct), even though it shares its storage internally until you change it (copy-on-write).
- **What happens when a struct contains a class property?** The struct is copied, but both copies point to the same class instance, so changes made through that property are shared.
- **Which is safer for multithreading?** Value types, because each thread works on its own copy, so there is no shared mutable state to protect.

### Q3. What are the differences between a struct and a class? `[Fundamental]`
A struct is a value type that is copied, while a class is a reference type that is shared. Classes also support inheritance, `deinit`, and identity checks with `===`, and they are managed by ARC; structs get a free memberwise initializer and need `mutating` to change their own properties.

```swift
struct PointS { var x = 0 }
class PointC { var x = 0 }

var s1 = PointS(); var s2 = s1; s2.x = 5    // s1.x is still 0 (copy)
let c1 = PointC(); let c2 = c1; c2.x = 5    // c1.x is now 5 (shared)
```

**Follow-ups:**
- **Can a struct conform to protocols?** Yes. Structs get polymorphism through protocols and extensions instead of inheritance.
- **Why can you use `===` on classes but not on structs?** `===` checks whether two references point to the same instance, and structs have no identity, only values.
- **Can a struct have a `deinit`?** Only a noncopyable (`~Copyable`) struct; normal structs can't.

### Q4. When would you choose a class over a struct? `[Senior]`
I choose a class when I need identity, shared mutable state that several owners observe, inheritance or Objective-C interop, or a `deinit` for cleanup. Otherwise I start with a struct, and if the shared state is accessed from multiple threads I consider an actor instead.

```swift
// Shared, observed by many screens, needs identity → class
final class SessionManager {
    static let shared = SessionManager()
    var currentUser: User?
}

// Plain data → struct
struct User { let id: Int; var name: String }
```

**Follow-ups:**
- **Why mark classes `final` by default?** It prevents unplanned subclassing and lets the compiler use faster static dispatch.
- **When would you pick an actor instead of a class?** When the shared mutable state is accessed from several concurrent tasks and needs protection from data races.
- **Why are SwiftUI view models usually classes?** SwiftUI needs to observe one shared instance over time, which `@Observable` and `ObservableObject` classes provide.

### Q5. Are value types always stored on the stack? `[Senior]`
No. Value types can live on the heap when they are stored inside a class, captured by an escaping closure, boxed inside an `any Protocol`, or used in an `indirect enum`. What matters about a value type is its copy behavior, not where it is stored.

```swift
final class Holder {
    var point = CGPoint(x: 1, y: 2)   // struct, but stored on the heap inside the class
}

let items = [1, 2, 3]   // Array is a struct, but its element buffer lives on the heap
```

**Follow-ups:**
- **Are class instances ever stored on the stack?** By default they live on the heap, but the optimizer can sometimes put an object on the stack if it never escapes the function.
- **Why does stack vs heap matter for performance?** A heap allocation needs bookkeeping and reference counting, while a stack allocation is just moving a pointer.
- **Does `any Protocol` cause a heap allocation?** It can: if the value is bigger than the existential's small inline buffer (three words), it is boxed on the heap.

### Q6. What is copy-on-write (CoW)? How would you implement it for a custom type? `[Senior]`
Copy-on-write means copies share the same storage until one of them is changed, and only then is the real copy made. `Array`, `String`, `Dictionary`, and `Set` do this automatically; for a custom type you wrap a class and copy it only when `isKnownUniquelyReferenced` says it is shared.

```swift
final class Storage { var values: [Int]; init(_ v: [Int]) { values = v } }

struct CoWList {
    private var storage = Storage([])

    mutating func append(_ value: Int) {
        if !isKnownUniquelyReferenced(&storage) {
            storage = Storage(storage.values)   // copy only when shared
        }
        storage.values.append(value)
    }
}
```

**Follow-ups:**
- **Does a custom struct get copy-on-write automatically?** No. Only its stored properties that already use CoW, like arrays, behave that way.
- **What does `isKnownUniquelyReferenced` do?** It returns `true` if only one strong reference to the object exists, which means it is safe to change it in place.
- **Does CoW make a type thread-safe?** No. It only avoids unnecessary copies; changing the same variable from two threads still needs protection.

### Q7. Why do struct methods need the `mutating` keyword? `[Fundamental]`
Inside a struct method, `self` is read-only by default, so `mutating` is needed to allow the method to change its properties. It also means you can't call that method on a `let` constant.

```swift
struct Counter {
    var count = 0
    mutating func increment() { count += 1 }
}

var c = Counter()
c.increment()           // ✅
let fixed = Counter()
// fixed.increment()    // ❌ cannot use mutating member on a 'let' constant
```

**Follow-ups:**
- **Can a `mutating` method replace `self` completely?** Yes, for example `self = Counter()` inside a mutating method.
- **Do class methods need `mutating`?** No. Classes are reference types, so their methods can change properties freely.
- **Can a protocol requirement be `mutating`?** Yes. That lets structs implement it as a mutating method, while classes implement it without the keyword.

### Q8. How do `inout` parameters work? `[Senior]`
An `inout` parameter lets a function change a variable passed in by the caller: the value is copied in, modified, and written back when the function returns. You pass it with `&`, and you can't pass a constant or a literal.

```swift
func double(_ number: inout Int) {
    number *= 2
}

var value = 5
double(&value)
print(value)    // 10
```

**Follow-ups:**
- **Can an escaping closure capture an `inout` parameter?** No, because the `inout` value is only valid until the function returns.
- **How is `inout` different from passing a class instance?** A class already shares the object, but `inout` lets you replace the caller's variable itself, even for value types.
- **Can you pass a computed property as `inout`?** Yes. Swift calls the getter, lets the function change the value, then calls the setter at the end.

### Q9. What is the Law of Exclusivity? `[Lead/Expert]`
The Law of Exclusivity says a variable can't be written to while another access to the same variable is still in progress. Swift checks this at compile time where it can and at runtime otherwise, which prevents a whole class of memory and concurrency bugs.

```swift
var count = 1
func increment(_ a: inout Int, by b: inout Int) { a += b }

increment(&count, by: &count)   // ❌ Overlapping accesses to 'count'
```

**Follow-ups:**
- **Is exclusivity checked in release builds?** Yes. Since Swift 5, the runtime checks are on in release builds too.
- **How do you fix the overlapping access in the example?** Copy the value into a temporary variable first, so the two accesses don't overlap.
- **Why does Swift need this rule?** It lets the compiler assume a variable isn't being changed from two places at once, which enables optimizations and memory safety.

### Q10. When would you use a tuple vs a struct? `[Fundamental]`
I use a tuple for a small, temporary grouping of values, like returning two values from a private function. I use a struct when the data has a real meaning in the app, is passed across APIs, needs methods, or must conform to protocols, because tuples can't conform to protocols.

```swift
// Tuple: quick, local
func minMax(_ a: [Int]) -> (min: Int, max: Int) { (a.min()!, a.max()!) }

// Struct: meaningful model
struct Range: Codable { let min: Int; let max: Int }
```

**Follow-ups:**
- **Can you compare two tuples with `==`?** Yes, for tuples of up to six elements whose types are `Equatable`, but tuples still can't formally conform to protocols.
- **Can tuple elements have names?** Yes, for example `(min: Int, max: Int)`, and you access them as `result.min`.
- **Why avoid tuples in public APIs?** You can't add methods, conformances, or documentation to them, and changing them breaks callers, while a struct can grow over time.

### Q11. What is the difference between `Any`, `AnyObject`, and `AnyHashable`? `[Fundamental]`
`Any` can hold a value of any type at all, `AnyObject` can hold only class instances, and `AnyHashable` is a wrapper that holds any `Hashable` value so you can mix different key types in one dictionary.

```swift
let anything: [Any] = [1, "two", 3.0]
let objects: [AnyObject] = [NSString(), UIView()]
let mixedKeys: [AnyHashable: String] = [1: "int key", "a": "string key"]
```

**Follow-ups:**
- **Why should you avoid `Any`?** You lose type safety and have to cast at runtime, which moves errors from compile time to runtime.
- **What is `AnyClass`?** It is the type of any class type itself, an alias for `AnyObject.Type`.
- **What is `AnyHashable` useful for in practice?** Mixing different `Hashable` types as keys, like in `userInfo` dictionaries or SwiftUI's `id` values.

### Q12. Explain `is`, `as`, `as?`, and `as!`. `[Fundamental]`
`is` checks a type and returns a `Bool`; `as` is a safe cast the compiler guarantees, like upcasting or bridging; `as?` tries a downcast and returns an optional (`nil` if it fails); and `as!` forces a downcast and crashes if it fails.

```swift
class Animal {}
class Dog: Animal { func bark() { print("Woof") } }

let pet: Animal = Dog()

pet is Dog                          // true
let base = Dog() as Animal          // upcast, always succeeds
if let dog = pet as? Dog { dog.bark() }   // safe downcast
let dog = pet as! Dog               // forced, crashes if pet isn't a Dog
```

**Follow-ups:**
- **What is the difference between `is` and `as?`?** `is` only tells you `true` or `false`, while `as?` also gives you the cast value to use.
- **When is `as!` acceptable?** When a failure would be a programmer error, like dequeuing a cell type you registered yourself.
- **Can you cast to a protocol?** Yes, for example `if let item = value as? CustomStringConvertible { print(item.description) }`.

### Q13. Where do actors fit among Swift's types? `[Senior]`
An actor is a reference type, like a class, but it protects its mutable state so only one task can access it at a time, which prevents data races. Actors can't use inheritance, and code outside the actor must use `await` to reach its state.

```swift
actor BankAccount {
    var balance = 0.0
    func deposit(_ amount: Double) { balance += amount }
}

let account = BankAccount()
Task {
    await account.deposit(100)
    print(await account.balance)   // 100.0
}
```

**Follow-ups:**
- **What is actor reentrancy?** When an actor method pauses at an `await`, other calls can run on the actor, so its state may have changed when the method resumes.
- **What does `nonisolated` do?** It marks a member that doesn't touch the actor's mutable state, so it can be used without `await`.
- **How is a normal actor different from `@MainActor`?** A normal actor has its own isolated executor, while `@MainActor` is a global actor that runs code on the main thread for UI work.

## 2. Optionals

### Q14. What is an optional under the hood? `[Fundamental]`
An optional is a generic enum with two cases: `.none`, which is `nil`, and `.some(value)`, which holds a value. `Int?` is just shorthand for `Optional<Int>`, which is why you can `switch` over an optional.

```swift
// enum Optional<Wrapped> { case none; case some(Wrapped) }

let age: Int? = 30
switch age {
case .some(let value): print("Age is \(value)")
case .none:            print("No age")
}
```

**Follow-ups:**
- **How do you match an optional in a `switch` more shortly?** Use `case let value?` to match `.some(value)`, and `case nil` for `.none`.
- **Is Swift's `nil` the same as Objective-C's `nil`?** No. In Swift `nil` means "no value" for any type, including structs, while in Objective-C it is a null pointer to an object.
- **What is a double optional like `Int??`?** An optional inside an optional, which can be `nil`, `.some(nil)`, or `.some(5)`; it often appears with dictionaries of optionals.

### Q15. What are the different ways to unwrap an optional? `[Fundamental]`
You can unwrap an optional with `if let` or `guard let`, give a default with `??`, use optional chaining with `?.`, pattern match in a `switch`, transform it with `map`/`flatMap`, or force unwrap with `!` only when `nil` is truly impossible.

```swift
let name: String? = "Sam"

if let name { print(name) }                 // if let
let display = name ?? "Guest"               // nil-coalescing
let length = name?.count                    // optional chaining → Int?
let upper = name.map { $0.uppercased() }    // map
```

**Follow-ups:**
- **When is force unwrapping acceptable?** When `nil` is truly impossible and a crash would reveal a bug, like `URL(string: "https://apple.com")!` with a fixed string.
- **What does optional chaining return?** Always an optional, even if the final property is not optional.
- **What is the `if let name` shorthand?** Since Swift 5.7 you can write `if let name` instead of `if let name = name`.

### Q16. When do you use `guard let` vs `if let`? `[Fundamental]`
I use `guard let` for an early exit, because the unwrapped value stays available for the rest of the function and avoids deep nesting. I use `if let` when the value is only needed inside a small block.

```swift
func greet(_ name: String?) {
    guard let name else { return }   // exit early if nil
    print("Hello, \(name)")          // name is usable from here on
}

if let user = currentUser {
    print(user.name)                 // user only exists inside this block
}
```

**Follow-ups:**
- **What must the `else` of a `guard` do?** It must exit the current scope with `return`, `throw`, `break`, `continue`, or a call like `fatalError()`.
- **Can `guard` check things other than optionals?** Yes, any Boolean condition, for example `guard items.count > 0 else { return }`.
- **Can you unwrap several optionals in one statement?** Yes, separate them with commas, and all of them must succeed.

### Q17. What are implicitly unwrapped optionals, and when are they appropriate? `[Senior]`
An implicitly unwrapped optional, written `T!`, is an optional that unwraps itself automatically when used and crashes if it is `nil`. It is appropriate when a value can't be set in `init` but is guaranteed before use, like an `@IBOutlet`.

```swift
class ProfileViewController: UIViewController {
    @IBOutlet var nameLabel: UILabel!   // set by the storyboard before viewDidLoad

    override func viewDidLoad() {
        super.viewDidLoad()
        nameLabel.text = "Sam"          // no unwrapping needed
    }
}
```

**Follow-ups:**
- **What happens if you use an implicitly unwrapped optional while it is `nil`?** The app crashes at runtime.
- **Is `T!` a separate type?** No. Since Swift 4.2 it is a normal `Optional<T>` with a flag that allows automatic unwrapping.
- **How do you avoid IUOs in code-only UI?** Create the views in `init`, as `let` constants, or as `lazy var` properties.

### Q18. What is the difference between `map` and `flatMap` on an optional? `[Senior]`
`map` transforms the value inside an optional, while `flatMap` is used when the transformation itself returns an optional, so you get a single optional instead of a double optional.

```swift
let input: String? = "42"

let a = input.map { Int($0) }       // Int??  (optional inside optional)
let b = input.flatMap { Int($0) }   // Int?   (flattened)
```

**Follow-ups:**
- **Is `Optional.flatMap` the same as `Array.compactMap`?** No. `compactMap` transforms array elements and drops `nil`s, while `Optional.flatMap` chains optional-returning steps.
- **When does `map` on an optional return `nil`?** When the original optional is `nil`; the closure isn't called at all.
- **How can you replace an `if let` with `map`?** For example `let title = user.map { "Hi \($0.name)" } ?? "Guest"`.

## 3. Properties

### Q19. What is the difference between stored and computed properties? `[Fundamental]`
A stored property keeps a value in memory, while a computed property calculates its value every time it is read and doesn't use any storage.

```swift
struct Rectangle {
    var width: Double            // stored
    var height: Double           // stored
    var area: Double {           // computed
        width * height
    }
}
```

**Follow-ups:**
- **Can a computed property be declared with `let`?** No. Computed properties must be `var`, even if they are read-only.
- **Can a computed property have a setter?** Yes, with `set { }`, where the new value is available as `newValue`.
- **How do protocols declare properties?** With `{ get }` or `{ get set }`, and the conforming type chooses whether to make it stored or computed.

### Q20. What are `lazy` properties? What are their caveats? `[Senior]`
A `lazy` property isn't created until the first time it is accessed, which is useful for expensive setup. The caveats are that it must be a `var`, it isn't thread-safe, and storing a closure that captures `self` in it can create a retain cycle.

```swift
final class ReportViewController: UIViewController {
    lazy var formatter: DateFormatter = {
        let f = DateFormatter()        // created only on first use
        f.dateStyle = .medium
        return f
    }()
}
```

**Follow-ups:**
- **Can a `let` property be `lazy`?** No, because a lazy property is changed on its first access, so it must be `var`.
- **How would you make lazy setup thread-safe?** Protect it with a lock, use an actor, or use a `static let`, which is created exactly once safely.
- **Can a struct have a `lazy` property?** Yes, but you can only read it on a `var` instance, because the first read changes the struct.

### Q21. How do `willSet` and `didSet` behave during initialization? `[Senior]`
Property observers don't run when a class sets its own properties inside its own initializer. They do run when a subclass sets an inherited property after calling `super.init`.

```swift
class Counter {
    var value = 0 { didSet { print("didSet \(value)") } }
    init() { value = 10 }     // observer NOT called here
}

let c = Counter()
c.value = 20                  // prints "didSet 20"
```

**Follow-ups:**
- **Can you add observers to an inherited property?** Yes, override the property in the subclass and add `willSet` or `didSet`.
- **Can a computed property have `didSet`?** Not on its own; you put that logic in its setter instead. You can only add observers when overriding an inherited property.
- **Does `didSet` run if you assign the same value again?** Yes. It runs on every assignment, even if the value didn't change.

### Q22. What is the difference between `static` and `class` for properties and methods? `[Fundamental]`
Both create members that belong to the type instead of an instance, but `class` members can be overridden by subclasses and `static` members can't. `static` is effectively the same as `class final`.

```swift
class Vehicle {
    static var count = 0                         // can't be overridden
    class var wheels: Int { 4 }                  // can be overridden
}

class Bike: Vehicle {
    override class var wheels: Int { 2 }
}
```

**Follow-ups:**
- **Can structs use the `class` keyword for type members?** No, structs and enums only use `static`.
- **Can you have a `class` stored property?** No. Only `static` stored properties are allowed; `class` works for computed properties and methods.
- **How do classes implement a protocol's `static` requirement?** With either `static` or `class`; using `class` lets subclasses override it.

### Q23. Are `static let` properties thread-safe? Why are they used for singletons? `[Senior]`
Yes, static stored properties are created lazily and exactly once, and that creation is thread-safe, so `static let shared` is a safe way to build a singleton. Only the creation is safe, though; any mutable state inside the singleton still needs its own protection.

```swift
final class NetworkManager {
    static let shared = NetworkManager()   // created once, thread-safe
    private init() {}
}

NetworkManager.shared
```

**Follow-ups:**
- **How do you make a singleton's mutable state thread-safe?** Turn it into an actor, isolate it to `@MainActor`, or protect it with a lock or serial queue.
- **Why make a singleton's `init` private?** To stop other code from creating extra instances.
- **What are the downsides of singletons?** Hidden global state, tight coupling, and harder testing; injecting a protocol-typed dependency is usually better.

### Q24. What are property wrappers? Write one. `[Senior]`
A property wrapper is a type marked `@propertyWrapper` that holds the logic for storing a value, so the same logic can be reused on many properties with a simple attribute. `@State`, `@Published`, and `@AppStorage` are examples.

```swift
@propertyWrapper
struct Clamped {
    private var value: Int
    let range: ClosedRange<Int>

    init(wrappedValue: Int, _ range: ClosedRange<Int>) {
        self.range = range
        self.value = min(max(wrappedValue, range.lowerBound), range.upperBound)
    }

    var wrappedValue: Int {
        get { value }
        set { value = min(max(newValue, range.lowerBound), range.upperBound) }
    }
}

struct Player {
    @Clamped(0...100) var health = 100
}
```

**Follow-ups:**
- **What does the compiler generate for a property wrapper?** A hidden storage property like `_health` of the wrapper type, and a computed `health` that forwards to `wrappedValue`.
- **Can you use property wrappers on local variables?** Yes, since Swift 5.4.
- **Can you apply more than one wrapper to a property?** Yes, they are nested, with the outermost (first written) wrapper on the outside.

### Q25. What is `projectedValue` in a property wrapper? `[Senior]`
`projectedValue` is an extra value a property wrapper exposes through the `$` prefix. For example, with `@State var name`, `$name` gives you a `Binding`, and with `@Published var count`, `$count` gives you a publisher.

```swift
@propertyWrapper
struct Logged<Value> {
    var wrappedValue: Value { didSet { history.append(wrappedValue) } }
    private(set) var history: [Value] = []
    var projectedValue: [Value] { history }    // accessed with $

    init(wrappedValue: Value) { self.wrappedValue = wrappedValue }
}

struct Form { @Logged var text = "" }
var form = Form()
form.text = "Hi"
print(form.$text)   // ["Hi"]
```

**Follow-ups:**
- **What is the difference between `_name` and `$name`?** `_name` is the wrapper instance itself (private), while `$name` is the wrapper's `projectedValue`.
- **What does `$` give you on a `@Binding` property?** Another `Binding`, so you can pass it further down to child views.
- **Does `projectedValue` have to be the same type as `wrappedValue`?** No, it can be any type you choose.

## 4. Initialization

### Q26. What are designated and convenience initializers? `[Fundamental]`
A designated initializer fully sets up all of a class's properties and calls the superclass initializer, while a convenience initializer is a helper that must call another initializer in the same class. The simple rule is: designated delegates up, convenience delegates across.

```swift
class User {
    let name: String
    let age: Int

    init(name: String, age: Int) {          // designated
        self.name = name
        self.age = age
    }

    convenience init(name: String) {        // convenience
        self.init(name: name, age: 0)
    }
}
```

**Follow-ups:**
- **Can a convenience initializer call `super.init`?** No. It must call another initializer of the same class.
- **Are designated initializers inherited?** Yes, automatically, if the subclass defines no designated initializers of its own and gives default values to its new properties.
- **Do structs have convenience initializers?** There is no keyword for it; a struct initializer can simply call `self.init(...)`.

### Q27. Explain two-phase initialization. `[Senior]`
In phase one, every stored property gets a value, going up the class chain, and `self` can't be used yet. In phase two, going back down, each class can customize the instance and safely use `self`, which prevents using properties before they are set.

```swift
class Base {
    let id: Int
    init(id: Int) { self.id = id }
}

class Child: Base {
    let name: String
    init(name: String) {
        self.name = name        // Phase 1: set own properties first
        super.init(id: 1)       // then go up the chain
        print(self.name)        // Phase 2: now self is fully usable
    }
}
```

**Follow-ups:**
- **Why can't you call a method before `super.init`?** Because the object isn't fully initialized yet, and the method could read a property that has no value.
- **What error do you get if you use `self` too early?** Something like "'self' used before 'super.init' call" or "used before all stored properties are initialized".
- **How does Swift improve on Objective-C here?** Objective-C allowed calling methods on a half-built object, which could run overridden methods that read uninitialized properties.

### Q28. What are failable initializers? `[Fundamental]`
A failable initializer, written `init?`, returns `nil` instead of an instance when the input is invalid. It is useful for validation; if you need to explain why it failed, a throwing initializer is better.

```swift
struct Email {
    let value: String
    init?(_ value: String) {
        guard value.contains("@") else { return nil }
        self.value = value
    }
}

Email("sam@mail.com")   // Email
Email("invalid")        // nil
```

**Follow-ups:**
- **Which failable initializer do enums get for free?** `init?(rawValue:)`, when the enum has raw values.
- **When would you use a throwing initializer instead?** When the caller needs to know why it failed, not just that it failed.
- **Can a subclass override a failable initializer with a non-failable one?** Yes, but not the other way around.

### Q29. What does `required` mean on an initializer? `[Senior]`
`required` means every subclass must implement that initializer. You see it most with `init?(coder:)` in UIKit subclasses and when a non-final class conforms to a protocol that declares an initializer.

```swift
class CustomView: UIView {
    override init(frame: CGRect) { super.init(frame: frame) }

    required init?(coder: NSCoder) {     // must be implemented
        fatalError("init(coder:) has not been implemented")
    }
}
```

**Follow-ups:**
- **Why does `UIView` require `init?(coder:)`?** Because `UIView` adopts `NSCoding`, which is used to create views from storyboards and XIBs, so every subclass must provide it.
- **Do you write `override` with a `required` initializer?** No. Writing `required` in the subclass already implies the override.
- **Does a `final` class need `required` for a protocol initializer?** No, because a final class can't have subclasses.

### Q30. How do you keep a struct's memberwise initializer while adding a custom one? `[Fundamental]`
Writing any initializer inside the struct's main body removes the free memberwise initializer, so you put the custom initializer in an extension to keep both.

```swift
struct User {
    let name: String
    let age: Int
}

extension User {
    init(name: String) { self.init(name: name, age: 0) }
}

User(name: "Sam", age: 30)   // memberwise still works
User(name: "Sam")            // custom one works too
```

**Follow-ups:**
- **Is the memberwise initializer available outside the module?** No, it is `internal`, so public types in a framework need an explicit `public init`.
- **How do default values affect the memberwise initializer?** A `var` with a default value becomes an optional argument you can leave out.
- **Do classes get a memberwise initializer?** No. A class only gets a free `init()` if all its properties have default values.

### Q31. When is `deinit` called? `[Fundamental]`
`deinit` is called right before a class instance is freed from memory, which happens when its strong reference count reaches zero. It is used for cleanup like removing observers or invalidating timers.

```swift
class Downloader {
    deinit { print("Downloader freed") }
}

var d: Downloader? = Downloader()
d = nil     // prints "Downloader freed"
```

**Follow-ups:**
- **Can you call `deinit` yourself?** No. Only the runtime calls it, when the last strong reference goes away.
- **Is `deinit` called when the app is terminated?** Not reliably. The system just reclaims the whole process memory, so don't rely on `deinit` to save data.
- **In what order do subclass and superclass `deinit` run?** The subclass `deinit` runs first, then the superclass `deinit` runs automatically.

## 5. Enums

### Q32. What is the difference between raw values and associated values? `[Fundamental]`
A raw value is one fixed value per case that is the same type for all cases and is decided at compile time. An associated value is extra data attached to a case when you create it, and it can be a different type for each case.

```swift
enum Planet: Int {              // raw values
    case mercury = 1, venus, earth
}

enum Result {                   // associated values
    case success(data: String)
    case failure(code: Int)
}

Planet(rawValue: 3)             // .earth
Result.failure(code: 404)
```

**Follow-ups:**
- **Which types can be raw values?** `String`, `Character`, and integer or floating-point types; `Int` raw values count up automatically and `String` ones default to the case name.
- **Can an enum with associated values be `Equatable` automatically?** Yes, if all of its associated values are `Equatable`.
- **Does an enum with associated values get `init(rawValue:)`?** No, that is only for enums with raw values.

### Q33. What is an `indirect` enum? `[Senior]`
An `indirect` enum is an enum that can contain itself, which Swift allows by storing the associated values on the heap. It is used for recursive structures like expression trees or linked lists.

```swift
indirect enum Expression {
    case number(Int)
    case add(Expression, Expression)
}

let sum = Expression.add(.number(2), .number(3))
```

**Follow-ups:**
- **Can you mark just one case as `indirect`?** Yes, write `indirect case add(Expression, Expression)` instead of marking the whole enum.
- **Why is `indirect` needed for recursion?** A value type needs a fixed size at compile time, and an enum that contains itself directly would be infinitely large.
- **What does `indirect` cost?** A heap allocation and reference counting for the indirect cases.

### Q34. What is `@unknown default`? `[Senior]`
`@unknown default` is used when switching over an enum that might gain new cases in the future, such as enums from Apple's frameworks. It works like `default`, but the compiler warns you when a new case appears so you don't miss handling it.

```swift
switch AVCaptureDevice.authorizationStatus(for: .video) {
case .authorized:               print("Allowed")
case .denied, .restricted:      print("Blocked")
case .notDetermined:            print("Ask the user")
@unknown default:               print("New case added by Apple")
}
```

**Follow-ups:**
- **How is `@unknown default` different from `default`?** `default` silently handles new cases, while `@unknown default` still warns you so you notice them.
- **What is a frozen enum?** An enum marked `@frozen` promises it will never get new cases, so switches over it don't need a default, like `Optional`.
- **Do you need `@unknown default` for your own app's enums?** No. Your own enums are compiled with your code, so the compiler already makes you handle every case.

### Q35. How would you use an enum to model screen state? `[Senior]`
I use an enum so the screen can only be in one valid state at a time, instead of separate `isLoading`, `data`, and `error` properties that could conflict. This makes invalid states impossible to represent.

```swift
enum ViewState<Value> {
    case idle
    case loading
    case loaded(Value)
    case failed(Error)
}

var state: ViewState<[User]> = .loading   // can't be "loading" and "failed" at once
```

**Follow-ups:**
- **How would you show old data while reloading?** Add a case like `.refreshing([User])`, or keep the data in `.loaded` and add a separate refreshing flag.
- **How do you use this enum in SwiftUI?** Switch on the state in `body` to show a `ProgressView`, the list, or an error view.
- **Why can't this enum be `Equatable` automatically?** Because `Error` isn't `Equatable`; you can store your own `Equatable` error type or a message string instead.

### Q36. Can enums have stored properties, methods, and conformances? `[Fundamental]`
Enums can't have stored instance properties, because their data lives in associated values, but they can have computed properties, methods, static properties, initializers, extensions, and protocol conformances. `CaseIterable` gives you `allCases` for free.

```swift
enum Direction: CaseIterable {
    case north, south

    var symbol: String {                 // computed property
        self == .north ? "↑" : "↓"
    }
    func opposite() -> Direction {       // method
        self == .north ? .south : .north
    }
}

Direction.allCases   // [.north, .south]
```

**Follow-ups:**
- **Can an enum have a custom initializer?** Yes, it assigns a case to `self`, for example `init(score: Int) { self = score > 50 ? .pass : .fail }`.
- **Can an enum with associated values be `CaseIterable`?** Not automatically; you would have to write `allCases` yourself.
- **Can enums have static stored properties?** Yes, for example `static let defaultValue = Direction.north`.

## 6. Functions & Closures

### Q37. What is a closure? Are closures value or reference types? `[Fundamental]`
A closure is a block of code you can store and pass around, and it can capture variables from the place where it was created. Closures are reference types, so assigning a closure to two variables makes both point to the same closure.

```swift
var total = 0
let addTen = { total += 10 }   // captures 'total'
let sameClosure = addTen        // same closure, not a copy

addTen()
sameClosure()
print(total)                    // 20
```

**Follow-ups:**
- **What does "capturing" mean?** The closure keeps a reference to variables from where it was created, so it can still use them after that scope ends.
- **What is the difference between a function and a closure?** A function is a named closure; a closure expression is unnamed and written with `{ }`.
- **What is trailing closure syntax?** Writing the last closure argument after the parentheses, like `numbers.map { $0 * 2 }`.

### Q38. What is the difference between escaping and non-escaping closures? `[Fundamental]`
A non-escaping closure, the default, is called before the function returns. An `@escaping` closure can be called after the function returns, for example when it is stored or run later asynchronously, and that's where retain cycles usually happen.

```swift
func runNow(_ work: () -> Void) {
    work()                                  // non-escaping
}

var handlers: [() -> Void] = []
func runLater(_ work: @escaping () -> Void) {
    handlers.append(work)                   // escapes: stored for later
}
```

**Follow-ups:**
- **Why do escaping closures need an explicit `self`?** It makes the capture of `self` visible so you think about retain cycles; since Swift 5.3 you can skip it with `[self]` or when `self` is a struct.
- **Are optional closure parameters escaping?** Yes. A closure inside an optional, like `(() -> Void)?`, is escaping automatically.
- **What is `withoutActuallyEscaping`?** It lets you pass a non-escaping closure to an API that needs an escaping one, when you are sure it won't be kept.

### Q39. What is `@autoclosure`? `[Senior]`
`@autoclosure` automatically wraps an argument in a closure so it is evaluated only if and when it is needed. Swift uses it in `assert`, `??`, `&&`, and `||` so the right-hand side isn't computed unless necessary.

```swift
func log(_ message: @autoclosure () -> String, enabled: Bool) {
    if enabled { print(message()) }
}

log(expensiveDescription(), enabled: false)   // expensiveDescription() never runs
```

**Follow-ups:**
- **Can an `@autoclosure` also be escaping?** Yes, write `@autoclosure @escaping`, for example when the value is stored and evaluated later.
- **How does `??` use `@autoclosure`?** The default value on the right is only computed if the left side is `nil`.
- **What is the downside of `@autoclosure`?** The caller can't see that the argument might not run, which can be confusing if it has side effects.

### Q40. What are capture lists, and how do they change capture behavior? `[Senior]`
By default a closure captures a variable by reference, so it sees later changes. A capture list like `[x]` copies the value at the moment the closure is created, and it is also where you write `[weak self]` or `[unowned self]`.

```swift
var x = 10
let byReference = { print(x) }
let byValue = { [x] in print(x) }

x = 20
byReference()   // 20
byValue()       // 10
```

**Follow-ups:**
- **If you capture a class instance with `[obj]`, are its property changes visible?** Yes. The capture list copies the reference, not the object, so property changes are still seen.
- **What is the difference between `[weak self]` and `[unowned self]`?** `weak` makes `self` optional and safe if it is gone; `unowned` assumes it is alive and crashes if it isn't.
- **What does `guard let self` do inside a closure?** It turns the weak `self` into a strong one for the rest of the closure, so `self` stays alive until the closure finishes.

### Q41. What are higher-order functions? Explain `map`, `compactMap`, `flatMap`, `filter`, `reduce`. `[Fundamental]`
A higher-order function is a function that takes or returns another function. `map` transforms every element, `compactMap` transforms and removes `nil`s, `flatMap` transforms and flattens nested arrays, `filter` keeps matching elements, and `reduce` combines everything into one value.

```swift
let numbers = ["1", "2", "x", "4"]

numbers.compactMap { Int($0) }           // [1, 2, 4]
[1, 2, 3].map { $0 * 2 }                 // [2, 4, 6]
[[1, 2], [3]].flatMap { $0 }             // [1, 2, 3]
[1, 2, 3, 4].filter { $0.isMultiple(of: 2) }  // [2, 4]
[1, 2, 3].reduce(0, +)                   // 6
```

**Follow-ups:**
- **Why prefer `reduce(into:)` over `reduce`?** It changes one accumulator in place instead of creating a new copy at every step.
- **Are `map` and `filter` lazy on arrays?** No. They run immediately and create new arrays; use `.lazy` to delay the work.
- **Why use `first(where:)` instead of `filter { }.first`?** `first(where:)` stops at the first match, while `filter` checks every element first.

### Q42. What is the difference between `forEach` and `for-in`? `[Fundamental]`
In `forEach`, `return` only skips the current element and you can't use `break` or `continue`. A `for-in` loop supports `break`, `continue`, `where` clauses, and `await`.

```swift
for n in 1...5 where n.isMultiple(of: 2) {
    if n == 4 { break }        // ✅ break works
    print(n)                   // 2
}

(1...5).forEach { n in
    if n == 3 { return }       // only skips 3, keeps looping
    print(n)                   // 1 2 4 5
}
```

**Follow-ups:**
- **Can you use `await` inside `forEach`?** No, its closure is synchronous; use a `for-in` loop instead.
- **When is `forEach` a good choice?** At the end of a short functional chain, like `items.filter(\.isActive).forEach(save)`.
- **Is there a performance difference?** Practically none; choose based on readability and whether you need `break` or `continue`.

### Q43. How does `defer` work? `[Fundamental]`
A `defer` block runs when the current scope ends, no matter how it ends, whether by return, throw, or break. If there are several `defer` blocks, they run in reverse order.

```swift
func loadData() {
    isLoading = true
    defer { isLoading = false }   // always runs when the function exits

    guard let data = fetch() else { return }
    process(data)
}
```

**Follow-ups:**
- **Does `defer` run if the function throws?** Yes. It runs however the scope exits, including a thrown error.
- **Can a `defer` block contain `return` or `throw`?** No. You can't jump out of a `defer` block.
- **Does `defer` run when the app crashes?** No. A crash such as `fatalError()` stops the program immediately.

### Q44. What is `rethrows`? `[Senior]`
`rethrows` means a function throws only if the closure you pass to it throws. If you pass a non-throwing closure, you don't need `try`; that's how `map` and `filter` work.

```swift
func perform(_ work: () throws -> Void) rethrows {
    try work()
}

perform { print("Safe") }          // no 'try' needed
try perform { throw MyError.failed } // 'try' needed
```

**Follow-ups:**
- **Can a `rethrows` function throw its own errors?** Only in response to the closure throwing; it can't throw on its own if the closure doesn't throw.
- **Which standard library functions use `rethrows`?** `map`, `filter`, `contains(where:)`, `first(where:)`, and many others.
- **How do typed throws relate to `rethrows`?** In Swift 6, generic code can use `throws(E)` with the closure's error type `E`, which describes the same idea more precisely.

## 7. Memory Management (ARC)

### Q45. How does ARC work? `[Fundamental]`
ARC, or Automatic Reference Counting, counts how many strong references point to each class instance and frees the instance when the count reaches zero. The compiler inserts this counting at build time, so memory is released at a predictable moment.

```swift
class Photo { deinit { print("freed") } }

var a: Photo? = Photo()   // count = 1
var b = a                 // count = 2
a = nil                   // count = 1
b = nil                   // count = 0 → prints "freed"
```

**Follow-ups:**
- **Does ARC apply to structs?** Not to the struct itself, but if a struct holds class references, copying it retains and releases those references.
- **What is the difference between a strong and a weak reference?** A strong reference keeps the object alive; a weak one doesn't, and it becomes `nil` when the object is freed.
- **Is an object always freed at the end of its scope?** Not exactly. The optimizer can free it right after its last use, so use `withExtendedLifetime` if you need it alive longer.

### Q46. What is a retain cycle? Give common examples in iOS. `[Fundamental]`
A retain cycle happens when two or more objects hold strong references to each other, so none of them can ever be freed. Common causes are strong delegates, stored closures that capture `self`, timers that target `self`, and Combine `sink` closures that capture `self`.

```swift
class ViewModel {
    var onUpdate: (() -> Void)?
    func setup() {
        onUpdate = { self.refresh() }            // ❌ self → closure → self
        onUpdate = { [weak self] in self?.refresh() }   // ✅ cycle broken
    }
    func refresh() {}
}
```

**Follow-ups:**
- **How does a `Timer` create a retain cycle?** The run loop keeps the timer, and the timer keeps its target; invalidate the timer, or use the block-based API with `[weak self]`.
- **Do selector-based `NotificationCenter` observers create a cycle?** No. Since iOS 9 they don't retain the observer; the block-based API is the one that can.
- **How do Combine `sink` closures cause cycles?** `self` stores the `AnyCancellable`, which holds the closure, which captures `self`; use `[weak self]` or `assign(to: &$property)`.

### Q47. What is the difference between `weak` and `unowned`? `[Senior]`
Both avoid a strong reference, but a `weak` reference is optional and becomes `nil` when the object is freed, while an `unowned` reference assumes the object is still alive and crashes if it isn't. I use `weak` when the other object might die first and `unowned` only when it is guaranteed to outlive the reference.

```swift
class Customer {
    var card: CreditCard?
}

class CreditCard {
    unowned let owner: Customer         // a card never outlives its customer
    init(owner: Customer) { self.owner = owner }
}

class Cell {
    weak var delegate: CellDelegate?    // delegate may be gone first
}
```

**Follow-ups:**
- **Can `unowned` be optional?** Yes, since Swift 5 you can write `unowned var owner: Customer?`.
- **Why must `weak` be a `var`?** Because ARC changes it to `nil` when the object is freed.
- **What is `unowned(unsafe)`?** An `unowned` reference with no runtime check at all, so using a freed object is undefined behavior instead of a clean crash.

### Q48. Why should delegates be `weak`, and what does that require of the protocol? `[Fundamental]`
A delegate usually owns the object that points back to it, so a strong delegate reference would create a retain cycle. Because `weak` only works with classes, the protocol must be limited to classes with `AnyObject`.

```swift
protocol ProfileViewDelegate: AnyObject {
    func didTapSave()
}

class ProfileView: UIView {
    weak var delegate: ProfileViewDelegate?
}
```

**Follow-ups:**
- **What happens if the delegate protocol isn't `AnyObject`?** The compiler refuses `weak`, because `weak` only works with class-bound protocols.
- **Are delegates always held weakly?** No. For example, `URLSession` keeps a strong reference to its delegate until you invalidate the session.
- **What are alternatives to the delegate pattern?** Closures, Combine publishers, and `AsyncStream`.

### Q49. Do you always need `[weak self]` in closures? `[Senior]`
No. You need it only when `self` stores the closure, directly or indirectly, or when you don't want the closure to keep `self` alive longer. Non-escaping closures like `map` and short-lived ones like `UIView.animate` don't create cycles.

```swift
// ✅ No weak needed: not stored by self
UIView.animate(withDuration: 0.3) { self.view.alpha = 0 }

// ✅ Weak needed: self stores the closure
viewModel.onChange = { [weak self] in self?.reload() }
```

**Follow-ups:**
- **Do `Task { }` closures need `[weak self]`?** A Task keeps `self` alive until it finishes, which is not a cycle unless `self` stores the task; for long work, use `weak` or cancel the task in `deinit`.
- **What is the risk of using `[weak self]` everywhere?** Work can silently do nothing when `self` is `nil`, and the code gets more optional handling.
- **Does `DispatchQueue.main.async { self... }` need `[weak self]`?** Not for cycles; it only keeps `self` alive a little longer.

### Q50. How do you detect memory leaks? `[Senior]`
I use Xcode's Memory Graph Debugger, the Instruments Leaks and Allocations tools, print statements in `deinit`, and unit tests that check an object is freed after its last reference is removed.

```swift
func testViewModelIsDeallocated() {
    var sut: ProfileViewModel? = ProfileViewModel()
    weak var weakSUT = sut
    sut = nil
    XCTAssertNil(weakSUT, "ProfileViewModel leaked")
}
```

**Follow-ups:**
- **What is the difference between the Leaks and Allocations instruments?** Leaks finds memory that nothing points to anymore; Allocations shows memory growth, including memory that is still referenced but no longer needed.
- **Can the Memory Graph Debugger find every leak?** No. It shows retain cycles well, but a cache that just keeps growing needs Allocations to spot.
- **How do you catch leaks automatically?** Add a test helper that registers a weak reference in `addTeardownBlock` and asserts it is `nil` after the test.

### Q51. When would you use `autoreleasepool` in Swift? `[Senior]`
I use `autoreleasepool` in a tight loop that creates many temporary Objective-C objects, like images, so they are released after each iteration instead of piling up and spiking memory.

```swift
for url in imageURLs {
    autoreleasepool {
        let image = UIImage(contentsOfFile: url.path)
        process(image)
    }   // temporary objects are freed here, every iteration
}
```

**Follow-ups:**
- **Do pure Swift objects use autorelease?** No. Only Objective-C APIs return autoreleased objects.
- **Why isn't the main run loop's pool enough?** It drains once per run loop cycle, so a single long loop can still build up a lot of memory before it drains.
- **Do GCD queues have autorelease pools?** Yes, but they drain between work items, not between iterations of your loop.

### Q52. How does ARC differ from garbage collection? `[Fundamental]`
ARC frees memory immediately when the last reference goes away, with no pauses, but it can't clean up retain cycles on its own. A garbage collector runs at runtime and can clean up cycles, but it causes unpredictable pauses and uses more memory.

```swift
// With ARC, you break cycles yourself:
class Parent { var child: Child? }
class Child { weak var parent: Parent? }   // weak back-reference prevents a cycle
```

**Follow-ups:**
- **Why did Apple choose ARC?** Predictable performance and lower memory use, which matter on mobile devices, plus smooth interop with Objective-C.
- **Can a Swift app still leak memory?** Yes, mainly through retain cycles that ARC can't break on its own.
- **Does ARC have a runtime cost?** Yes, atomic reference count updates, although the optimizer removes many of them.

## 8. Protocols & Protocol-Oriented Programming

### Q53. What is protocol-oriented programming, and how does it compare with OOP inheritance? `[Senior]`
Protocol-oriented programming means building behavior from protocols and protocol extensions instead of class hierarchies. It works with structs and enums, lets a type adopt many protocols instead of inheriting from one class, and makes testing easier by swapping in mocks.

```swift
protocol Flyable { func fly() }
protocol Swimmable { func swim() }

extension Flyable { func fly() { print("Flying") } }

struct Duck: Flyable, Swimmable {     // combines behaviors, no base class
    func swim() { print("Swimming") }
}
```

**Follow-ups:**
- **What is the downside of protocol-oriented programming?** Over-abstraction, like creating a protocol for every type even when there is only one implementation.
- **How does it help testing?** You depend on a protocol, so in tests you can inject a mock instead of the real network or database.
- **Can protocols have stored properties?** No. They only declare requirements, and extensions can't add stored properties either.

### Q54. What are protocol extensions and default implementations? `[Fundamental]`
A protocol extension lets you write a method once and share it with every type that conforms to the protocol. A conforming type can replace that default only if the method is also declared as a requirement in the protocol.

```swift
protocol Greeter {
    func greet()
}

extension Greeter {
    func greet() { print("Hello") }     // default implementation
}

struct English: Greeter {}               // uses default
struct French: Greeter {
    func greet() { print("Bonjour") }    // custom
}
```

**Follow-ups:**
- **Can a protocol extension add stored properties?** No, only computed properties and methods.
- **Can you constrain a protocol extension?** Yes, for example `extension Collection where Element: Numeric` only applies to collections of numbers.
- **Can a protocol extension make the protocol adopt another protocol?** No. Protocol inheritance must be written on the protocol declaration itself.

### Q55. Explain static vs dynamic dispatch with protocol extensions. `[Senior]`
Methods declared as protocol requirements use dynamic dispatch, so the real type's version is called. Methods that exist only in a protocol extension use static dispatch, so the version is chosen by the variable's declared type.

```swift
protocol Greeter { func greet() }
extension Greeter {
    func greet() { print("Hello") }
    func farewell() { print("Bye") }      // not a requirement
}

struct Person: Greeter {
    func greet() { print("Hi") }
    func farewell() { print("See ya") }
}

let p: Greeter = Person()
p.greet()      // "Hi"   (dynamic)
p.farewell()   // "Bye"  (static, uses the extension)
```

**Follow-ups:**
- **How do you make `farewell()` dynamically dispatched?** Add it to the protocol as a requirement.
- **Why is this a source of bugs?** The same object behaves differently depending on whether the variable's type is the protocol or the concrete type.
- **What happens with a subclass when only the superclass conforms?** If the superclass uses the default implementation, the subclass's version isn't called through the protocol; the superclass must implement the method itself.

### Q56. What are associated types? `[Senior]`
An associated type is a placeholder type inside a protocol, and each conforming type decides what that type actually is. For example, `Collection` has an `Element` type that is `Int` for `[Int]`.

```swift
protocol Repository {
    associatedtype Entity
    func fetchAll() -> [Entity]
}

struct UserRepository: Repository {
    func fetchAll() -> [User] { [] }   // Entity is inferred as User
}
```

**Follow-ups:**
- **How is the associated type decided?** It is usually inferred from the method signatures, or you can set it explicitly with `typealias Entity = User`.
- **Can you constrain an associated type?** Yes, for example `associatedtype Entity: Identifiable`.
- **Why couldn't `Repository` be used as a plain type before?** The compiler didn't know what `Entity` was; since Swift 5.7 you can write `any Repository` or `any Repository<User>`.

### Q57. What is protocol composition? `[Fundamental]`
Protocol composition is the practice of combining multiple protocols into a single requirement so that a type or function must conform to all of them at the same time.

```swift
protocol Named { var name: String { get } }
protocol Aged  { var age: Int { get } }

struct Person: Named, Aged {
    let name: String
    let age: Int
}

func introduce(_ person: Named & Aged) {
    print("\(person.name) is \(person.age)")
}

introduce(Person(name: "Sam", age: 30))   // "Sam is 30"
```

**Follow-ups:**
- **Can a composition include a class?** Yes, for example `UIViewController & Coordinatable` means "a view controller that also conforms to Coordinatable."
- **Can you name a composition?** Yes, with a typealias; the standard library does `typealias Codable = Encodable & Decodable`.
- **Why does composition encourage small protocols?** You combine only what a function needs, which follows the Interface Segregation Principle.

### Q58. What is conditional conformance? `[Senior]`
Conditional conformance means a generic type conforms to a protocol only when its type arguments meet certain conditions. For example, an array is `Equatable` only when its elements are `Equatable`.

```swift
struct Box<T> { let value: T }

extension Box: Equatable where T: Equatable {}

Box(value: 1) == Box(value: 1)    // ✅ true, because Int is Equatable
```

**Follow-ups:**
- **Where does the standard library use conditional conformance?** `Optional` is `Equatable` when `Wrapped` is, and `Array` is `Codable` when `Element` is.
- **Can a type conform to the same protocol under two different conditions?** No. A type can have only one conformance to a given protocol.
- **How is it different from a constrained extension?** A constrained extension adds methods, while conditional conformance adds a protocol conformance.

### Q59. How do you make protocol methods optional? `[Fundamental]`
The Swift way is to give the method a default, often empty, implementation in a protocol extension, so conforming types can skip it. The older way is `@objc optional`, which only works with class-only `@objc` protocols.

```swift
protocol ListDelegate {
    func didSelect(row: Int)
    func didScroll()
}

extension ListDelegate {
    func didScroll() {}           // default makes it "optional"
}

struct Handler: ListDelegate {
    func didSelect(row: Int) { print(row) }   // didScroll not required
}
```

**Follow-ups:**
- **Why do `@objc optional` requirements only work with classes?** Because Objective-C protocols can only be adopted by classes.
- **How do you call an `@objc optional` method?** With optional chaining, like `delegate?.didScroll?()`.
- **What is the risk of empty default implementations?** If a conformer misspells the method name, the default is silently used and nothing warns you.

### Q60. What does `Self` mean in a protocol? `[Senior]`
`Self` with a capital S means "the type that conforms to this protocol," while lowercase `self` is the current instance. `Equatable`, for example, uses `Self` to say both sides of `==` must be the same type.

```swift
protocol Copyable {
    func copy() -> Self
}

struct Note: Copyable {
    var text: String
    func copy() -> Note { Note(text: text) }   // Self becomes Note
}
```

**Follow-ups:**
- **What does a class method returning `Self` mean?** It returns the dynamic type, so a subclass calling it gets an instance of the subclass back.
- **Why couldn't protocols with `Self` requirements be used as types before?** The compiler didn't know which concrete type `Self` was; now you can use them with `any`, with some limits.
- **What is the difference between `Self` and `self`?** `Self` is the type, `self` is the current instance.

### Q61. What is the contract between `Equatable` and `Hashable`? `[Senior]`
If two values are equal, they must produce the same hash value; the reverse doesn't have to be true. So you should hash exactly the properties you compare in `==`, otherwise `Set` and `Dictionary` will behave incorrectly.

```swift
struct User: Hashable {
    let id: Int
    var name: String

    static func == (lhs: User, rhs: User) -> Bool { lhs.id == rhs.id }
    func hash(into hasher: inout Hasher) { hasher.combine(id) }   // same property as ==
}
```

**Follow-ups:**
- **What happens if `hash(into:)` uses a property that `==` ignores?** Equal values can land in different buckets, so a `Set` may hold duplicates or fail to find items.
- **Why shouldn't you save hash values?** Swift seeds hashing randomly on each launch, so the same value hashes differently next time.
- **What happens if you change a class object that is inside a `Set`?** If the change affects its hash, the set can't find it anymore and behaves incorrectly.

### Q62. What is retroactive conformance, and why does Swift 6 warn about it? `[Lead/Expert]`
Retroactive conformance is making a type you don't own conform to a protocol you don't own, like making `Date` conform to `Identifiable`. Swift 6 warns because if Apple adds the same conformance later, the behavior becomes ambiguous; you can mark your intent with `@retroactive` or wrap the type instead.

```swift
// Warned in Swift 6, unless you acknowledge it:
extension Date: @retroactive Identifiable {
    public var id: TimeInterval { timeIntervalSince1970 }
}

// Safer: wrap it in your own type
struct EventDate: Identifiable {
    let date: Date
    var id: TimeInterval { date.timeIntervalSince1970 }
}
```

**Follow-ups:**
- **When is retroactive conformance acceptable?** In an app target for small conveniences, where no other module is likely to add the same conformance.
- **Does Swift warn if you own the type or the protocol?** No. The warning only appears when both the type and the protocol come from other modules.
- **Why is it especially risky in libraries?** Two libraries could add the same conformance, and an app using both would get a conflict.

## 9. Generics

### Q63. Why use generics? Give an example. `[Fundamental]`
Generics let you write code once that works with many types while staying type-safe, without casting to `Any`. For example, one `Stack` can hold `Int`s, `String`s, or `User`s.

```swift
struct Stack<Element> {
    private var items: [Element] = []
    mutating func push(_ item: Element) { items.append(item) }
    mutating func pop() -> Element? { items.popLast() }
}

var numbers = Stack<Int>()
numbers.push(1)
var names = Stack<String>()
names.push("Sam")
```

**Follow-ups:**
- **Why use generics instead of `Any`?** You keep type checking at compile time, avoid casting, and usually get faster code.
- **Can you add methods to a generic type only for some types?** Yes, for example `extension Stack where Element: Equatable { func contains(_ x: Element) -> Bool { ... } }`.
- **Do you always have to write the generic type?** No. Swift usually infers it from the arguments, like `Stack<Int>` from `push(1)`.

### Q64. How do generic constraints and `where` clauses work? `[Senior]`
A generic constraint limits a generic type to types that conform to a protocol, like `T: Equatable`. A `where` clause adds extra conditions, such as requiring two collections to have the same element type.

```swift
func findIndex<T: Equatable>(of value: T, in array: [T]) -> Int? {
    array.firstIndex(of: value)
}

extension Collection where Element: Numeric {
    var total: Element { reduce(0, +) }
}

[1, 2, 3].total   // 6
```

**Follow-ups:**
- **Is `<T: Equatable>` different from `where T: Equatable`?** No, they mean the same; `where` is just more readable for longer or same-type constraints.
- **Can a single method in a generic type have its own `where` clause?** Yes, since Swift 5.3, for example `func sum() -> Element where Element: Numeric`.
- **What is a same-type constraint?** A rule that two types must be equal, like `where C1.Element == C2.Element`.

### Q65. What is the difference between `some` and `any`? `[Senior]`
`some Protocol` means one specific concrete type that is hidden from the caller but known to the compiler, so it is fast. `any Protocol` means a box that can hold any conforming type and can change at runtime, which is more flexible but slower. I default to `some` and use `any` when I need to mix different types.

```swift
func makeShape() -> some Shape { Circle() }   // always a Circle, hidden

let shapes: [any Shape] = [Circle(), Rectangle()]   // mixed types
```

**Follow-ups:**
- **Can a function returning `some Shape` return different types in different branches?** No. It must always return the same concrete type.
- **What does `some` mean in a parameter?** It's shorthand for a generic: `func draw(_ s: some Shape)` is the same as `func draw<S: Shape>(_ s: S)`.
- **Why is `any` slower?** The value is stored in a box, calls go through dynamic dispatch, and large values may need a heap allocation.

### Q66. Why does SwiftUI use `some View`? `[Senior]`
A SwiftUI `body` returns a very long nested generic type that is impractical to write by hand. `some View` hides that type from us while still letting the compiler know it exactly, which SwiftUI needs to compare and update views efficiently.

```swift
struct ProfileView: View {
    var body: some View {          // real type: VStack<TupleView<(Text, Image)>>
        VStack {
            Text("Sam")
            Image(systemName: "person")
        }
    }
}
```

**Follow-ups:**
- **Why does `if/else` work inside `body`?** `@ViewBuilder` wraps the two branches in one type, `_ConditionalContent`, so `body` still returns a single type.
- **Why avoid `AnyView`?** It erases the type information SwiftUI uses for diffing, which can hurt performance and animations.
- **What is `@ViewBuilder`?** A result builder that turns several view statements into one combined view.

### Q67. What is type erasure? Implement a type-erased wrapper. `[Lead/Expert]`
Type erasure hides a specific concrete type behind a wrapper with a common interface, like `AnyPublisher` or `AnyView`. It was mainly needed for protocols with associated types, though `any Protocol<Type>` now replaces many hand-written wrappers.

```swift
protocol DataLoader {
    associatedtype Output
    func load() async throws -> Output
}

struct AnyDataLoader<Output>: DataLoader {
    private let _load: () async throws -> Output

    init<L: DataLoader>(_ loader: L) where L.Output == Output {
        _load = loader.load
    }

    func load() async throws -> Output { try await _load() }
}
```

**Follow-ups:**
- **Which Apple types use type erasure?** `AnyPublisher`, `AnyView`, `AnyHashable`, and `AnySequence`.
- **Why does Combine use `eraseToAnyPublisher()`?** To hide the long, nested publisher type from the API, so the implementation can change freely.
- **When do you still need a hand-written wrapper today?** When you need a concrete type that itself conforms to the protocol, for example to use it as a generic argument or add `Equatable`.

### Q68. What are primary associated types? `[Senior]`
Primary associated types let a protocol list its main associated type in angle brackets, like `protocol Repository<Entity>`. This lets you write constrained types such as `any Repository<User>` or `some Collection<Int>` without manual type erasure.

```swift
protocol Repository<Entity> {
    associatedtype Entity
    func fetchAll() -> [Entity]
}

func showUsers(from repo: any Repository<User>) {
    print(repo.fetchAll())
}
```

**Follow-ups:**
- **Which standard library protocols have primary associated types?** For example `Sequence<Element>` and `Collection<Element>`.
- **Can a protocol have more than one primary associated type?** Yes, list them separated by commas in the angle brackets.
- **Is there an OS requirement?** Yes, some uses of constrained existentials like `any Collection<Int>` need runtime support from iOS 16 or later.

### Q69. How do generics affect performance? `[Lead/Expert]`
When the compiler knows the concrete type, it creates a specialized version of the generic code, which is as fast as normal code. Across module boundaries it often can't specialize unless the code is `@inlinable`, so the generic code runs through slower dynamic dispatch.

```swift
// Marking public generic code @inlinable lets other modules specialize it
@inlinable
public func sum<T: Numeric>(_ values: [T]) -> T {
    values.reduce(0, +)
}
```

**Follow-ups:**
- **What is specialization?** The compiler creates a copy of the generic function for a specific type, like `Int`, so it runs like normal code.
- **What is the downside of `@inlinable`?** The function body becomes part of your public interface, so changing it needs clients to recompile, and code size can grow.
- **Does this matter in normal app code?** Usually not, because whole-module optimization handles it; it matters for hot paths across modules or packages.

### Q70. What are parameter packs? `[Lead/Expert]`
Parameter packs let a generic function accept any number of arguments of different types while keeping each type. `each T` declares the pack and `repeat` expands it; this is how SwiftUI's `ViewBuilder` removed the old 10-child limit.

```swift
func describe<each T>(_ values: repeat each T) {
    for value in repeat each values {
        print(value)
    }
}

describe(1, "two", 3.0)   // 1, two, 3.0
```

**Follow-ups:**
- **How was this solved before parameter packs?** With many overloads, one per number of arguments, like `ViewBuilder.buildBlock` for up to 10 children.
- **Which Swift version added iteration over packs?** Swift 6.0 added `for value in repeat each values`.
- **Where are parameter packs useful?** Tuple-like generic APIs, zipping any number of sequences, SwiftUI builders, and test argument helpers.

## 10. Error Handling

### Q71. How does Swift's error handling work? Is it like exceptions? `[Fundamental]`
A function marked `throws` can throw a value that conforms to `Error`, and the caller must use `try`, then either handle it in `do-catch` or pass it up. Unlike exceptions in other languages, a thrown error is just a cheap special return path, and every `try` makes the failure point visible.

```swift
enum LoginError: Error { case wrongPassword }

func login(password: String) throws {
    if password != "1234" { throw LoginError.wrongPassword }
}

do {
    try login(password: "0000")
} catch {
    print("Failed: \(error)")
}
```

**Follow-ups:**
- **Which types can be thrown?** Any type that conforms to `Error`; enums are most common, but structs and classes work too.
- **Can a non-throwing function call a throwing one?** Yes, but only with `do-catch`, `try?`, or `try!`.
- **Can initializers throw?** Yes, `init() throws` is common for validation or loading data.

### Q72. What is the difference between `try`, `try?`, and `try!`? `[Fundamental]`
`try` passes the error to a `do-catch` or up to the caller; `try?` turns the result into an optional and throws the error away; and `try!` crashes if an error is thrown, so it's only for errors that should never happen.

```swift
let data = try loadFile()               // handle or propagate
let maybe = try? loadFile()             // nil if it fails
let config = try! loadBundledConfig()   // crash if it fails (should never fail)
```

**Follow-ups:**
- **What does `try?` return for a function that already returns an optional?** Since Swift 5, a single optional, not a double optional.
- **Why is `try?` risky?** It throws away the reason for the failure, so debugging becomes harder.
- **Where is `try!` acceptable?** In tests or for things that can't fail if the app is built correctly, like decoding a bundled JSON file.

### Q73. When would you use `Result` instead of `throws`? `[Senior]`
`Result` stores a success or a failure as a value, which is useful when you need to save it, pass it around, or return it through a completion handler. With async/await, `throws` is usually the better choice for normal control flow.

```swift
func fetchUser(completion: @escaping (Result<User, Error>) -> Void) {
    completion(.success(User(name: "Sam")))
}

fetchUser { result in
    switch result {
    case .success(let user): print(user.name)
    case .failure(let error): print(error)
    }
}
```

**Follow-ups:**
- **How do you convert between `Result` and `throws`?** `Result { try work() }` creates a Result, and `try result.get()` turns it back into a throwing call.
- **Can `Result`'s failure type be anything?** No, the `Failure` type must conform to `Error`.
- **How does `Result` help bridge callbacks to async/await?** In `withCheckedThrowingContinuation`, you can call `continuation.resume(with: result)`.

### Q74. What are typed throws? When would you use them? `[Lead/Expert]`
Typed throws, added in Swift 6, let a function declare the exact error type it throws, like `throws(ValidationError)`, so the `catch` block gets that type instead of `any Error`. They're good for closed error sets inside a module, but plain `throws` is still the better default for public APIs.

```swift
enum ValidationError: Error { case empty, tooShort }

func validate(_ s: String) throws(ValidationError) {
    if s.isEmpty { throw .empty }
    if s.count < 3 { throw .tooShort }
}

do throws(ValidationError) {
    try validate("")
} catch {
    switch error {              // error is ValidationError, not any Error
    case .empty:    print("Empty")
    case .tooShort: print("Too short")
    }
}
```

**Follow-ups:**
- **What does `throws(Never)` mean?** The function can never throw, so it is the same as a non-throwing function.
- **Why avoid typed throws in public APIs?** Adding a new error case or type later becomes a breaking change for every client.
- **How do typed throws help generic code?** A function can throw exactly the same error type as the closure passed to it, without converting it to `any Error`.

### Q75. How do you give errors user-friendly descriptions? `[Fundamental]`
You make the error conform to `LocalizedError` and provide an `errorDescription`, and optionally a `failureReason` or `recoverySuggestion`. This keeps user-facing messages separate from technical details.

```swift
enum NetworkError: LocalizedError {
    case offline

    var errorDescription: String? {
        switch self {
        case .offline: "You're offline. Please check your connection."
        }
    }
}

print(NetworkError.offline.localizedDescription)
```

**Follow-ups:**
- **What is the difference between `localizedDescription` and `errorDescription`?** `localizedDescription` returns your `errorDescription` when the error is a `LocalizedError`; otherwise it returns a generic system message.
- **Should you show raw error messages to users?** No. Show a friendly message, and log the technical details separately.
- **How do you localize the messages?** Return localized strings, for example with `String(localized: "offline_message")`.

### Q76. How would you design an error-handling strategy for an app? `[Lead/Expert]`
I layer the errors: network errors are mapped into domain errors, and domain errors are mapped into states the UI can show, so views never see `URLError`. I also decide which errors can be retried, which should be shown to the user, and which are programmer bugs, and I log everything in one central place.

```swift
enum ProfileError: Error {
    case offline, timeout, unknown

    init(_ error: Error) {
        switch (error as? URLError)?.code {
        case .notConnectedToInternet: self = .offline
        case .timedOut:               self = .timeout
        default:                      self = .unknown
        }
    }
}

// Repository maps URLError → ProfileError; the view only sees ProfileError
```

**Follow-ups:**
- **How would you handle an expired token?** An interceptor refreshes the token once, other requests wait for it, and then the failed requests are retried.
- **How would you retry failed requests?** With exponential backoff, only for temporary errors like timeouts, and only for requests that are safe to repeat.
- **When do you use `precondition` instead of throwing?** `precondition` is for programmer mistakes that should never happen; throwing is for failures that are expected, like no network.

## 11. Collections & Strings

### Q77. Compare `Array`, `Set`, and `Dictionary`. `[Fundamental]`
An `Array` is an ordered list that allows duplicates, a `Set` is an unordered collection of unique values with fast lookup, and a `Dictionary` stores unique keys mapped to values with fast lookup by key. `Set` elements and `Dictionary` keys must be `Hashable`.

```swift
let array = [1, 2, 2, 3]              // ordered, duplicates allowed
let set: Set = [1, 2, 2, 3]           // {1, 2, 3}, unique, unordered
let dict = ["id": 1, "age": 30]       // key → value

set.contains(2)                       // fast O(1) lookup
dict["age"]                           // Optional(30)
```

**Follow-ups:**
- **Why must `Set` elements be `Hashable`?** The set uses each element's hash to find its bucket quickly, which gives O(1) average lookup.
- **Is a `Dictionary`'s order guaranteed?** No. Sort the keys when you need an order, or use `OrderedDictionary` from the swift-collections package.
- **When would you switch from an `Array` to a `Set`?** When you call `contains` many times on a large collection and don't care about order or duplicates.

### Q78. What is the difference between `Sequence`, `Collection`, and `IteratorProtocol`? `[Senior]`
`IteratorProtocol` gives you the next element through `next()`. A `Sequence` can produce an iterator and may be iterated only once or even be infinite. A `Collection` is a sequence that is finite, can be iterated many times, and supports index-based access.

```swift
struct Countdown: Sequence, IteratorProtocol {
    var current: Int

    mutating func next() -> Int? {
        guard current > 0 else { return nil }
        defer { current -= 1 }
        return current
    }
}

for n in Countdown(current: 3) { print(n) }   // 3 2 1
```

**Follow-ups:**
- **Can every `Sequence` be iterated twice?** No. Only `Collection` guarantees that; a sequence might be consumed the first time, like a stream of input.
- **What do you need to implement to conform to `Collection`?** `startIndex`, `endIndex`, a subscript, and `index(after:)`.
- **What does `RandomAccessCollection` add?** Jumping to any index and measuring distances in O(1), which also makes `count` O(1).

### Q79. What are lazy sequences? `[Senior]`
A lazy sequence, created with `.lazy`, doesn't run its transformations until an element is actually requested, so it avoids building large temporary arrays. The catch is that the work is repeated each time you access the elements.

```swift
let firstBigSquare = (1...1_000_000)
    .lazy
    .map { $0 * $0 }
    .first { $0 > 1000 }    // stops after 32 elements, not 1,000,000

print(firstBigSquare!)      // 1024
```

**Follow-ups:**
- **When should you not use `.lazy`?** For small collections, or when you will go through the results many times, because the work repeats each time.
- **What type does `.lazy.map` return?** A `LazyMapSequence`; wrap it in `Array(...)` when you need a real array.
- **Does `filter` work lazily too?** Yes, `.lazy.filter` returns a `LazyFilterSequence` that checks elements only as they are requested.

### Q80. Why can't you index a `String` with an `Int`? `[Senior]`
Because one `Character` can be made of several Unicode scalars and take a different number of bytes, finding the nth character means walking through the string, which is O(n). Swift uses `String.Index` so that cost is visible instead of hidden behind `str[5]`.

```swift
let word = "Swift"
// word[1]                                    // ❌ not allowed

let i = word.index(word.startIndex, offsetBy: 1)
print(word[i])                                // "w"
print(word.prefix(3))                         // "Swi"
```

**Follow-ups:**
- **Why is `String.count` O(n)?** Swift has to walk the string to group bytes into characters.
- **Can you use an index from one string on another string?** No. An index is only valid for the string it came from, and using it elsewhere can crash.
- **How do you access characters by position many times efficiently?** Convert the string to an `Array` once with `Array(text)`, then use integer indexes.

### Q81. What is a `Substring`, and what is the memory concern? `[Senior]`
A `Substring` is a slice of a `String` that shares the original string's memory, so creating it is fast. The concern is that keeping even a tiny `Substring` alive keeps the whole original string in memory, so you convert it to a `String` before storing it.

```swift
let log = String(repeating: "x", count: 1_000_000) + "ERROR"
let tail = log.suffix(5)            // Substring, still holds the 1 MB string

let saved = String(tail)            // independent copy, original can be freed
```

**Follow-ups:**
- **Why does Swift have `Substring` at all?** So slicing is fast and doesn't copy memory, which matters when parsing large text.
- **How do you write a function that accepts both `String` and `Substring`?** Make it generic over `StringProtocol`, like `func clean<S: StringProtocol>(_ text: S)`.
- **Does `ArraySlice` have the same issue?** Yes. It keeps the whole array alive, and its indexes don't start at 0, so convert with `Array(slice)` before storing.

### Q82. What useful `Dictionary` APIs should a senior engineer know? `[Senior]`
The ones I use most are the `default:` subscript for counting, `Dictionary(grouping:by:)` to group items, `merging` to combine dictionaries, `uniqueKeysWithValues` to build a lookup table, and `mapValues` to transform only the values.

```swift
var counts: [String: Int] = [:]
counts["apple", default: 0] += 1

let byDepartment = Dictionary(grouping: users, by: \.department)
let lookup = Dictionary(uniqueKeysWithValues: users.map { ($0.id, $0) })
let merged = defaults.merging(overrides) { _, new in new }
let names = lookup.mapValues(\.name)
```

**Follow-ups:**
- **What happens if `uniqueKeysWithValues` gets a duplicate key?** It crashes; use `Dictionary(_:uniquingKeysWith:)` to decide which value wins.
- **What is the difference between `map` and `mapValues` on a dictionary?** `map` returns an array, while `mapValues` keeps the keys and returns a dictionary.
- **What does `compactMapValues` do?** It transforms the values and removes any key whose new value is `nil`.

## 12. Access Control & Modules

### Q83. Explain Swift's access levels. `[Fundamental]`
From most to least open: `open` can be used and subclassed outside the module, `public` can be used but not subclassed outside, `package` is visible within the same Swift package, `internal` (the default) is visible within the module, `fileprivate` within the file, and `private` within the declaration and its extensions in the same file.

```swift
open class BaseViewController {}      // subclassable by other modules
public struct APIClient {}            // usable, not subclassable outside
package func sharedHelper() {}        // same package only
internal var cache = [String: Data]() // same module (default)
fileprivate let key = "token"         // same file
private var secret = "123"            // same declaration
```

**Follow-ups:**
- **What is the difference between `open` and `public`?** Both are visible outside the module, but only `open` lets other modules subclass the class or override the method.
- **Are members of a `public` type public too?** No. They are `internal` by default, so you must mark each one `public` yourself.
- **What does `private(set)` mean?** Everyone can read the property, but only code inside the type can change it.

### Q84. What's the difference between `private` and `fileprivate` today? `[Fundamental]`
`private` is visible inside the type and its extensions in the same file. `fileprivate` is needed only when a different type in the same file needs access.

```swift
struct Account {
    private var balance = 0
}

extension Account {
    func show() { print(balance) }      // ✅ private works in same-file extension
}

struct Auditor {
    func check(_ a: Account) {
        // print(a.balance)             // ❌ needs fileprivate
    }
}
```

**Follow-ups:**
- **When did `private` change to include same-file extensions?** In Swift 4.
- **Is a `private` member visible in an extension in another file?** No. Only extensions in the same file can see it.
- **Which one should you use by default?** `private`, and switch to `fileprivate` only when another type in the same file really needs access.

### Q85. What does `@testable import` do? `[Fundamental]`
`@testable import` lets a test target access the `internal` parts of a module, as long as the module is built with testing enabled. It still doesn't give access to `private` or `fileprivate` code.

```swift
@testable import MyApp

final class CartTests: XCTestCase {
    func testTotal() {
        let cart = Cart()               // Cart is internal in MyApp
        XCTAssertEqual(cart.total, 0)
    }
}
```

**Follow-ups:**
- **Does `@testable import` work with release builds?** Only if the module is built with "Enable Testability," which is normally on only for Debug.
- **Why is testing through public behavior usually better?** Tests don't break every time you refactor internal details.
- **Does it work with Swift Testing?** Yes, Swift Testing uses the same `@testable import`.

### Q86. What are ABI stability, module stability, and library evolution? `[Lead/Expert]`
ABI stability means binaries built with different Swift versions can work together, so apps don't have to bundle the Swift runtime. Module stability means a framework built with one compiler can be imported by a newer one. Library evolution lets a binary framework change without breaking its users, and `@frozen` promises a type's layout will never change.

```swift
// Built with BUILD_LIBRARY_FOR_DISTRIBUTION = YES

@frozen
public struct Point {          // layout locked: faster, but can never add stored properties
    public var x: Double
    public var y: Double
}

public struct Settings {       // not frozen: can add properties in future versions
    public var theme: String
}
```

**Follow-ups:**
- **Does a normal iOS app need library evolution turned on?** No. It is only needed for binary frameworks that are shipped and updated separately from the apps using them.
- **What does library evolution cost?** Non-frozen types are accessed indirectly, which is a bit slower, so `@frozen` is used for performance-critical types.
- **What is a `.swiftinterface` file?** A text description of a module's public API that a newer compiler can read to import the framework.

## 13. Method Dispatch & Performance

### Q87. What types of method dispatch does Swift use? `[Senior]`
Swift uses static dispatch for structs, enums, `final` and `private` methods, which is the fastest; table (vtable) dispatch for overridable class methods; witness tables for protocol requirements; and message dispatch through the Objective-C runtime for `@objc dynamic` methods.

```swift
struct Calculator { func add() {} }          // static
class Animal { func speak() {} }             // vtable (can be overridden)
protocol Drawable { func draw() }            // witness table
class Model: NSObject {
    @objc dynamic var name = ""              // message dispatch (KVO)
}
```

**Follow-ups:**
- **Which kind of dispatch is fastest?** Static dispatch, because the call target is known at compile time and can be inlined.
- **Can methods declared in a class extension be overridden?** Not normally; only if they are `@objc`, because extension methods use static dispatch.
- **What is a protocol witness table?** A table, one per conformance, that maps each protocol requirement to the type's actual implementation.

### Q88. How do `final`, `private`, and whole-module optimization help performance? `[Senior]`
They let the compiler prove a method can't be overridden, so it can use fast static dispatch and inline the code. Whole-module optimization, on by default in Release, can even infer `final` for internal classes that have no subclasses.

```swift
final class ImageCache {          // no subclasses → static dispatch
    private func evict() {}       // private → static dispatch
    func store() {}               // also static, because the class is final
}
```

**Follow-ups:**
- **How do `private` and `fileprivate` help the compiler?** The compiler can see every possible override in that file, so it can treat the method as `final`.
- **What is whole-module optimization?** Compiling the whole module as one unit, so the compiler sees all code and can optimize across files.
- **Can you subclass a `final` class?** No, the compiler won't allow it.

### Q89. What do `@objc` and `dynamic` do? `[Senior]`
`@objc` makes a declaration visible to the Objective-C runtime, which is needed for `#selector` and target-action. `dynamic` forces calls to go through the Objective-C runtime so the implementation can change at runtime, which is needed for KVO and method swizzling.

```swift
class ProfileViewController: UIViewController {
    @objc func saveTapped() {}                     // usable with #selector

    override func viewDidLoad() {
        super.viewDidLoad()
        button.addTarget(self, action: #selector(saveTapped), for: .touchUpInside)
    }
}

class Player: NSObject {
    @objc dynamic var progress = 0.0               // observable with KVO
}
```

**Follow-ups:**
- **Does `@objc` alone make Swift calls use message dispatch?** No. Swift calls still use normal dispatch; only `dynamic` forces the Objective-C runtime.
- **What is method swizzling?** Swapping a method's implementation at runtime; it is powerful but risky and hard to debug.
- **Why don't you need KVO with `@Observable`?** The Observation framework tracks property access with macros, without the Objective-C runtime.

### Q90. How would you improve compile times in a large Swift project? `[Lead/Expert]`
First I measure, using Xcode's Build Timeline and the compiler flags that warn about slow functions. Then I add explicit types to complex expressions, break up long chains, split the app into smaller SPM modules, and keep interfaces small with `private` and `final`.

```swift
// Slow: the compiler must infer types through a long chain
let total = items.map { $0.price * 1.2 }.reduce(0, +) + tax + shipping - discount

// Faster: explicit types and smaller steps
let prices: [Double] = items.map { $0.price * 1.2 }
let subtotal: Double = prices.reduce(0, +)
let total: Double = subtotal + tax + shipping - discount

// Build setting to find slow functions:
// OTHER_SWIFT_FLAGS = -Xfrontend -warn-long-function-bodies=100
```

**Follow-ups:**
- **What is the most common cause of slow compiles?** Type inference on long or complex expressions, especially big literals and chained operators.
- **How does splitting into modules help?** A change in one module recompiles fewer files, and independent modules can build in parallel.
- **How do you stop build times from getting worse again?** Keep the slow-function warning flags on and track build times in CI.

### Q91. What runtime performance pitfalls do you watch for in Swift? `[Lead/Expert]`
I watch for `any Protocol` in hot paths, structs with many class properties that cause extra retain/release work on every copy, accidental full copies of large arrays, repeated O(n) string operations in loops, and heavy use of `AnyView` in SwiftUI. And I always profile with Instruments before optimizing.

```swift
// ❌ Calling count (O(n)) on every loop iteration
for i in 0..<text.count { /* ... */ }

// ✅ Iterate the string directly
for character in text { /* ... */ }
```

**Follow-ups:**
- **Which tool do you use to find slow code?** The Time Profiler in Instruments, on a real device with a Release build.
- **Why do structs with many class properties hurt performance?** Every copy has to retain each reference and later release it.
- **How do you reduce existential overhead?** Use generics or `some` in hot paths so the compiler knows the concrete type.

## 14. Advanced & Modern Swift

### Q92. What are result builders? Write a simple one. `[Lead/Expert]`
A result builder, marked `@resultBuilder`, turns a list of statements inside a closure into a single combined value. SwiftUI's `@ViewBuilder` is the best-known example.

```swift
@resultBuilder
struct ListBuilder {
    static func buildBlock(_ items: String...) -> [String] { items }
}

func makeList(@ListBuilder _ content: () -> [String]) -> [String] {
    content()
}

let items = makeList {
    "Swift"
    "SwiftUI"
}
// ["Swift", "SwiftUI"]
```

**Follow-ups:**
- **What does `buildOptional` support?** An `if` without an `else` inside the builder.
- **What does `buildEither` support?** `if/else` and `switch` statements, by building the first or second branch.
- **Where else are result builders used?** SwiftUI, `RegexBuilder`, and custom DSLs like HTML or layout builders.

### Q93. What are Swift macros? `[Lead/Expert]`
Macros generate code at compile time and can only add code, never change existing code. Freestanding macros start with `#`, like `#Preview`, and attached macros start with `@`, like `@Observable`; the trade-offs are longer build times and harder debugging.

```swift
@Observable                     // attached macro: generates observation code
final class CartModel {
    var items: [String] = []
}

#Preview {                      // freestanding macro
    CartView()
}
```

**Follow-ups:**
- **How are Swift macros different from C macros?** Swift macros work on the syntax tree, are type-checked, run in a sandbox, and can only add code, while C macros are blind text replacement.
- **How do you debug a macro?** Use "Expand Macro" in Xcode to see the generated code, and unit test it with `assertMacroExpansion`.
- **Why do macros add build time?** They depend on the swift-syntax library, which is large; using a prebuilt swift-syntax helps.

### Q94. What are key paths, and how are they useful? `[Senior]`
A key path is a type-safe reference to a property, written like `\User.name`, that you can store and use later. They are useful for generic sorting, mapping, and bindings, and you can even pass one as a function, as in `users.map(\.name)`.

```swift
struct User { let name: String; let age: Int }
let users = [User(name: "Sam", age: 30), User(name: "Ana", age: 25)]

let names = users.map(\.name)                     // ["Sam", "Ana"]
let byAge = users.sorted { $0[keyPath: \.age] < $1[keyPath: \.age] }
```

**Follow-ups:**
- **What is the difference between `WritableKeyPath` and `ReferenceWritableKeyPath`?** `WritableKeyPath` writes through a `var` value, while `ReferenceWritableKeyPath` writes to a class property, even through a `let` reference.
- **Where does SwiftUI use key paths?** In `ForEach(items, id: \.id)`, `@Environment(\.dismiss)`, and bindings like `$model.name`.
- **Can key paths go through nested properties?** Yes, for example `\User.address.city`.

### Q95. What is `@dynamicMemberLookup`? `[Lead/Expert]`
`@dynamicMemberLookup` lets a type respond to property access that it doesn't define itself, using a special subscript. When combined with key paths, it stays type-safe; SwiftUI's `Binding` uses it to make `$model.name` work.

```swift
@dynamicMemberLookup
struct Wrapper<T> {
    var value: T
    subscript<U>(dynamicMember keyPath: KeyPath<T, U>) -> U {
        value[keyPath: keyPath]
    }
}

let w = Wrapper(value: User(name: "Sam", age: 30))
print(w.name)   // "Sam", forwarded to value.name
```

**Follow-ups:**
- **Is there a string-based version?** Yes, `subscript(dynamicMember: String)`, which isn't type-safe and is mostly used for interop with dynamic languages.
- **What is the downside of `@dynamicMemberLookup`?** Readers may not realize the property is forwarded, though the key-path version still gives autocomplete and type checks.
- **Where is it used in SwiftUI?** `Binding` uses it so `$model.name` becomes a `Binding<String>` to that property.

### Q96. What is `callAsFunction`? `[Senior]`
`callAsFunction` is a method that lets you call an instance as if it were a function. SwiftUI uses it so you can write `dismiss()` with the `DismissAction` value.

```swift
struct Validator {
    let minLength: Int
    func callAsFunction(_ text: String) -> Bool {
        text.count >= minLength
    }
}

let isValid = Validator(minLength: 3)
isValid("Swift")     // true, same as isValid.callAsFunction("Swift")
```

**Follow-ups:**
- **Can a type have several `callAsFunction` methods?** Yes, they can be overloaded with different parameters.
- **Why use `callAsFunction` instead of a closure property?** The type can have state, other methods, and protocol conformances while still being called like a function.

### Q97. What are noncopyable types (`~Copyable`)? `[Lead/Expert]`
A noncopyable type, marked `~Copyable`, can't be copied, only moved, which guarantees there is exactly one owner of a resource like a file handle. Noncopyable structs can have a `deinit`, and a `consuming` method can end the value's lifetime.

```swift
struct FileHandle: ~Copyable {
    private let fd: Int32
    init(fd: Int32) { self.fd = fd }

    consuming func close() {
        print("closing \(fd)")
        discard self          // already cleaned up, skip deinit
    }

    deinit { print("auto-closing \(fd)") }
}

let file = FileHandle(fd: 3)
// let copy = file           // ❌ can't copy
file.close()
```

**Follow-ups:**
- **Can noncopyable types conform to protocols?** Yes, to protocols that support `~Copyable`, which Swift 6.0 made possible with noncopyable generics.
- **Can you store them in a normal `Array`?** No, `Array` needs copyable elements, but `Optional` and `InlineArray` can hold noncopyable values.
- **What are real examples?** File handles, tokens that must be used once, and `Mutex` from the Synchronization library.

### Q98. What do `consume`, `borrowing`, and `consuming` mean? `[Lead/Expert]`
They are ownership keywords that control copies explicitly. A `borrowing` parameter only reads the value while the caller keeps it, a `consuming` parameter takes ownership of it, and `consume x` ends a local variable's lifetime so the compiler can move it instead of copying.

```swift
func printName(_ user: borrowing User) { print(user.name) }   // read only
func save(_ user: consuming User) { database.store(user) }    // takes ownership

let user = User(name: "Sam", age: 30)
printName(user)
save(consume user)     // user can't be used after this line
```

**Follow-ups:**
- **Do you need these keywords in everyday app code?** Rarely. They matter mostly in performance-critical code and with noncopyable types.
- **What is required for a noncopyable parameter?** It must be marked `borrowing`, `consuming`, or `inout`, so ownership is always clear.
- **What is the difference between `consuming` and `inout`?** `inout` must give a valid value back to the caller, while `consuming` takes the value away for good.

### Q99. What are `if` and `switch` expressions? `[Fundamental]`
Since Swift 5.9, `if` and `switch` can directly produce a value, so you can assign their result to a variable without a temporary `var` or a closure.

```swift
let score = 82
let grade = if score > 90 { "A" } else if score > 75 { "B" } else { "C" }

let color: Color = switch status {
case .active:   .green
case .inactive: .gray
}
```

**Follow-ups:**
- **What are the limits of `if` and `switch` expressions?** Each branch must be a single expression of the same type, and you can't use them inside a larger expression like `if ... + 1`.
- **Can a branch throw or call `fatalError()`?** Yes, because those don't return a value.
- **Can you use them as a return value?** Yes, for example `return if isAdmin { .full } else { .limited }`, or as an implicit return.

### Q100. What does the Swift 6 language mode change? `[Senior]`
The Swift 6 language mode turns data-race safety checks into errors instead of warnings, so `Sendable` issues, actor isolation problems, and unsafe global state must be fixed. It also requires the `any` keyword for existential types; teams usually adopt it module by module.

```swift
// ❌ Error in Swift 6: global mutable state isn't concurrency-safe
var cache: [String: Data] = [:]

// ✅ Fix: protect it with an actor (or isolate it to @MainActor)
actor Cache {
    var storage: [String: Data] = [:]
}
```

**Follow-ups:**
- **What is `Sendable`?** A protocol that marks a type as safe to pass between concurrent tasks or actors.
- **Can you use the Swift 6 compiler but stay in Swift 5 mode?** Yes. The language mode is set per target, so you can migrate one module at a time.
- **What is `@unchecked Sendable`?** You tell the compiler you guarantee thread safety yourself, for example with a lock; the compiler stops checking, so use it carefully.

### Q101. What notable features arrived in Swift 6.x? `[Lead/Expert]`
Swift 6.0 brought typed throws, pack iteration, and noncopyable generics; Swift 6.2 added `InlineArray`, `Span`, and "approachable concurrency" with main-actor-by-default; Swift 6.3 added the `@c` attribute for C interop and an official Android SDK; and Swift 6.4 in Xcode 27 added the `anyAppleOS` availability shorthand and `async defer`. Be ready to say which ones you have actually used.

```swift
// Swift 6.2: fixed-size array stored inline, no heap allocation
var rgb: InlineArray<3, UInt8> = [255, 128, 0]

// Swift 6.4: one name for every Apple platform
@available(anyAppleOS 27, *)
func newFeature() {}
```

**Follow-ups:**
- **What is `Span`?** A safe, non-escaping view over contiguous memory that replaces many uses of unsafe buffer pointers.
- **What does "main actor by default" mean?** With the Default Actor Isolation setting set to `MainActor`, code in that module runs on the main actor unless you mark it otherwise.
- **What does `@concurrent` do?** In Swift 6.2 it marks an async function to run off the caller's actor, on the shared background executor.

## 15. Codable

### Q102. How does `Codable` work? `[Fundamental]`
`Codable` is a combination of `Encodable` and `Decodable`, and the compiler writes the encoding and decoding code for you when all properties are themselves `Codable`. You then use an encoder or decoder, like `JSONDecoder`, to convert between your type and data.

```swift
struct User: Codable {
    let id: Int
    let name: String
}

let json = #"{"id": 1, "name": "Sam"}"#.data(using: .utf8)!
let user = try JSONDecoder().decode(User.self, from: json)
let data = try JSONEncoder().encode(user)
```

**Follow-ups:**
- **Which types are `Codable` out of the box?** Basic types like `String`, `Int`, `Double`, `Bool`, `Date`, `URL`, and `Data`, plus arrays, dictionaries, and optionals of `Codable` types.
- **How do you skip a property when decoding?** Leave it out of `CodingKeys` and give it a default value.
- **How are `Date`s encoded by default?** As a number of seconds since January 1, 2001, so you usually set a `dateEncodingStrategy` like `.iso8601`.

### Q103. How do you handle mismatched keys, missing values, and custom formats? `[Senior]`
I use `CodingKeys` to map JSON keys to property names, `decodeIfPresent` with a default for missing values, and decoder strategies like `.convertFromSnakeCase` and `.iso8601` for common formats.

```swift
struct User: Decodable {
    let id: Int
    let isPremium: Bool

    enum CodingKeys: String, CodingKey {
        case id
        case isPremium = "is_premium"           // mismatched key
    }

    init(from decoder: Decoder) throws {
        let c = try decoder.container(keyedBy: CodingKeys.self)
        id = try c.decode(Int.self, forKey: .id)
        isPremium = try c.decodeIfPresent(Bool.self, forKey: .isPremium) ?? false  // missing value
    }
}

let decoder = JSONDecoder()
decoder.dateDecodingStrategy = .iso8601        // custom format
```

**Follow-ups:**
- **What happens if you use `.convertFromSnakeCase` and custom `CodingKeys` together?** The keys are converted first, so your custom raw values must match the camelCase form, not the original snake_case.
- **How do you decode a nested JSON object?** Use `nestedContainer(keyedBy:forKey:)`, or create a small nested struct.
- **How do you debug a `DecodingError`?** Print it or catch cases like `.keyNotFound`; it includes the `codingPath`, which shows exactly where decoding failed.

### Q104. How do you decode an enum safely when the server may add new values? `[Senior]`
A normal `String` enum throws an error on an unknown value, which breaks decoding of the whole response. I add a fallback case, like `unknown(String)`, so new server values are kept instead of crashing the decode.

```swift
enum Status: Decodable {
    case active, suspended, unknown(String)

    init(from decoder: Decoder) throws {
        let raw = try decoder.singleValueContainer().decode(String.self)
        switch raw {
        case "active":    self = .active
        case "suspended": self = .suspended
        default:          self = .unknown(raw)
        }
    }
}
```

**Follow-ups:**
- **Is there a shorter way when the enum has raw values?** Yes, `self = Status(rawValue: raw) ?? .unknown` inside the custom `init(from:)`.
- **How do you encode it back?** Implement `Encodable` and write the raw string for each case, including the stored string for `.unknown`.
- **Why not just let decoding fail?** The server can ship new values before every user has updated the app, and old app versions would break.

### Q105. How would you decode a heterogeneous array (e.g. a feed with different item types)? `[Lead/Expert]`
I first decode a `type` field that tells me what kind of item it is, then decode the matching model into an enum with associated values. Unknown types go into an `unsupported` case so one new item type doesn't break the whole feed.

```swift
enum FeedItem: Decodable {
    case post(Post)
    case ad(Ad)
    case unsupported

    private enum CodingKeys: String, CodingKey { case type }

    init(from decoder: Decoder) throws {
        let type = try decoder.container(keyedBy: CodingKeys.self)
            .decode(String.self, forKey: .type)
        switch type {
        case "post": self = .post(try Post(from: decoder))
        case "ad":   self = .ad(try Ad(from: decoder))
        default:     self = .unsupported
        }
    }
}
```

**Follow-ups:**
- **How do you skip one broken item without failing the whole array?** Decode each element in an unkeyed container with `try?`, and on failure decode a throwaway type to move to the next element.
- **How would you encode this enum?** `switch` on `self`, encode the payload, and add the matching `type` key.
- **Why can `Post(from: decoder)` reuse the same decoder?** The `type` field is in the same JSON object, and `Post` simply ignores keys it doesn't know.

### Q106. Closure capture `[Senior]`
```swift
var x = 10
let a = { print(x) }
let b = { [x] in print(x) }
x = 20
a()
b()
```
**Output:** `20` then `10`.
`a` captures the variable itself, so it sees the new value; `b` uses a capture list, so it keeps a copy of the value from when it was created.

**Follow-ups:**
- **How would you make `a` also print `10`?** Add a capture list, `{ [x] in print(x) }`, or copy the value into a `let` before creating the closure.
- **If `x` were a class instance and you changed one of its properties, what would `b` print?** The new value, because the capture list copies the reference, not the object.

### Q107. Struct vs class copy `[Fundamental]`
```swift
struct PointS { var x = 0 }
class PointC { var x = 0 }

var s1 = PointS(); var s2 = s1; s2.x = 5
let c1 = PointC(); let c2 = c1; c2.x = 5
print(s1.x, c1.x)
```
**Output:** `0 5`.
The struct was copied, so changing `s2` doesn't touch `s1`; the class is shared, so `c1` and `c2` are the same object.

**Follow-ups:**
- **What if `PointS` also had a class property and you changed it through `s2`?** That change would show up in `s1` too, because both struct copies point to the same object.
- **What if `c2` were a struct declared with `let`?** `c2.x = 5` would be a compile error, because a `let` struct is fully immutable.

### Q108. Classes inside an array `[Senior]`
```swift
class Box { var value = 0 }
var a = [Box()]
var b = a
b[0].value = 5
print(a[0].value)
```
**Output:** `5`.
The array itself is copied, but both arrays hold a reference to the same `Box` object.

**Follow-ups:**
- **How would you make `b` fully independent of `a`?** Make `Box` a struct, or copy each object, like `b = a.map { Box(copying: $0) }`.
- **Would `b[0] = Box()` change `a`?** No. Replacing an element changes only `b`'s own copy of the array.

### Q109. Protocol extension dispatch `[Senior]`
```swift
protocol Animal { func sound() -> String }
extension Animal {
    func sound() -> String { "..." }
    func describe() -> String { "Generic animal" }
}
struct Dog: Animal {
    func sound() -> String { "Woof" }
    func describe() -> String { "Dog" }
}
let pet: Animal = Dog()
print(pet.sound(), pet.describe())
```
**Output:** `Woof Generic animal`.
`sound()` is a protocol requirement, so `Dog`'s version is used; `describe()` exists only in the extension, so the version is picked from the declared type `Animal`.

**Follow-ups:**
- **How would you make `describe()` print `"Dog"`?** Add `describe()` to the protocol as a requirement, or declare the variable as `let pet = Dog()`.
- **What would print if `pet` were declared as `Dog`?** `Woof Dog`, because the concrete type's methods are used.

### Q110. `defer` order `[Fundamental]`
```swift
func test() {
    defer { print("1") }
    defer { print("2") }
    print("3")
}
test()
```
**Output:** `3 2 1`.
The normal code runs first, then the `defer` blocks run in reverse order.

**Follow-ups:**
- **What happens if the function returns before reaching the second `defer`?** Only the `defer` blocks that were already reached run.
- **What happens with a `defer` inside a loop?** It runs at the end of every iteration, not at the end of the function.

### Q111. `defer` and return values `[Senior]`
```swift
func value() -> Int {
    var x = 1
    defer { x = 100 }
    return x
}
print(value())
```
**Output:** `1`.
The return value is calculated before `defer` runs, so changing `x` afterwards doesn't affect what is returned.

**Follow-ups:**
- **What if the function returned a class instance and `defer` changed one of its properties?** The caller would see the change, because it receives the same object.
- **What if `x` were an `inout` parameter?** The caller would see `100`, because `defer` runs before the value is written back.

### Q112. Property observers during init `[Senior]`
```swift
class Counter {

    init() { value = 10 }
}
let c = Counter()
c.value = 20
```
**Output:** only `didSet 20`.
Observers don't run when a class sets its own property inside its own `init`, only on later changes.

**Follow-ups:**
- **Would `didSet` fire if a subclass set `value` in its own `init`?** Yes, after calling `super.init`.
- **Is there a way to trigger the observer during `init`?** Yes, a known trick is setting the property inside a `defer` block in `init`, but it's clearer to call the logic directly.

### Q113. Generic overload resolution `[Lead/Expert]`
```swift
func describe<T>(_ v: T) { print("generic") }
func describe(_ v: Int) { print("Int") }
func wrapper<T>(_ v: T) { describe(v) }

describe(5)
wrapper(5)
```
**Output:** `Int` then `generic`.
Swift picks overloads at compile time; inside `wrapper`, the compiler only knows `v` is some `T`, not an `Int`.

**Follow-ups:**
- **How would you make `wrapper(5)` print `"Int"`?** Add a non-generic `wrapper(_ v: Int)` overload, or check at runtime with `if let i = v as? Int { describe(i) }`.
- **Is this related to protocol extension dispatch?** Yes, both are decided at compile time from the static type, not the runtime type.

### Q114. Mutating an array while iterating `[Senior]`
```swift
var nums = [1, 2, 3]
for n in nums { nums.append(n) }
print(nums)
```
**Output:** `[1, 2, 3, 1, 2, 3]`.
The loop iterates over a copy of the original array, so appending doesn't cause an infinite loop or a crash.

**Follow-ups:**
- **What would happen with `NSMutableArray` and fast enumeration?** Changing it while enumerating throws an exception and crashes, because it is a reference type.
- **How do you safely remove items that match a condition?** Use `nums.removeAll { $0 > 1 }` instead of removing inside a loop.

### Q115. Lazy closure retain cycle `[Senior]`
```swift
class ViewModel {
    var name = "A"
    lazy var greet: () -> String = { "Hello \(self.name)" }
    deinit { print("deinit") }
}
var vm: ViewModel? = ViewModel()
_ = vm?.greet()
vm = nil
```
**Output:** nothing is printed.
The object stores a closure that strongly captures `self`, creating a retain cycle, so `deinit` never runs; fix it with `{ [unowned self] in ... }` or `[weak self]`.

**Follow-ups:**
- **Why is `[unowned self]` safe here?** The closure is stored on `self`, so it can never outlive `self`.
- **Would `lazy var greeting: String = { "Hello \(self.name)" }()` leak?** No. That closure runs once immediately and isn't stored, so no cycle is created.

### Q116. String counting `[Senior]`

- **What does `family.utf16.count` print?** `8`: each emoji takes 2 UTF-16 units and each joiner takes 1.

### Q117. `let` with reference vs value types `[Fundamental]`
```swift
class User { var name = "A" }
struct Config { var name = "A" }

let u = User()
u.name = "B"      // ?
let c = Config()
c.name = "B"      // ?
```
**Answer:** The class line compiles; the struct line is a compile error.
`let` on a class only fixes the reference, but `let` on a struct makes the whole value, including its properties, immutable.

**Follow-ups:**
- **What if `User.name` were declared with `let`?** Then `u.name = "B"` would also fail, because the property itself is a constant.
- **What if `c` were declared with `var`?** Then `c.name = "B"` would compile, because the struct value is now mutable.

## 18. Senior / Lead Scenario Questions

> These have no single correct answer. Interviewers look at your reasoning, trade-offs, and communication, so start with the short answer, then explain the "why."

### Q118. How do you decide between struct, class, enum, and actor in a large codebase? `[Senior]`
I default to a struct for models and data, an enum for a fixed set of states, a class when I need identity, a lifecycle, or UIKit interop, and an actor when mutable state is shared across concurrent tasks. I also think about how each choice affects testing, thread safety, and `Sendable` in Swift 6.

```swift
struct Product: Sendable { let id: Int; let price: Double }   // data
enum CheckoutState { case cart, paying, done }                // states
@MainActor final class CheckoutViewModel {}                   // UI lifecycle
actor InventoryStore { var stock: [Int: Int] = [:] }          // shared, concurrent
```

**Follow-ups:**
- **When is an actor overkill?** When the state is only used from the main thread; a `@MainActor` class is simpler.
- **How do you make a class `Sendable`?** Make it `final` with only immutable, `Sendable` properties, or protect its state with a lock and mark it `@unchecked Sendable`.
- **Should a SwiftUI view model be a struct?** Usually not; use an `@Observable` class, and keep simple local state in `@State`.

### Q119. Design a type-safe networking layer using Swift features. `[Lead/Expert]`
I define an `Endpoint` protocol with an associated `Response` type, so every request knows exactly what it returns, and a generic `APIClient` that sends it with async/await and decodes the result. The session is injected so I can mock it in tests; follow-ups to prepare are token refresh, retries, cancellation, and caching.

```swift
protocol Endpoint {
    associatedtype Response: Decodable
    var path: String { get }
    var method: String { get }
}

struct APIClient {
    let baseURL: URL
    var session: URLSession = .shared

    func send<E: Endpoint>(_ endpoint: E) async throws -> E.Response {
        var request = URLRequest(url: baseURL.appending(path: endpoint.path))
        request.httpMethod = endpoint.method
        let (data, response) = try await session.data(for: request)
        guard let http = response as? HTTPURLResponse,
              (200..<300).contains(http.statusCode) else {
            throw URLError(.badServerResponse)
        }
        return try JSONDecoder().decode(E.Response.self, from: data)
    }
}
```

**Follow-ups:**
- **How would you handle token refresh?** Use an actor that refreshes the token once and lets all waiting requests share the new token, then retry them.
- **How would you test the client?** Inject a protocol instead of `URLSession`, or register a custom `URLProtocol` that returns fake responses.
- **How does cancellation work?** If the calling `Task` is cancelled, `session.data(for:)` stops and throws a cancellation error automatically.

### Q120. How would you plan migrating a large app to Swift 6 language mode? `[Lead/Expert]`
I migrate step by step, not all at once: turn on strict concurrency checking module by module, start with leaf modules like models and utilities, then features, then the app target. Along the way I make models `Sendable`, put UI code on `@MainActor`, turn shared singletons into actors, and track every `@unchecked Sendable` as tech debt.

```swift
// 1. Models become Sendable
struct Order: Sendable { let id: UUID; let total: Double }

// 2. UI code is isolated to the main actor
@MainActor final class OrdersViewModel: ObservableObject {
    @Published var orders: [Order] = []
}

// 3. Old dependencies that aren't updated yet
@preconcurrency import LegacyAnalytics
```

**Follow-ups:**
- **What are the strict concurrency levels?** `minimal`, `targeted`, and `complete`, from the fewest checks to full Swift 6 checking.
- **What do you do with third-party code that isn't `Sendable`?** Use `@preconcurrency import`, or wrap it behind an actor until the library is updated.
- **How do you track progress?** Count concurrency warnings per module and watch them go down release by release.

### Q121. How do you enforce code quality and consistency across a team? `[Lead/Expert]`
I automate everything a machine can check, with SwiftLint, SwiftFormat, and CI that requires passing tests, so code reviews can focus on design and correctness instead of style. I also write down shared conventions and decisions in ADRs and document APIs with DocC.

```yaml
# .swiftlint.yml
opt_in_rules:
  - force_unwrapping
  - implicitly_unwrapped_optional
force_try: error
line_length: 120
```

**Follow-ups:**
- **What should code reviews focus on?** Design, correctness, edge cases, and tests, and leave formatting to automated tools.
- **How do you handle disagreements in reviews?** Point to the agreed guidelines or ADRs, and if it is still unclear, talk it through instead of a long comment thread.
- **How do you help new developers follow the conventions?** Clear docs, lint rules that explain themselves, small starter tasks, and pairing on the first pull requests.

### Q122. Your team wants to adopt macros (or another new Swift feature). How do you evaluate it? `[Lead/Expert]`
I ask what problem it solves and how much boilerplate or bug risk it removes, then weigh that against costs like build time, debugging difficulty, and onboarding. I run a short spike in one module, measure the results, record the decision in an ADR, and check how easy it would be to back out.

```swift
// Before: manual boilerplate the macro would replace
final class CartModel: ObservableObject {
    @Published var items: [String] = []
}

// After: one macro, less code (spike this in one module first, then measure build time)
@Observable final class CartModel {
    var items: [String] = []
}
```

**Follow-ups:**
- **How would you measure a feature's build-time impact?** Compare clean and incremental build times before and after, using Xcode's Build Timeline.
- **What if the team is split on adopting it?** Run a time-boxed spike, collect data, and record the decision and its reasons in an ADR.

### Q123. How would you design a public Swift SDK used by other teams or companies? `[Lead/Expert]`
I keep the public surface as small as possible, follow the Swift API Design Guidelines, choose `public` vs `open` on purpose, and use semantic versioning with clear deprecations. For binary distribution I turn on library evolution and use `@frozen` only when a layout will truly never change, and I ship via SPM or XCFramework with DocC documentation.

```swift
public struct PaymentSDK {
    public init(apiKey: String) {}

    public func pay(amount: Decimal) async throws -> Receipt { /* ... */ }

    @available(*, deprecated, renamed: "pay(amount:)")
    public func makePayment(_ amount: Decimal) async throws -> Receipt {
        try await pay(amount: amount)
    }
}
```

**Follow-ups:**
- **How do you version and remove old APIs?** Use semantic versioning, deprecate first with `@available(*, deprecated, renamed:)`, and remove only in the next major version.
- **How do you avoid breaking binary compatibility?** Add new APIs instead of changing existing ones, and never change the layout of a `@frozen` type.
- **How do you make the SDK easy for clients to test?** Expose the main services as protocols, so clients can mock them.

### Q124. Production has crashes from force unwraps and `fatalError`s. What do you do as a lead? `[Lead/Expert]`
In the short term I use crash reports to find and hotfix the top offenders. Then I fix the root cause by making invalid states impossible, using non-optional types, enums, and validation at boundaries, and I prevent it from coming back with lint rules for force unwraps, review checklists, and edge-case tests.

```swift
// ❌ Before: crashes if the server omits "name"
let name = json["name"] as! String

// ✅ After: handle the missing value safely
guard let name = json["name"] as? String else {
    logger.error("Missing name in response")
    return .failed(.invalidData)
}
```

**Follow-ups:**
- **How do you get the team to stop using force unwraps?** Share the crash data, add a lint rule, and fix existing ones gradually instead of all at once.
- **When is `fatalError` acceptable?** For code that is truly unreachable, like an unused `init(coder:)`, or a broken app configuration that must be caught during development.

### Q125. How would you explain value semantics to a junior developer? `[Senior]`
I'd say a value type is like handing someone a photocopy: they can write on it and your original stays the same, while a reference type is like sharing a Google Doc link where everyone edits the same document. Then I'd show a short example and the bug that value semantics prevents; here the interviewer is really checking your mentoring and communication skills.

```swift
struct Note { var text: String }      // photocopy
class SharedNote { var text = "" }    // shared link

var mine = Note(text: "Hi")
var yours = mine
yours.text = "Changed"
print(mine.text)                      // "Hi" (my copy is safe)
```

**Follow-ups:**
- **How would you check that the junior really understood?** Ask them to predict the output of a small example, then pair with them on a real bug.
- **When would you tell them reference semantics is the right choice?** When something must be shared and stay in sync, like a single download manager used by several screens.
