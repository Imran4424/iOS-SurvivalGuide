## 1. Fundamentals

### Q1. What is SwiftUI, and how does declarative UI differ from imperative UI? `[Fundamental]`
SwiftUI is Apple's declarative UI framework: you describe what the screen should look like for the current state, and SwiftUI updates the screen when the state changes. In imperative UIKit you change views step by step yourself, like `label.text = ...`, so you have to keep the UI and the data in sync by hand.

```swift
struct CounterView: View {
    @State private var count = 0

    var body: some View {
        VStack {
            Text("Count: \(count)")             // UI is a function of state
            Button("Increment") { count += 1 }  // change state, SwiftUI updates the text
        }
    }
}
```

**Follow-ups:**
- **What is the main benefit of declarative UI?** A whole class of "the UI doesn't match the data" bugs disappears, because the UI is always rebuilt from the current state.
- **What is the cost?** You must understand how SwiftUI tracks state and identity, otherwise you get surprising resets and extra updates.
- **Can you mix SwiftUI and UIKit?** Yes, with `UIHostingController` to put SwiftUI in UIKit, and `UIViewRepresentable` to put UIKit in SwiftUI.

### Q2. What is the `View` protocol? `[Fundamental]`
`View` is the protocol every SwiftUI view conforms to; it requires a `body` property that returns `some View`. Built-in views like `Text` and `Image` are primitive views that SwiftUI draws directly, and since the iOS 18 SDK the `View` protocol is marked `@MainActor`.

```swift
struct Greeting: View {
    let name: String

    var body: some View {          // the only requirement
        Text("Hello, \(name)")
    }
}
```

**Follow-ups:**
- **What is the `Body` type of `Text`?** `Never`, because `Text` is a primitive view that SwiftUI renders directly instead of building from other views.
- **What does `@MainActor` on `View` mean for you?** `body` and view methods run on the main actor, so you can update UI-bound models from them without `await`.
- **Can a view have no `body`?** Only primitive framework views; every view you write must provide one.

### Q3. Why are SwiftUI views structs instead of classes? `[Senior]`
SwiftUI views are lightweight descriptions of the UI, not the real on-screen objects, and SwiftUI creates and throws them away all the time, which is cheap with structs. The data that must last, like `@State`, is stored by SwiftUI outside the struct.

```swift
struct Badge: View {
    let count: Int                // input, recreated with the struct
    @State private var isPulsing = false   // stored by SwiftUI, survives recreation

    var body: some View {
        Text("\(count)")
            .scaleEffect(isPulsing ? 1.2 : 1)
    }
}
```

**Follow-ups:**
- **Where is `@State` actually stored?** In SwiftUI's internal storage (the attribute graph), tied to the view's identity, not inside the struct.
- **Why is it a mistake to store data in a normal `var` in a view?** The struct is recreated on every parent update, so the value is lost and changing it doesn't trigger an update.
- **Do views being structs prevent memory leaks?** The views themselves can't leak, but the reference-type models they hold still can.

### Q4. Why does `body` return `some View`? `[Senior]`
`some View` hides the real, very long nested type of the body, while still letting the compiler know it exactly. Knowing the exact type lets SwiftUI compare old and new views efficiently and work out each view's structural identity.

```swift
struct ProfileHeader: View {
    var body: some View {     // real type: VStack<TupleView<(Text, Button<Text>)>>
        VStack {
            Text("Sam")
            Button("Follow") {}
        }
    }
}
```

**Follow-ups:**
- **Can different branches of `body` return different view types?** Only through `@ViewBuilder`, which wraps both branches into one type.
- **Why not return `AnyView` instead?** `AnyView` hides the type from SwiftUI too, which hurts identity and diffing.
- **What is the difference between `some View` and `any View`?** `some View` is one fixed type known to the compiler; `any View` would be a box that can hold different types at runtime.

### Q5. What is `@ViewBuilder`? `[Fundamental]`
`@ViewBuilder` is a result builder that turns several statements, including `if` and `switch`, into one combined view. `body` is a view builder automatically, and you can mark your own properties, functions, and closure parameters with it.

```swift
struct ProfileView: View {
    let user: User?

    var body: some View {
        VStack {
            header
            if let user { Text(user.name) } else { Text("Guest") }
        }
    }

    @ViewBuilder
    private var header: some View {
        if user?.isPremium == true {
            Label("Premium", systemImage: "star.fill")
        }                                   // empty branch is allowed
    }
}
```

**Follow-ups:**
- **What does a view builder turn an `if/else` into?** A `_ConditionalContent` view that holds either branch, so the result is still one type.
- **What does an `if` without `else` become?** An optional view that shows nothing when the condition is false.
- **What changed in iOS 27 / Xcode 27?** `ViewBuilder` is now exposed as `ContentBuilder`, which Apple says significantly improves build times.

### Q6. Why does modifier order matter? `[Fundamental]`
Each modifier wraps the view in a new view, so modifiers apply from the inside out in the order you write them. Changing the order changes what each modifier affects.

```swift
Text("Hello")
    .padding()
    .background(.yellow)   // yellow covers text + padding

Text("Hello")
    .background(.yellow)   // yellow covers only the text
    .padding()             // padding is outside the yellow area
```

**Follow-ups:**
- **Which other pairs are order-sensitive?** `.frame` with `.border`, `.clipShape` with `.shadow`, and `.padding` with `.onTapGesture`, which changes the tap area.
- **Why does `.shadow` after `.clipShape` work but not before?** Applied before, the shadow is drawn outside the shape and then clipped away.
- **How do you think about a modifier chain?** Read it top to bottom as layers wrapping each other, like boxes inside boxes.

### Q7. What are `Group`, `EmptyView`, and `AnyView`? `[Fundamental]`
`Group` groups views without changing the layout and lets you apply a modifier to all of them; `EmptyView` is a view that shows nothing; and `AnyView` is a type-erased view that hides the concrete type. I avoid `AnyView` because it stops SwiftUI from using structural identity and efficient diffing.

```swift
Group {
    Text("Title")
    Text("Subtitle")
}
.font(.headline)            // applies to both texts

func makeBadge(isNew: Bool) -> some View {
    isNew ? AnyView(Text("NEW")) : AnyView(EmptyView())   // ❌ works, but erases type
}
```

**Follow-ups:**
- **What should you use instead of `AnyView`?** `@ViewBuilder`, `Group`, or generics, which keep the real type.
- **When is `AnyView` acceptable?** In rare places like a plugin system where views of truly unknown types come from outside.
- **Does `Group` add anything to the layout?** No, its children are laid out as if they belonged to the parent directly.

### Q8. What happens when a `@State` value changes? `[Senior]`
SwiftUI marks the views that read that state as invalid, runs their `body` again, compares the new description with the old one using identity, and applies only the minimal changes to the screen. Views that don't read the changed state aren't re-evaluated at all.

```swift
struct Screen: View {
    @State private var count = 0

    var body: some View {
        VStack {
            Text("\(count)")        // reads count → updates
            StaticFooter()          // doesn't read count → body skipped
            Button("+1") { count += 1 }
        }
    }
}
```

**Follow-ups:**
- **Is the update applied immediately?** No, it happens in the next render pass, so several changes in one event are combined into one update.
- **Does re-running `body` mean the whole screen is redrawn?** No. `body` only produces a description; SwiftUI updates only the parts that actually changed.
- **Why does this matter for performance?** The fewer views that read a frequently changing value, the less work each change causes.

## 2. View Identity, Lifetime & Dependencies

> This is the single most important topic for senior SwiftUI interviews. Apple's WWDC21 session "Demystify SwiftUI" is the canonical reference.

### Q9. What is view identity, and why does it matter? `[Senior]`
Identity is how SwiftUI recognizes that a view in the new update is the same view as before. It decides how long `@State` lives, whether a change animates in place or plays an insert/remove transition, and how little work an update needs.

```swift
// Same identity: the toggle keeps its state and the color animates
Circle()
    .fill(isOn ? .green : .red)
    .animation(.default, value: isOn)
```

**Follow-ups:**
- **What happens to `@State` when identity changes?** It is thrown away, and the new view starts with fresh state.
- **What happens visually when identity changes?** The old view is removed and the new one inserted, with a fade transition by default.
- **What are the two kinds of identity?** Structural identity, from type and position, and explicit identity, from `.id` or `ForEach` IDs.

### Q10. What are structural identity and explicit identity? `[Senior]`
Structural identity comes from a view's type and position in the hierarchy, so the two branches of an `if/else` are different views. Explicit identity is an ID you give yourself, with `.id(_:)` or through the IDs in `ForEach` and `List`.

```swift
// Structural: two different views with separate state
if isLoggedIn {
    HomeView()
} else {
    LoginView()
}

// Explicit: identity tied to data
ForEach(messages) { message in      // uses message.id
    MessageRow(message: message)
}
```

**Follow-ups:**
- **Which one does SwiftUI use by default?** Structural identity; explicit identity is added only where you provide IDs.
- **Why does `AnyView` break structural identity?** It hides the type, and type is one half of what structural identity is built from.
- **Does `if #available` create two identities?** Yes, but that's fine because the OS version never changes while the app runs.

### Q11. When should you use a conditional modifier instead of `if/else`? `[Senior]`
When the view is the same and only a property changes, use a ternary inside the modifier, because that keeps one identity, so state is kept and the change animates smoothly. An `if/else` creates two identities, so switching branches destroys one view and its state and creates another.

```swift
// ❌ Two identities: state resets, cross-fade
if isHighlighted {
    CardView().background(.yellow)
} else {
    CardView()
}

// ✅ One identity: state kept, background animates
CardView()
    .background(isHighlighted ? Color.yellow : Color.clear)
```

**Follow-ups:**
- **What's wrong with the popular `.if(condition) { $0.modifier() }` extension?** It hides an `if/else` inside, so it causes the same identity reset.
- **When is `if/else` the right choice?** When the two branches are truly different views, like a login screen versus a home screen.
- **How do you hide a view without losing its state?** Use `.opacity(0)` or `.hidden()` instead of removing it with `if`.

### Q12. What does `.id(_:)` do, and when would you use it? `[Senior]`
`.id(_:)` gives a view an explicit identity, and changing the ID destroys the view and creates a new one, resetting all its state. I use it to reset a form when a different item is selected, and as a target for `ScrollViewReader`.

```swift
// Reset the editor's internal state when a different document is selected
DocumentEditor(document: selectedDocument)
    .id(selectedDocument.id)
```

**Follow-ups:**
- **What is the classic misuse of `.id`?** Passing a value that changes on every update, like `UUID()`, which rebuilds the view every time.
- **Does `.id` restart `.task` and `onAppear`?** Yes, because a new identity means a new view that appears again.
- **How else can you scroll to a view?** With `ScrollViewReader` and `proxy.scrollTo(id)`, or with `scrollPosition(id:)` in iOS 17.

### Q13. What is the difference between a view's lifetime and its identity? `[Senior]`
The view struct is short-lived: it is recreated every time the parent's `body` runs. The view's lifetime is how long its identity stays in the hierarchy, and `@State`, `@StateObject`, and `.task` are tied to that lifetime, not to the struct.

```swift
struct Row: View {
    let title: String
    init(title: String) {
        self.title = title
        print("init")      // can print many times for one row on screen
    }
    var body: some View { Text(title) }
}
```

**Follow-ups:**
- **Why shouldn't you do expensive work in a view's `init`?** It can run many times for a single view on screen.
- **Where should setup work go instead?** In `.task` or `.onAppear`, which run once per appearance of the view's identity.
- **When does a view's lifetime end?** When its identity leaves the hierarchy, for example when an `if` branch switches or a row is removed.

### Q14. Why must `ForEach` identifiers be stable and unique? `[Senior]`
SwiftUI uses the IDs to match rows between updates, so unstable IDs cause wrong animations, rows that lose their state, and extra work. Duplicate IDs are undefined behavior: the wrong row can be shown or updated.

```swift
// ❌ Index identity: deleting row 0 shifts every row's identity
ForEach(items.indices, id: \.self) { index in
    ItemRow(item: items[index])
}

// ✅ Stable, unique identity
ForEach(items) { item in        // Item: Identifiable, id from server/database
    ItemRow(item: item)
}
```

**Follow-ups:**
- **Is `id: \.self` ever fine?** Yes, for a static list of unique values like `["S", "M", "L"]` that never changes.
- **Why not create a `UUID()` in the model's `init` for API data?** If the model is rebuilt on each fetch, it gets a new ID every time; use the server's ID instead.
- **What do you see when IDs are duplicated?** A console warning, plus rows showing or updating the wrong content.

### Q15. What are a view's dependencies? `[Senior]`
A view's dependencies are everything it reads that can change: its input properties, `@State`, `@Binding`, environment values, and observed model properties. When one of them changes, SwiftUI re-runs that view's `body`.

```swift
struct PriceLabel: View {
    let price: Decimal                         // input
    @Environment(\.locale) private var locale  // environment
    @State private var showDetails = false     // local state

    var body: some View {
        Text(price, format: .currency(code: "USD"))
    }
}
```

**Follow-ups:**
- **How do you reduce a view's dependencies?** Pass only the values it needs, like `item.title` instead of the whole model.
- **Are values read only inside a button action dependencies?** No. Only values read while `body` runs are tracked.
- **How can you see which dependency changed?** Call `Self._printChanges()` inside `body` while debugging.

### Q16. Does SwiftUI re-run `body` for a child when its parent's `body` runs? `[Lead/Expert]`
The child struct is recreated, but SwiftUI compares its inputs with the previous ones, and if they are equal, it can skip the child's `body`. Closures and non-equatable reference types can't be compared well, so children holding closures are often re-evaluated anyway.

```swift
struct Parent: View {
    @State private var tick = 0
    var body: some View {
        VStack {
            Button("Tick \(tick)") { tick += 1 }
            Avatar(name: "Sam")      // same input → body can be skipped
        }
    }
}
```

**Follow-ups:**
- **How can you control this comparison yourself?** Make the view `Equatable` and compare only the fields that matter (see Q102).
- **Why do closures defeat the comparison?** SwiftUI can't tell whether two closures are the same, so it assumes the input changed.
- **Is skipping guaranteed?** No. It is an optimization, so code must stay correct even if `body` runs more often.

## 3. State Management & Property Wrappers

### Q17. What is `@State`? `[Fundamental]`
`@State` declares a value that the view itself owns; SwiftUI stores it outside the struct and keeps it for the view's lifetime, re-running `body` when it changes. I use it for simple local UI state like toggles, text input, and selection, and since iOS 17 also to own `@Observable` models.

```swift
struct SearchBar: View {
    @State private var text = ""        // owned by this view, private

    var body: some View {
        TextField("Search", text: $text)
    }
}
```

**Follow-ups:**
- **Why mark `@State` as `private`?** Only the owning view should set and change it; others should get a binding.
- **Can `@State` hold a class?** Yes, since iOS 17 for `@Observable` classes, which is how a view owns its model.
- **What happens to `@State` when the view leaves the screen?** It is discarded when the view's identity leaves the hierarchy.

### Q18. What is `@Binding`? `[Fundamental]`
`@Binding` is a two-way connection to a value that someone else owns, so the child can read and change it without owning it. You create one from state with the `$` prefix.

```swift
struct SettingsView: View {
    @State private var notificationsEnabled = true
    var body: some View {
        NotificationToggle(isOn: $notificationsEnabled)
    }
}

struct NotificationToggle: View {
    @Binding var isOn: Bool
    var body: some View { Toggle("Notifications", isOn: $isOn) }
}
```

**Follow-ups:**
- **Does a binding copy the value?** No, it reads and writes the original source of truth.
- **When should a child use `@Binding` instead of a plain `let`?** Only when it needs to change the value; for read-only use, a plain property is simpler.
- **How do you preview a view that needs a binding?** Use `.constant(true)`, or `@Previewable @State` in iOS 18 previews.

### Q19. How do you create custom, derived, and constant bindings? `[Senior]`
You can build a binding with custom `get` and `set` closures, get bindings to collection elements with `List($items)`, reach into properties with `$model.property`, and use `.constant(value)` when nothing should change.

```swift
// Derived binding
Toggle("Dark Mode", isOn: Binding(
    get: { settings.theme == .dark },
    set: { settings.theme = $0 ? .dark : .light }
))

// Binding to each element (iOS 15+)
List($todos) { $todo in
    Toggle(todo.title, isOn: $todo.isDone)
}

// Constant binding
Toggle("Preview", isOn: .constant(true))
```

**Follow-ups:**
- **What is the downside of custom `Binding(get:set:)`?** It is recreated on every `body` run and can't be compared, so it may cause extra updates; prefer `$model.property` when possible.
- **How does `$profile.name` work?** `Binding` uses dynamic member lookup to create a binding to the `name` property.
- **Can you turn an optional binding into a non-optional one?** Yes, with `Binding($optionalValue)`, which returns `nil` if the value is `nil`.

### Q20. What is the difference between `@StateObject` and `@ObservedObject`? `[Senior]`
`@StateObject` means the view owns the object: SwiftUI creates it once per view identity and keeps it. `@ObservedObject` means the view only watches an object that someone else owns and passes in, so SwiftUI doesn't keep it alive across view recreation.

```swift
struct ProfileScreen: View {
    @StateObject private var model = ProfileModel()   // created once, owned here
    var body: some View { ProfileDetails(model: model) }
}

struct ProfileDetails: View {
    @ObservedObject var model: ProfileModel           // received, not owned
    var body: some View { Text(model.name) }
}
```

**Follow-ups:**
- **What is the classic bug?** `@ObservedObject var model = Model()` creates a new model every time the parent updates, resetting its data.
- **Why is `@StateObject` created only once?** Its initializer takes an autoclosure that SwiftUI calls only the first time.
- **What replaces these with `@Observable`?** `@State` for ownership, and a plain property or `@Bindable` for received objects.

### Q21. What is `@EnvironmentObject`? `[Fundamental]`
`@EnvironmentObject` lets any descendant view read an `ObservableObject` that an ancestor injected, without passing it through every level. You inject it with `.environmentObject(object)`, and if no ancestor did, the app crashes when the view reads it.

```swift
ContentView()
    .environmentObject(AppSettings())

struct ThemeLabel: View {
    @EnvironmentObject var settings: AppSettings
    var body: some View { Text(settings.themeName) }
}
```

**Follow-ups:**
- **What is the `@Observable` replacement?** `.environment(object)` to inject and `@Environment(Type.self)` to read.
- **Why does it crash instead of failing to compile?** The environment is resolved at runtime, so the compiler can't check that an ancestor injected it.
- **What is the downside of using it everywhere?** Dependencies become hidden and previews crash unless you inject every object.

### Q22. What are the rules for choosing the right property wrapper? `[Senior]`
For a simple value the view owns I use `@State`; for a value a parent owns that I need to change, `@Binding`; for a model the view owns, `@State` with `@Observable` (or `@StateObject` before iOS 17); for a model passed in, a plain property, or `@Bindable` when I need bindings; for a model shared deep in the tree, `@Environment(Model.self)`; and for system values, `@Environment(\.key)`.

```swift
struct EditorScreen: View {
    @State private var isPreviewing = false          // simple, owned
    @State private var model = EditorModel()         // @Observable, owned
    @Environment(\.dismiss) private var dismiss      // system value
    @Environment(Session.self) private var session   // shared model

    var body: some View { EditorForm(model: model) }
}

struct EditorForm: View {
    @Bindable var model: EditorModel                 // passed in, needs $ bindings
    var body: some View { TextField("Title", text: $model.title) }
}
```

**Follow-ups:**
- **What is the iOS 13–16 version of this table?** `@StateObject` to own, `@ObservedObject` to receive, and `@EnvironmentObject` to share.
- **When do you need `@Bindable` instead of a plain property?** Only when the view needs `$` bindings to the model's properties, like for a `TextField`.
- **What question do you ask first?** "Who owns this data?" The owner uses `@State`; everyone else reads it or gets a binding.

### Q23. How do you initialize `@State` from a value passed into the view? What's the catch? `[Senior]`
You set the underlying storage in `init` with `_draft = State(initialValue: value)`. The catch is that the initial value is used only the first time the view's identity is created, so if the parent later passes a different value, the state doesn't change.

```swift
struct NameEditor: View {
    @State private var draft: String

    init(initialName: String) {
        _draft = State(initialValue: initialName)   // used only once
    }

    var body: some View { TextField("Name", text: $draft) }
}
```

**Follow-ups:**
- **What if the child should follow the parent's value?** Use a `@Binding` or a plain `let` instead of `@State`.
- **What if it should reset when the input changes?** Add `.id(initialName)` on the child, or react with `.onChange(of:)`.
- **Is this a good pattern for a draft that is saved later?** Yes, a local copy for editing is a valid reason to use it, as long as you know it won't follow later changes.

### Q24. What is a "single source of truth," and why does it matter? `[Senior]`
It means each piece of data has exactly one owner, and everyone else reads it or gets a binding to it. Copying the same value into several places lets the copies drift apart, so I derive values instead of storing duplicates.

```swift
struct CartView: View {
    @State private var items: [Item] = []            // the source of truth

    private var total: Decimal {                     // derived, not stored
        items.reduce(0) { $0 + $1.price }
    }

    var body: some View { Text(total, format: .currency(code: "USD")) }
}
```

**Follow-ups:**
- **What is a sign that you have two sources of truth?** Code that copies a value into `@State` and then has to "sync" it back in `onChange`.
- **When is storing a derived value acceptable?** When computing it is expensive; then store it in the model and update it when the source changes.
- **How does this relate to bindings?** A binding is how a child gets write access without becoming a second owner.

### Q25. What is `@AppStorage` and `@SceneStorage`? `[Fundamental]`
`@AppStorage` reads and writes a value in `UserDefaults` and updates the view when it changes, which is good for small preferences. `@SceneStorage` saves a small value per scene, like the selected tab or a draft, so the system can restore it later.

```swift
@AppStorage("hasSeenOnboarding") private var hasSeenOnboarding = false
@SceneStorage("selectedTab") private var selectedTab = Tab.home
```

**Follow-ups:**
- **Should you store a login token in `@AppStorage`?** No. `UserDefaults` isn't secure; secrets belong in the Keychain.
- **Which types can `@AppStorage` store?** Simple types like `Bool`, `Int`, `Double`, `String`, `URL`, `Data`, and `RawRepresentable` enums.
- **When is `@SceneStorage` restored?** When the system recreates the scene, for example after the app was killed in the background.

### Q26. What is `@FocusState`? `[Fundamental]`
`@FocusState` tracks and controls which text field has keyboard focus. You bind fields to it with `.focused(_:equals:)` and move focus by setting the value, or set it to `nil` to hide the keyboard.

```swift
struct LoginForm: View {
    enum Field { case email, password }
    @State private var email = ""
    @State private var password = ""
    @FocusState private var focusedField: Field?

    var body: some View {
        Form {
            TextField("Email", text: $email)
                .focused($focusedField, equals: .email)
                .onSubmit { focusedField = .password }   // move to next field
            SecureField("Password", text: $password)
                .focused($focusedField, equals: .password)
                .onSubmit { focusedField = nil }          // dismiss keyboard
        }
        .onAppear { focusedField = .email }
    }
}
```

**Follow-ups:**
- **How do you change the keyboard's return key?** With `.submitLabel(.next)` or `.submitLabel(.go)`.
- **Can you use a `Bool` instead of an enum?** Yes, for a single field: `@FocusState private var isFocused: Bool` with `.focused($isFocused)`.
- **Why might setting focus in `onAppear` not work?** Sometimes the field isn't ready yet; setting it in `.task` or after a short delay usually fixes it.

### Q27. What is `DynamicProperty`? `[Lead/Expert]`
`DynamicProperty` is the protocol behind `@State`, `@Environment`, and `@Query`; SwiftUI updates these properties before calling `body`. You can build your own property wrapper that conforms to it and uses `@State` or `@Environment` inside, to package reusable view logic.

```swift
@propertyWrapper
struct FeatureFlag: DynamicProperty {
    @Environment(\.featureFlags) private var flags
    let name: String

    var wrappedValue: Bool { flags.isEnabled(name) }
}

struct CheckoutView: View {
    @FeatureFlag(name: "applePay") var showApplePay
    var body: some View { if showApplePay { Text("Apple Pay") } }
}
```

**Follow-ups:**
- **What method can you implement to react before `body` runs?** `update()`, which SwiftUI calls before each `body` evaluation.
- **Why use this instead of a helper function?** The wrapper can hold its own `@State` and read the environment, which a plain function can't.
- **Where does it work?** Only inside views (and other dynamic properties), because SwiftUI is what updates it.

## 4. The Observation Framework (`@Observable`)

### Q28. What is `@Observable`, and how does it differ from `ObservableObject`? `[Senior]`
`@Observable` is the iOS 17 macro from Swift's Observation framework that makes every stored property of a class observable automatically. Unlike `ObservableObject`, where any `@Published` change updates every view watching the object, `@Observable` only updates the views that actually read the property that changed.

```swift
// Before (iOS 13+)
final class CartStore: ObservableObject {
    @Published var items: [Item] = []
    @Published var couponCode = ""
}

// After (iOS 17+)
@Observable
final class CartStore {
    var items: [Item] = []
    var couponCode = ""
}
```

**Follow-ups:**
- **Do you still need `@Published`?** No. All stored properties are tracked by default; use `@ObservationIgnored` to exclude one.
- **Is `@Observable` based on Combine?** No, it is built on the Swift Observation framework, so `$property` publishers no longer exist.
- **Does it track nested objects?** Yes, it tracks properties read through nested `@Observable` objects, arrays, and optionals.

### Q29. Why is `@Observable` better for performance? `[Senior]`
Tracking is per property and per view, based on what each `body` actually reads. A badge that shows `cart.items.count` won't update when `couponCode` changes, while with `ObservableObject` it would.

```swift
struct CartBadge: View {
    let cart: CartStore              // @Observable
    var body: some View {
        Text("\(cart.items.count)")  // depends only on items
    }
}
```

**Follow-ups:**
- **Are reads inside a button action tracked?** No. Only reads during `body` are tracked, so actions don't add dependencies.
- **Can you still cause too many updates?** Yes, if one big view reads many properties; splitting views still helps.
- **How do you verify the improvement?** Use `Self._printChanges()` or the SwiftUI instrument to count body updates before and after.

### Q30. What is `@Bindable`? `[Senior]`
`@Bindable` lets a view create `$` bindings to the properties of an `@Observable` object it doesn't own. You can use it as a property wrapper, or as a local variable inside `body` for objects read from the environment.

```swift
@Observable final class Profile { var name = ""; var bio = "" }

struct ProfileEditor: View {
    @Bindable var profile: Profile          // passed in by a parent
    var body: some View {
        TextField("Name", text: $profile.name)
    }
}

struct SettingsScreen: View {
    @Environment(Profile.self) private var profile
    var body: some View {
        @Bindable var profile = profile     // local bindable for environment objects
        TextField("Name", text: $profile.name)
    }
}
```

**Follow-ups:**
- **Do you need `@Bindable` to just display values?** No, a plain property is enough to read and track the object.
- **Why doesn't `@Environment(Profile.self)` give you `$profile`?** It's read-only access to the object, so you wrap it in a local `@Bindable` to get bindings.
- **What if the view owns the object with `@State`?** Then `$model.name` already works, because `@State` provides bindings.

### Q31. How do you own an `@Observable` model in a view, and what's the pitfall? `[Lead/Expert]`
You own it with `@State private var model = Model()`. The pitfall, before Xcode 27, is that `@State`'s initial value is evaluated every time the view struct is created, so extra models are created and thrown away; if the model's `init` does network calls or subscriptions, that causes wasted work or bugs. In Xcode 27, `@State` became a macro and stored classes are created lazily, once per view lifetime, but keeping `init` cheap is still good practice.

```swift
struct FeedScreen: View {
    @State private var model = FeedModel()   // keep FeedModel.init cheap

    var body: some View {
        FeedList(model: model)
            .task { await model.loadIfNeeded() }   // side effects belong here
    }
}
```

**Follow-ups:**
- **Why didn't `@StateObject` have this problem?** Its initializer takes an autoclosure, which SwiftUI only calls the first time.
- **What are the fixes on older toolchains?** Keep `init` cheap and start work in `.task`, create the model in a parent and pass it down, or create it lazily in `.task` into an optional `@State`.
- **Is there a source change to watch for with the Xcode 27 `@State` macro?** Yes, a property that has a default value and is also assigned in `init` can now give a "used before being initialized" error; remove the default value.

### Q32. What does `@ObservationIgnored` do? `[Senior]`
`@ObservationIgnored` excludes a stored property from observation, so changing it never updates any view. I use it for caches, formatters, internal bookkeeping, and injected dependencies.

```swift
@Observable
final class SearchModel {
    var query = ""
    var results: [Result] = []
    @ObservationIgnored private var cache: [String: [Result]] = [:]
    @ObservationIgnored private let api: SearchAPI

    init(api: SearchAPI) { self.api = api }
}
```

**Follow-ups:**
- **What happens if you don't ignore a cache?** Every cache write can trigger view updates for views that read it.
- **Do computed properties need it?** No. Computed properties are tracked through the stored properties they read.
- **Is a `let` property tracked?** No, constants can't change, so there's nothing to observe.

### Q33. How do you share an `@Observable` object through the environment? `[Fundamental]`
You inject it with `.environment(object)` high in the hierarchy and read it with `@Environment(Type.self)` in any descendant.

```swift
@main
struct ShopApp: App {
    @State private var cart = Cart()
    var body: some Scene {
        WindowGroup {
            ContentView().environment(cart)
        }
    }
}

struct CartBadge: View {
    @Environment(Cart.self) private var cart
    var body: some View { Text("\(cart.items.count)") }
}
```

**Follow-ups:**
- **What happens if no ancestor injected it?** Reading a non-optional type crashes; declare `@Environment(Cart.self) private var cart: Cart?` if it may be missing.
- **Why keep it in `@State` in the `App`?** So the single instance is owned and kept alive for the app's whole life.
- **Can two different objects of the same type be in the environment?** Only the nearest one is visible; use a custom key (`@Entry`) if you need more than one.

### Q34. How do you observe changes to `@Observable` properties outside SwiftUI? `[Lead/Expert]`
`withObservationTracking` tracks the properties read in its first closure and calls `onChange` once, just before the next change, so you must register again to keep watching. Swift 6.2 (iOS 26) added `Observations`, an async sequence that emits new values as they change.

```swift
// One-shot tracking
withObservationTracking {
    _ = cart.total
} onChange: {
    print("total is about to change")
}

// Swift 6.2: async stream of values
for await total in Observations({ cart.total }) {
    print("New total: \(total)")
}
```

**Follow-ups:**
- **Why does `onChange` not give you the new value?** It fires before the change happens (will-set), so you read the value later or re-register.
- **When would you need this?** In UIKit code, services, or tests that react to a model shared with SwiftUI.
- **How does `Observations` group changes?** It emits transactionally, so several changes in one update produce one value.

### Q35. How would you migrate a codebase from `ObservableObject` to `@Observable`? `[Lead/Expert]`
First the deployment target must be iOS 17 or later. Then, type by type, I replace `ObservableObject` with `@Observable`, remove `@Published`, and update call sites: `@StateObject` becomes `@State`, `@ObservedObject` becomes a plain property or `@Bindable`, and `@EnvironmentObject` becomes `@Environment(Type.self)`.

```swift
// Before
@StateObject private var model = ProfileModel()
.environmentObject(session)
@EnvironmentObject var session: Session

// After
@State private var model = ProfileModel()
.environment(session)
@Environment(Session.self) private var session
```

**Follow-ups:**
- **What breaks most often?** Code that subscribed to `$property` Combine publishers, which no longer exist.
- **What thread-safety change should you make?** Mark UI-bound models `@MainActor` so Swift 6 can check that changes happen on the main actor.
- **In what order do you migrate?** Leaf models first, measure the gains, then move up incrementally rather than all at once.

## 5. Environment & Preferences

### Q36. What is the SwiftUI environment? `[Fundamental]`
The environment is a set of values that flows down the view hierarchy automatically, like color scheme, locale, Dynamic Type size, `dismiss`, and your own values. A modifier like `.font(...)` or `.environment(\.locale, ...)` affects all descendants unless one of them overrides it.

```swift
struct DetailView: View {
    @Environment(\.dismiss) private var dismiss
    @Environment(\.colorScheme) private var colorScheme

    var body: some View {
        Button("Close") { dismiss() }
            .foregroundStyle(colorScheme == .dark ? .white : .black)
    }
}
```

**Follow-ups:**
- **Does a change in an environment value update every view?** Only views that read that specific value are updated.
- **Can a child override an environment value?** Yes, applying the modifier again lower in the tree overrides it for that subtree.
- **Which actions come from the environment?** `dismiss`, `openURL`, `refresh`, and `modelContext`, among others.

### Q37. How do you define a custom environment value? `[Senior]`
Since Xcode 16 you use the `@Entry` macro in an extension of `EnvironmentValues`, which also works on older OS versions. Before that, you defined an `EnvironmentKey` with a default value and a computed property.

```swift
extension EnvironmentValues {
    @Entry var theme: Theme = .standard
}

ContentView().environment(\.theme, .dark)

struct ThemedButton: View {
    @Environment(\.theme) private var theme
    var body: some View { Button("Buy") {}.tint(theme.accent) }
}
```

**Follow-ups:**
- **How did you do it before `@Entry`?** Create a struct conforming to `EnvironmentKey` with a `defaultValue`, then add a computed property with `get` and `set` on `EnvironmentValues`.
- **Why is a default value required?** So views always get a value even when no ancestor set one.
- **Can you add a convenience modifier?** Yes, like `extension View { func theme(_ t: Theme) -> some View { environment(\.theme, t) } }`.

### Q38. When should you use the environment vs passing values through initializers? `[Senior]`
I pass values through initializers by default, because they are explicit and checked by the compiler. I use the environment for things many views need at different depths, like a theme, services, feature flags, or a router.

```swift
// Initializer: direct parent → child data
ProductRow(product: product)

// Environment: cross-cutting, needed deep in the tree
ContentView()
    .environment(\.theme, .dark)
    .environment(router)
```

**Follow-ups:**
- **What is the risk of overusing the environment?** Dependencies become hidden, and `@Environment(Type.self)` crashes at runtime if the object is missing.
- **What is "prop drilling"?** Passing a value through many layers that don't use it, just to reach a deep child; the environment avoids that.
- **Which is easier to test?** Initializer injection, because a view's needs are visible in its signature.

### Q39. What are preference keys? `[Senior]`
Preferences send data up from children to their ancestors, the opposite direction of the environment. You define a `PreferenceKey` with a default value and a `reduce` function that combines values from several children; SwiftUI uses this for things like `navigationTitle`.

```swift
struct MaxWidthKey: PreferenceKey {
    static let defaultValue: CGFloat = 0
    static func reduce(value: inout CGFloat, nextValue: () -> CGFloat) {
        value = max(value, nextValue())
    }
}

Text(title)
    .background(GeometryReader { proxy in
        Color.clear.preference(key: MaxWidthKey.self, value: proxy.size.width)
    })

// In the parent
.onPreferenceChange(MaxWidthKey.self) { labelWidth = $0 }
```

**Follow-ups:**
- **Why use `static let` for `defaultValue`?** A `static var` is global mutable state, which Swift 6 reports as an error.
- **What does `reduce` do?** It combines values when several children set the same key, for example by taking the maximum.
- **Is there a simpler way to just read a size?** Yes, `onGeometryChange` (Q51).

## 6. Layout System

### Q40. How does SwiftUI's layout system work? `[Senior]`
It is a three-step negotiation: the parent proposes a size, the child chooses its own size (and may ignore the proposal), and the parent places the child. Views decide their own size, which is why `Text` stays as small as its content and `Color` fills everything offered.

```swift
HStack {
    Text("Hi")          // takes only what it needs
    Color.blue          // takes everything left
}
.frame(height: 44)
```

**Follow-ups:**
- **Are `.frame` and `.padding` part of this negotiation?** Yes, they are layout views that change the proposal or the placement.
- **Can a child be bigger than the space proposed?** Yes, a child can choose a larger size and overflow its parent.
- **What is an "ideal size"?** The size a view wants when given no constraint, which `.fixedSize()` asks it to use.

### Q41. How does `.frame` actually work? `[Senior]`
`.frame(width:height:)` creates a container that proposes that size to its child and reports that size to its parent; the child can still be smaller and is centered by default. `.frame(maxWidth: .infinity)` makes the container as wide as offered, and `alignment` positions the child inside it.

```swift
Text("Hi")
    .frame(width: 200, height: 100)   // frame is 200×100, text stays small and centered
    .background(.blue)                // blue fills 200×100

Text("Left aligned")
    .frame(maxWidth: .infinity, alignment: .leading)
```

**Follow-ups:**
- **Why doesn't `.frame` make `Text` bigger?** The frame is a separate container; the text inside still picks its own size.
- **What does `.frame(minHeight: 44)` do?** It makes the container at least 44 points tall, a common way to meet tap-target size.
- **Why does `.background` after `.frame` fill the frame?** Because the background is applied to the frame container, not to the text.

### Q42. How do stacks distribute space? What are `layoutPriority` and `fixedSize`? `[Senior]`
Stacks offer space to their least flexible children first, then share what's left among the more flexible ones. `.layoutPriority(1)` makes a child get space before the others, and `.fixedSize()` makes a view use its ideal size, ignoring the proposal.

```swift
HStack {
    Text("A very long product title that might truncate")
        .lineLimit(1)
    Spacer()
    Text("$1,299.00")
        .layoutPriority(1)     // price never truncates
}
```

**Follow-ups:**
- **How do you let text wrap to as many lines as needed in a tight layout?** `.fixedSize(horizontal: false, vertical: true)`.
- **What is the default layout priority?** `0`; higher values are served first.
- **What is the risk of `fixedSize()`?** The view can overflow its container because it stops respecting the space offered.

### Q43. Compare `VStack`, `LazyVStack`, and `List`. `[Senior]`
`VStack` creates all its children at once and is best for small, fixed content. `LazyVStack` creates rows only as they scroll into view, inside a `ScrollView`, and is good for long custom-styled feeds. `List` is also lazy, is backed by a platform list with cell reuse, and gives you swipe actions, selection, and edit mode for free.

```swift
ScrollView {
    LazyVStack(spacing: 12) {       // rows created on demand
        ForEach(posts) { PostCard(post: $0) }
    }
}

List(posts) { PostRow(post: $0) }   // lazy, reused cells, built-in features
```

**Follow-ups:**
- **Which uses less memory for huge data sets?** `List`, because it reuses cells, while rows created by `LazyVStack` aren't recycled the same way.
- **Does a `VStack` inside a `ScrollView` become lazy?** No, it still creates every child immediately.
- **What changed for swipe actions in iOS 27?** The new `swipeActionsContainer()` modifier lets `swipeActions` work in `ScrollView`, lazy stacks, and custom layouts, not just `List`.

### Q44. What is `Spacer`, and what are common layout mistakes with it? `[Fundamental]`
`Spacer` is a flexible view that expands along its stack's axis and pushes other views apart. Common mistakes are putting it in a `ZStack`, which has no axis, or in a `ScrollView` expecting it to fill the screen, because a scroll view offers unlimited space.

```swift
HStack {
    Text("Name")
    Spacer()             // pushes the value to the trailing edge
    Text("Sam")
}

Spacer(minLength: 0)     // removes the default minimum spacing
```

**Follow-ups:**
- **How do you fill the screen inside a `ScrollView`?** Use `.containerRelativeFrame(.vertical)` or `.frame(minHeight:)` from the container size.
- **Is `Spacer` the same as padding?** No, padding is a fixed amount, while `Spacer` takes whatever space is left.
- **What does `Spacer` do in a `VStack`?** It expands vertically, pushing views up or down.

### Q45. What is `GeometryReader`, and what are its pitfalls? `[Senior]`
`GeometryReader` gives you a proxy with the proposed size, safe area insets, and frames. Its pitfalls are that it takes all the space it is offered and places children at the top-leading corner, measuring and then writing to `@State` can cause layout loops, and it's often used for things the layout system already does.

```swift
GeometryReader { proxy in
    Text("Width: \(Int(proxy.size.width))")   // placed at top-leading
}
.frame(height: 44)                            // constrain it, or it takes everything
```

**Follow-ups:**
- **What are modern alternatives?** `containerRelativeFrame`, `onGeometryChange`, `ViewThatFits`, a custom `Layout`, and `visualEffect`.
- **Why put it in a `.background` instead?** Then it measures the view's size without changing the layout.
- **What is a layout loop?** A size measurement updates state, which changes the layout, which changes the size again, over and over.

### Q46. What is `ViewThatFits`? `[Senior]`
`ViewThatFits` takes several alternatives and shows the first one whose ideal size fits the available space. It is great for adaptive layouts and large accessibility text sizes.

```swift
ViewThatFits(in: .horizontal) {
    HStack { actionButtons }            // first choice
    VStack { actionButtons }            // fallback
    Menu("Actions") { actionButtons }   // last resort
}
```

**Follow-ups:**
- **What happens if none of the options fit?** It shows the last one.
- **What does `in: .horizontal` mean?** Only the width is checked, so height is allowed to grow.
- **How is it different from `AnyLayout`?** `ViewThatFits` picks by available space; `AnyLayout` switches layouts by your own condition while keeping identity.

### Q47. What is `AnyLayout`, and why use it instead of `if/else`? `[Lead/Expert]`
`AnyLayout` type-erases a `Layout`, so you can switch between, for example, a horizontal and a vertical stack without changing identity. Children keep their state and animate smoothly between the two layouts, which an `if/else` can't do.

```swift
struct AdaptiveStack<Content: View>: View {
    @Environment(\.dynamicTypeSize) private var dynamicTypeSize
    @ViewBuilder var content: Content

    var body: some View {
        let layout = dynamicTypeSize.isAccessibilitySize
            ? AnyLayout(VStackLayout(alignment: .leading))
            : AnyLayout(HStackLayout())
        layout { content }
    }
}
```

**Follow-ups:**
- **Why is `AnyLayout` fine when `AnyView` isn't?** It erases only the layout algorithm, not the children, so their identity is kept.
- **Can you animate the switch?** Yes, wrap the change in `withAnimation` and the children move to their new positions.
- **What types can you put in `AnyLayout`?** Any `Layout`, like `HStackLayout`, `VStackLayout`, `ZStackLayout`, `GridLayout`, or your own.

### Q48. How do you build a custom layout with the `Layout` protocol? `[Lead/Expert]`
Since iOS 16 you implement two methods: `sizeThatFits`, which reports how big the container wants to be, and `placeSubviews`, which positions each child. The classic interview task is a flow layout where tags wrap to the next line.

```swift
struct FlowLayout: Layout {
    var spacing: CGFloat = 8

    func sizeThatFits(proposal: ProposedViewSize, subviews: Subviews, cache: inout ()) -> CGSize {
        let maxWidth = proposal.width ?? .infinity
        var x: CGFloat = 0, y: CGFloat = 0, rowHeight: CGFloat = 0, widest: CGFloat = 0
        for subview in subviews {
            let size = subview.sizeThatFits(.unspecified)
            if x + size.width > maxWidth, x > 0 { x = 0; y += rowHeight + spacing; rowHeight = 0 }
            x += size.width + spacing
            rowHeight = max(rowHeight, size.height)
            widest = max(widest, x - spacing)
        }
        return CGSize(width: widest, height: y + rowHeight)
    }

    func placeSubviews(in bounds: CGRect, proposal: ProposedViewSize, subviews: Subviews, cache: inout ()) {
        var x = bounds.minX, y = bounds.minY, rowHeight: CGFloat = 0
        for subview in subviews {
            let size = subview.sizeThatFits(.unspecified)
            if x + size.width > bounds.maxX, x > bounds.minX { x = bounds.minX; y += rowHeight + spacing; rowHeight = 0 }
            subview.place(at: CGPoint(x: x, y: y), proposal: ProposedViewSize(size))
            x += size.width + spacing
            rowHeight = max(rowHeight, size.height)
        }
    }
}

// FlowLayout { ForEach(tags, id: \.self) { TagView(text: $0) } }
```

**Follow-ups:**
- **What is the `cache` parameter for?** Storing computed measurements so you don't repeat expensive work between `sizeThatFits` and `placeSubviews`.
- **Why can't you just use `GeometryReader` for this?** It would need measure-then-update cycles, while `Layout` measures and places in one layout pass.
- **How would you center each row instead of aligning it to the leading edge?** First group the subviews into rows and measure each row's width, then start each row at an offset of half the leftover space.

### Q49. What are alignment guides? `[Lead/Expert]`
Alignment guides decide how views line up inside a stack. You can shift a view's guide with `.alignmentGuide(_:computeValue:)`, or define a custom alignment to line up views that live in different stacks.

```swift
extension VerticalAlignment {
    private enum IconCenter: AlignmentID {
        static func defaultValue(in d: ViewDimensions) -> CGFloat { d[VerticalAlignment.center] }
    }
    static let iconCenter = VerticalAlignment(IconCenter.self)
}

HStack(alignment: .iconCenter) {
    Image(systemName: "bell")
    VStack(alignment: .leading) {
        Text("Title").font(.headline)
            .alignmentGuide(.iconCenter) { $0[VerticalAlignment.center] }   // icon lines up with title
        Text("A longer subtitle on a second line")
    }
}
```

**Follow-ups:**
- **When do you need a custom alignment?** When views in different stacks must line up, like an icon with only the first line of a text block.
- **How do you align text by its first baseline?** Use `HStack(alignment: .firstTextBaseline)`.
- **What does `computeValue` return?** The offset of the guide within the view, usually based on its dimensions.

### Q50. How does the safe area work in SwiftUI? `[Fundamental]`
Views stay inside the safe area by default, and you let a background extend under the bars with `.ignoresSafeArea()`, ideally on the background only. `.safeAreaInset(edge:)` adds content like a custom bottom bar and shrinks the safe area so scrolling content isn't hidden behind it.

```swift
ScrollView {
    MessagesList()
}
.safeAreaInset(edge: .bottom) {
    MessageComposer()
        .padding()
        .background(.bar)
}
```

**Follow-ups:**
- **Why apply `.ignoresSafeArea()` to the background only?** So text and buttons stay away from the notch and home indicator.
- **What does `.safeAreaPadding` do?** Added in iOS 17, it adds padding to the safe area itself, so content and scroll indicators respect it.
- **How do you keep content above the keyboard?** SwiftUI does it by default; use `.ignoresSafeArea(.keyboard)` to opt out.

### Q51. How do you read a view's size without breaking layout? `[Senior]`
I use `onGeometryChange`, which reads a value from the view's geometry and calls the action only when that value changes. It doesn't take extra space like `GeometryReader` does.

```swift
struct CollapsingHeader: View {
    @State private var headerHeight: CGFloat = 0

    var body: some View {
        HeaderView()
            .onGeometryChange(for: CGFloat.self) { proxy in
                proxy.size.height
            } action: { newHeight in
                headerHeight = newHeight
            }
    }
}
```

**Follow-ups:**
- **Which iOS versions support it?** It shipped with the iOS 18 SDK and is back-deployed to iOS 16.
- **Why is it better than a `GeometryReader` in the background?** It only fires when the transformed value changes, so it avoids extra updates and layout loops.
- **Can you read a frame in a coordinate space?** Yes, use `proxy.frame(in: .global)` or a named coordinate space in the transform.

### Q52. What is `containerRelativeFrame`? `[Senior]`
`containerRelativeFrame`, added in iOS 17, sizes a view relative to its nearest container, like a scroll view or the window, without using `GeometryReader`. It is commonly used for full-width paging cards.

```swift
ScrollView(.horizontal) {
    LazyHStack(spacing: 16) {
        ForEach(items) { item in
            CardView(item: item)
                .containerRelativeFrame(.horizontal)   // one card per screen width
        }
    }
    .scrollTargetLayout()
}
.scrollTargetBehavior(.viewAligned)                    // snap to cards
.contentMargins(.horizontal, 24, for: .scrollContent)
```

**Follow-ups:**
- **How do you show two cards per screen?** Use `.containerRelativeFrame(.horizontal, count: 2, spacing: 16)`.
- **What does `scrollTargetBehavior(.paging)` do instead?** It snaps by the scroll view's full page size rather than by individual views.
- **Why is `.scrollTargetLayout()` needed?** It tells the scroll view which views are snap targets for `.viewAligned`.

### Q53. What is `Grid`, and how does it differ from `LazyVGrid`? `[Senior]`
`Grid`, from iOS 16, isn't lazy: it measures all its cells so columns line up across rows, and it supports cells spanning columns, which is good for small, form-like tables. `LazyVGrid` creates cells on demand with column rules like `.adaptive(minimum:)`, which is good for large photo grids.

```swift
let columns = [GridItem(.adaptive(minimum: 100), spacing: 8)]

ScrollView {
    LazyVGrid(columns: columns, spacing: 8) {
        ForEach(photos) { photo in
            PhotoThumbnail(photo: photo)
                .frame(height: 100)
                .clipped()
        }
    }
}
```

**Follow-ups:**
- **What are the three kinds of `GridItem`?** `.fixed` for an exact width, `.flexible` to share space, and `.adaptive` to fit as many columns as possible.
- **How do you make a cell span two columns in `Grid`?** Use `.gridCellColumns(2)`.
- **When would `Grid` be a bad choice?** For hundreds of items, because it creates and measures every cell up front.

## 7. Lists, ScrollViews & Grids

### Q54. Show common `List` features: swipe actions, delete, move, refresh, search. `[Fundamental]`
`List` gives you swipe actions with `.swipeActions`, reordering with `.onMove`, pull-to-refresh with `.refreshable`, and a search field with `.searchable`, all with system behavior and accessibility built in.

```swift
List {
    ForEach(model.filteredTodos) { todo in
        TodoRow(todo: todo)
            .swipeActions(edge: .trailing) {
                Button("Delete", role: .destructive) { model.delete(todo) }
            }
            .swipeActions(edge: .leading) {
                Button("Done") { model.toggle(todo) }.tint(.green)
            }
    }
    .onMove { model.move(from: $0, to: $1) }
}
.refreshable { await model.reload() }
.searchable(text: $model.query)
.toolbar { EditButton() }
```

**Follow-ups:**
- **What does `role: .destructive` change?** It colors the action red and lets a full swipe perform it.
- **How do you turn off the full-swipe action?** `.swipeActions(allowsFullSwipe: false)`.
- **What did iOS 27 add for reordering?** `.reorderContainer(for:)` and `.reorderable()`, which bring drag-to-reorder to `List`, `ScrollView`, lazy stacks, and custom layouts.

### Q55. How do you implement pagination in a SwiftUI list? `[Senior]`
When a row near the end of the list appears, I ask the model to load the next page, and the model ignores the request if a page is already loading or there are no more pages. That guard prevents duplicate requests.

```swift
List(model.items) { item in
    ItemRow(item: item)
        .onAppear {
            if item.id == model.items.last?.id {
                Task { await model.loadNextPage() }
            }
        }
}

// In the @MainActor @Observable model
func loadNextPage() async {
    guard !isLoading, hasMore else { return }   // prevent duplicate requests
    isLoading = true
    defer { isLoading = false }
    if let page = try? await api.fetch(cursor: nextCursor) {
        items.append(contentsOf: page.items)
        nextCursor = page.nextCursor
        hasMore = page.nextCursor != nil
    }
}
```

**Follow-ups:**
- **How do you make loading feel smoother?** Trigger a few items before the last one, and show a `ProgressView` row while loading.
- **Why use a cursor instead of a page number?** A cursor doesn't skip or repeat items when new data is inserted while the user scrolls.
- **How do you show a load error?** Keep an error state in the model and show a "Retry" row at the bottom instead of the spinner.

### Q56. How do you scroll programmatically? `[Senior]`
On iOS 14 and later I use `ScrollViewReader` and call `proxy.scrollTo(id)`. On iOS 17 and later I can bind `scrollPosition(id:)` to state, which both reads and sets the current position.

```swift
// iOS 14+
ScrollViewReader { proxy in
    ScrollView {
        LazyVStack { ForEach(messages) { MessageRow(message: $0).id($0.id) } }
    }
    .onChange(of: messages.count) {
        guard let lastID = messages.last?.id else { return }
        withAnimation { proxy.scrollTo(lastID, anchor: .bottom) }
    }
}

// iOS 17+
ScrollView {
    LazyVStack { ForEach(messages) { MessageRow(message: $0) } }
        .scrollTargetLayout()
}
.scrollPosition(id: $scrolledID)
.defaultScrollAnchor(.bottom)        // chat starts at the bottom
```

**Follow-ups:**
- **Why pass a non-optional ID to `scrollTo`?** Passing an optional looks for a view whose ID is that optional value, which usually doesn't exist, so nothing happens.
- **What does `.scrollTargetLayout()` do here?** It tells `scrollPosition(id:)` which views to track.
- **What is the iOS 18 `ScrollPosition` type for?** It can scroll to an ID, an edge, or an exact offset from one value.

### Q57. How do you react to scroll position and visibility? `[Lead/Expert]`
iOS 18 added `onScrollGeometryChange` to react to things like the content offset, `onScrollVisibilityChange` to know when a view becomes visible, and `onScrollPhaseChange` to know if the user is dragging or the scroll is decelerating.

```swift
ScrollView { content }
    .onScrollGeometryChange(for: Bool.self) { geometry in
        geometry.contentOffset.y > 600
    } action: { _, isFarDown in
        showScrollToTop = isFarDown          // only fires when the Bool changes
    }

VideoPlayerView(url: url)
    .onScrollVisibilityChange(threshold: 0.5) { isVisible in
        isVisible ? player.play() : player.pause()
    }
```

**Follow-ups:**
- **Why transform the offset to a `Bool` first?** So the action runs only when crossing the threshold, not on every pixel of scrolling.
- **What is the danger of storing the raw offset in `@State`?** Every scroll frame updates state and re-runs every view that reads it.
- **What did people use before iOS 18?** A `GeometryReader` with a preference key inside the scroll content, which was more complex and less efficient.

### Q58. How do you add section headers and pinned headers? `[Fundamental]`
You wrap rows in `Section` with a header, and in a `LazyVStack` you pass `pinnedViews: [.sectionHeaders]` so headers stick to the top while their section scrolls.

```swift
ScrollView {
    LazyVStack(pinnedViews: [.sectionHeaders]) {
        ForEach(groups) { group in
            Section {
                ForEach(group.contacts) { ContactRow(contact: $0) }
            } header: {
                Text(group.letter)
                    .frame(maxWidth: .infinity, alignment: .leading)
                    .background(.bar)
            }
        }
    }
}
```

**Follow-ups:**
- **Do `List` headers stick automatically?** With the plain list style, yes; with grouped styles they scroll with the content.
- **Why give the header a background?** Otherwise rows show through it while it is pinned.
- **Can you pin footers too?** Yes, add `.sectionFooters` to `pinnedViews`.

### Q59. How do you handle selection in a `List`? `[Fundamental]`
You pass a binding to `List(selection:)`: a `Set` of IDs gives multiple selection, usually with edit mode, and a single optional ID gives single selection, which is common with `NavigationSplitView`.

```swift
@State private var selection = Set<Mail.ID>()

List(mails, selection: $selection) { mail in

.toolbar { EditButton() }
```

**Follow-ups:**
- **Why does multi-selection need edit mode on iPhone?** On iPhone, rows are only selectable in edit mode, while on iPad and Mac selection works directly.
- **How do you perform an action on the selected rows?** Read the IDs from `selection` and look up the items in your model.
- **What type must the selection be?** The same type as the row IDs, like `Mail.ID`.

## 8. Navigation & Presentation

### Q60. What is `NavigationStack`, and how does it improve on `NavigationView`? `[Fundamental]`
`NavigationStack`, from iOS 16, replaces the deprecated `NavigationView` with value-based navigation: a `NavigationLink(value:)` pushes a value, and `.navigationDestination(for:)` decides which view to show. Because the stack can be bound to a path, you can push, pop, and deep link just by changing data.

```swift
NavigationStack {
    List(products) { product in
        NavigationLink(product.name, value: product)
    }
    .navigationDestination(for: Product.self) { product in
        ProductDetailView(product: product)
    }
    .navigationTitle("Products")
}
```

**Follow-ups:**
- **Why is value-based navigation better for performance?** Destinations are created lazily when pushed, while `NavigationLink(destination:)` builds the destination view for every row up front.
- **How do you pop to root?** Clear the bound path, for example `path.removeAll()`.
- **Must values be `Hashable`?** Yes, everything pushed onto the path must be `Hashable`.

### Q61. How do you implement a router for programmatic navigation? `[Senior]`
I create an `@Observable` router that owns the navigation path as an array of route enum values, bind the `NavigationStack` to it, and share the router through the environment so any screen can push or pop.

```swift
enum Route: Hashable { case product(Product.ID), cart, orderConfirmation(orderID: String) }

@MainActor @Observable
final class Router {
    var path: [Route] = []
    func push(_ route: Route) { path.append(route) }
    func popToRoot() { path.removeAll() }
}

struct RootView: View {
    @State private var router = Router()
    var body: some View {
        NavigationStack(path: $router.path) {
            HomeView()
                .navigationDestination(for: Route.self) { route in
                    switch route {
                    case .product(let id): ProductDetailView(productID: id)
                    case .cart: CartView()
                    case .orderConfirmation(let id): ConfirmationView(orderID: id)
                    }
                }
        }
        .environment(router)
    }
}
```

**Follow-ups:**
- **How does a child screen navigate?** It reads `@Environment(Router.self) private var router` and calls `router.push(.cart)`.
- **Why is a router easy to test?** You can assert `router.path == [.cart, .orderConfirmation(orderID: "A123")]` without any UI.
- **Why store IDs instead of whole models in routes?** IDs are small and stable, and the destination can load fresh data.

### Q62. What is `NavigationPath`, and when would you use it over a typed array? `[Senior]`
`NavigationPath` is a type-erased list of `Hashable` values, so one stack can contain different types, like a `Product` and a `User`. A typed array like `[Route]` is simpler, easy to inspect, and easy to test, so I prefer it when one enum can describe every route.

```swift
@State private var path = NavigationPath()

NavigationStack(path: $path) {
    HomeView()
        .navigationDestination(for: Product.self) { ProductDetailView(product: $0) }
        .navigationDestination(for: User.self) { ProfileView(user: $0) }
}

path.append(product)   // different types in one path
path.append(user)
```

**Follow-ups:**
- **Can you read what's inside a `NavigationPath`?** Not directly, only its `count`, which is why a typed array is easier to inspect.
- **How do you save and restore it?** Use `path.codable` to get a `CodableRepresentation`, as long as every element is `Codable`.
- **When would a feature-modular app prefer `NavigationPath`?** When each feature defines its own route types and they share one stack.

### Q63. How do you handle deep links in SwiftUI? `[Senior]`
I handle incoming URLs with `.onOpenURL`, parse each URL into a route, reset the navigation, and push the route through the router. I also handle universal links, switch to the right tab, dismiss open sheets, and save the link if the user must log in first.

```swift
RootView()
    .onOpenURL { url in                          // myshop://product/42
        guard let route = Route(url: url) else { return }
        router.popToRoot()
        router.push(route)
    }

extension Route {
    init?(url: URL) {
        let parts = url.pathComponents.filter { $0 != "/" }
        switch (url.host(), parts.first) {
        case ("product", let id?): self = .product(id)
        case ("cart", _):          self = .cart
        default:                   return nil
        }
    }
}
```

**Follow-ups:**
- **How do you handle universal links?** With `.onContinueUserActivity(NSUserActivityTypeBrowsingWeb)` and the activity's `webpageURL`.
- **What do you do if the user isn't logged in?** Store the pending route, show login, and replay the route after a successful login.
- **How do you test deep link parsing?** Unit test `Route(url:)` with many URLs, including invalid ones.

### Q64. Where must `navigationDestination` be placed? `[Senior]`
It must be inside the `NavigationStack`, attached to a view that is always present. Putting it inside a lazy container like a `List` row means the destination may not be registered when it's needed.

```swift
NavigationStack {
    List(items) { item in
        NavigationLink(item.name, value: item)
        // ❌ don't put .navigationDestination here, inside a lazy row
    }
    .navigationDestination(for: Item.self) { ItemDetail(item: $0) }   // ✅ on the List
}
```

**Follow-ups:**
- **What happens if it's placed inside a lazy row?** SwiftUI logs a warning, and the link may do nothing if that row isn't loaded.
- **Can you register the same type twice in one stack?** You shouldn't; only one destination is used, so behavior becomes unclear.
- **Can a pushed screen register its own destinations?** Yes, destinations added on deeper screens work for links pushed from there.

### Q65. How do you present sheets, full-screen covers, and popovers? `[Fundamental]`
I use `.sheet(item:)` when the sheet needs data, because the item itself controls presentation, and `.sheet(isPresented:)` or `.fullScreenCover(isPresented:)` for simple flags. Detents like `.medium` turn a sheet into a half-height sheet.

```swift
@State private var selectedProduct: Product?
@State private var showFilters = false

List(products) { product in
    Button(product.name) { selectedProduct = product }
}
.sheet(item: $selectedProduct) { product in        // data-driven
    ProductDetailView(product: product)
        .presentationDetents([.medium, .large])
}
.fullScreenCover(isPresented: $showFilters) {       // flag-driven
    FiltersView()
}
```

**Follow-ups:**
- **Why is `sheet(item:)` safer than a `Bool` plus an optional?** With two separate values, the sheet can briefly present with stale or `nil` data.
- **How do you stop the user from swiping a sheet away?** `.interactiveDismissDisabled(hasUnsavedChanges)`.
- **How do you show a popover on iPad but a sheet on iPhone?** `.popover` already does this; on iOS 16.4+ use `.presentationCompactAdaptation(.popover)` to keep it a popover on iPhone.

### Q66. How does a presented view dismiss itself? `[Fundamental]`
It reads the `dismiss` action from the environment and calls it. `dismiss` closes the current sheet or pops the current navigation screen, depending on how the view was shown.

```swift
struct EditProfileView: View {
    @Environment(\.dismiss) private var dismiss

    var body: some View {
        NavigationStack {
            Form { /* fields */ }
                .toolbar {
                    ToolbarItem(placement: .cancellationAction) { Button("Cancel") { dismiss() } }
                    ToolbarItem(placement: .confirmationAction) { Button("Save") { save(); dismiss() } }
                }
        }
    }
}
```

**Follow-ups:**
- **Why read `dismiss` in the presented view, not the parent?** The action dismisses the presentation of the view that reads it.
- **What did people use before iOS 15?** `@Environment(\.presentationMode)`, which is now deprecated.
- **How else can the parent dismiss it?** By setting the bound item to `nil` or the `Bool` to `false`.

### Q67. How do you show alerts and confirmation dialogs with data? `[Fundamental]`
I use the `presenting:` version of `.alert`, which passes the selected item into the buttons and message. Since iOS 27, `.alert` and `.confirmationDialog` also accept an optional item binding, the same way sheets do.

```swift
@State private var itemToDelete: Item?

List(items) { item in
    Text(item.name)
        .swipeActions { Button("Delete", role: .destructive) { itemToDelete = item } }
}
.alert("Delete item?",
       isPresented: Binding(get: { itemToDelete != nil }, set: { if !$0 { itemToDelete = nil } }),
       presenting: itemToDelete) { item in
    Button("Delete", role: .destructive) { delete(item) }
    Button("Cancel", role: .cancel) { }
} message: { item in
    Text("\(item.name) will be permanently removed.")
}
```

**Follow-ups:**
- **What does the iOS 27 version look like?** `.confirmationDialog("Delete?", item: $itemToDelete) { item in ... }`, with no separate `Bool` needed.
- **When do you use a confirmation dialog instead of an alert?** For a choice between actions the user started, like "Delete" or "Archive"; alerts are for important messages.
- **What does `role: .cancel` do?** It marks the cancel button so the system places and styles it correctly.

### Q68. How does `TabView` work with the iOS 18 `Tab` API? `[Senior]`
In iOS 18 you build a `TabView` from `Tab` values, each with a title, icon, and selection value, and bind the selection to state for programmatic switching. Each tab gets its own `NavigationStack`, so each keeps its own history.

```swift
enum AppTab: Hashable { case home, search, profile }
@State private var selectedTab: AppTab = .home

TabView(selection: $selectedTab) {
    Tab("Home", systemImage: "house", value: .home) {
        NavigationStack { HomeView() }
    }
    Tab("Profile", systemImage: "person", value: .profile) {
        NavigationStack { ProfileView() }
    }
    Tab(value: .search, role: .search) {
        NavigationStack { SearchView() }
    }
}
.tabViewStyle(.sidebarAdaptable)     // tab bar on iPhone, sidebar option on iPad
```

**Follow-ups:**
- **How did you build tabs before iOS 18?** With `.tabItem { Label(...) }` and `.tag(...)` on each child view.
- **Why not put one `NavigationStack` around the whole `TabView`?** Every tab would share one history, and the tab bar would be pushed away.
- **What new tab role did iOS 27 add?** A `.prominent` role for a trailing, separated tab, similar to how the search tab is shown.

### Q69. What is `NavigationSplitView`? `[Senior]`
`NavigationSplitView` builds two- or three-column layouts for iPad and Mac, driven by list selection, and it automatically collapses into a normal stack on iPhone.

**Follow-ups:**

- **Can the detail column have its own navigation?** Yes, put a `NavigationStack` inside the detail column.
- **What do you show when nothing is selected?** A placeholder, often a `ContentUnavailableView`.

### Q70. What is the zoom navigation transition? `[Senior]`
The zoom transition, added in iOS 18, makes a pushed screen grow out of the tapped thumbnail and shrink back into it. You mark the source with `.matchedTransitionSource` and the destination with `.navigationTransition(.zoom(...))`, using the same ID and namespace.

```swift
.navigationDestination(for: Photo.self) { photo in
```

**Follow-ups:**

- **How is it different from `matchedGeometryEffect`?** It's built into navigation and handles the interactive swipe back, which `matchedGeometryEffect` doesn't.

## 9. Async Work, Lifecycle Modifiers & Concurrency

### Q71. What is the difference between `.onAppear` and `.task`? `[Senior]`
`.onAppear` runs a synchronous closure, so any `Task` you start inside it is yours to manage. `.task` runs an async closure and is cancelled automatically when the view disappears, so it is the preferred place for loading data.

```swift
List(items) { ItemRow(item: $0) }
    .onAppear { analytics.track("list_shown") }   // quick synchronous work
    .task { await model.load() }                  // async, auto-cancelled
```

**Follow-ups:**
- **Do both run again when you come back from a pushed screen?** Yes, both run on every appearance, so guard against reloading if you don't want it.
- **What does cancellation actually do?** It marks the task as cancelled; async APIs like `URLSession` stop, but your own loops must check `Task.isCancelled`.
- **Why is `onAppear { Task { } }` worse?** That task isn't cancelled when the view disappears, so it can keep running and update a screen that's gone.

### Q72. What does `.task(id:)` do? Show a debounced search. `[Senior]`
`.task(id:)` restarts the task whenever the `id` value changes, cancelling the previous one. Adding a short sleep at the start turns it into a debounce, because each keystroke cancels the last task during its sleep.

```swift
struct SearchView: View {
    @State private var query = ""
    @State private var results: [Movie] = []

    var body: some View {
        List(results) { Text($0.title) }
            .searchable(text: $query)
            .task(id: query) {
                try? await Task.sleep(for: .milliseconds(300))   // debounce
                guard !Task.isCancelled, !query.isEmpty else { return }
                results = (try? await api.search(query)) ?? []
            }
    }
}
```

**Follow-ups:**
- **Why check `Task.isCancelled` after the sleep?** Because `try?` swallows the cancellation error, so the code would otherwise continue.
- **Does it run on first appearance too?** Yes, it runs once when the view appears and again each time the `id` changes.
- **What type must `id` be?** Any `Equatable` value.

### Q73. How does `onChange(of:)` work in iOS 17+? `[Fundamental]`
`onChange(of:)` runs a closure after a value changes, and in iOS 17 the closure can receive both the old and the new value. Passing `initial: true` also runs it when the view first appears.

```swift
.onChange(of: selectedTab) { oldValue, newValue in
    analytics.track(from: oldValue, to: newValue)
}

.onChange(of: searchText, initial: true) {
    filter()                 // also runs on first appearance
}
```

**Follow-ups:**
- **What must the value conform to?** `Equatable`.
- **What is the risk of `onChange` chains?** One `onChange` changes state that triggers another, causing extra updates or loops; derive values instead.
- **Which thread does it run on?** The main actor, after the change.

### Q74. How do you consume an `AsyncSequence` in a view? `[Senior]`
I loop over it with `for await` inside `.task`. The loop ends automatically when the view disappears, because the task is cancelled.

```swift
.task {
    for await _ in NotificationCenter.default.notifications(named: .cartUpdated) {
        await model.refreshCart()
    }
}
```

**Follow-ups:**
- **How do you consume a Combine publisher instead?** With `.onReceive(publisher) { value in ... }`.
- **What if the sequence never ends and you use `onAppear { Task { } }`?** The loop keeps running after the view is gone, which is a leak.
- **How do you watch two sequences at once?** Use two `.task` modifiers, or a `withTaskGroup` inside one task.

### Q75. On which thread does SwiftUI view code run? `[Senior]`
Since the iOS 18 SDK, `View` is `@MainActor`, so `body`, view methods, and `.task` closures run on the main actor. Awaiting an async call doesn't block the main actor, but heavy synchronous work inside `.task` still freezes the UI, so I move that work to another actor.

```swift
.task {
    let thumbnails = await ThumbnailRenderer.shared.render(photos)   // runs on another actor
    self.thumbnails = thumbnails                                      // back on the main actor
}
```

**Follow-ups:**
- **How do you move work off the main actor?** Use a separate actor, a `nonisolated` or `@concurrent` async function, or `Task.detached`.
- **Does `await` mean the work runs in the background?** No. It only means the function can pause; where it runs depends on the function's isolation.
- **How do you spot main-thread blocking?** With the Hangs instrument, or by watching for UI freezes in the Time Profiler.

### Q76. How should UI-bound `@Observable` models handle concurrency? `[Lead/Expert]`
I mark them `@MainActor`, so every change that drives the UI happens on the main actor and Swift 6 can verify it. Their async methods suspend during network calls without blocking, and with Swift 6.2's "approachable concurrency" settings, new app targets can make main-actor isolation the default.

```swift
@MainActor @Observable
final class ProfileModel {
    private(set) var profile: Profile?
    private(set) var errorMessage: String?
    private let api: ProfileAPI

    init(api: ProfileAPI) { self.api = api }

    func load() async {
        do {
            profile = try await api.fetchProfile()
        } catch is CancellationError {
            // view disappeared; ignore
        } catch {
            errorMessage = error.localizedDescription
        }
    }
}
```

**Follow-ups:**
- **Why ignore `CancellationError`?** It just means the view went away, which isn't an error to show the user.
- **Why `private(set)`?** Views can read the state but only the model can change it, which keeps the data flow clear.
- **Does `@MainActor` make the network call run on the main thread?** No. The API's own async work runs wherever it is isolated; only the property updates happen on the main actor.

### Q77. How do you model loading, loaded, empty, and error states? `[Senior]`
I use an enum for the screen state and `switch` over it in the view, so only one valid state is possible at a time. `ContentUnavailableView` gives standard empty and error screens.

```swift
enum LoadState<Value> { case idle, loading, loaded(Value), failed(String) }

switch model.state {
case .idle, .loading:
    ProgressView()
case .loaded(let articles) where articles.isEmpty:
    ContentUnavailableView("No Articles", systemImage: "doc.text")
case .loaded(let articles):
    List(articles) { ArticleRow(article: $0) }
case .failed(let message):
    ContentUnavailableView {
        Label("Couldn't Load", systemImage: "wifi.exclamationmark")
    } description: { Text(message) } actions: {
        Button("Retry") { Task { await model.load() } }
    }
}
```

**Follow-ups:**
- **Why an enum instead of `isLoading`, `items`, and `error` properties?** Separate properties allow impossible combinations, like loading and failed at the same time.
- **How do you show old data while refreshing?** Keep the data in `.loaded` and show a small indicator, or add a `.refreshing(Value)` case.
- **What is `ContentUnavailableView.search`?** A ready-made "No results" view for search screens, added in iOS 17.

### Q78. How do you react to app lifecycle changes in SwiftUI? `[Fundamental]`
I read `scenePhase` from the environment and react to `.active`, `.inactive`, and `.background` with `onChange`. For app delegate callbacks, like push tokens, I add `@UIApplicationDelegateAdaptor` to the `App` struct.

```swift
@Environment(\.scenePhase) private var scenePhase

ContentView()
    .onChange(of: scenePhase) { _, newPhase in
        switch newPhase {
        case .active:     model.resumeUpdates()
        case .background: model.saveDraft()
        default:          break
        }
    }
```

**Follow-ups:**
- **What is the difference between reading `scenePhase` in the `App` and in a view?** In the `App` it reflects all scenes together; in a view it reflects that view's own scene.
- **How do you get the push notification device token?** Implement it in an `AppDelegate` connected with `@UIApplicationDelegateAdaptor(AppDelegate.self)`.
- **When should you save data?** When the phase becomes `.background`, because the app may be suspended or killed afterwards.

## 10. Animations & Transitions

### Q79. What is the difference between implicit and explicit animations? `[Fundamental]`
An implicit animation, `.animation(_:value:)`, animates changes to the modifiers above it in the chain whenever `value` changes. An explicit animation, `withAnimation { }`, animates every view change caused by the state changes inside the block.

```swift
// Implicit
RoundedRectangle(cornerRadius: 16)
    .frame(height: isExpanded ? 300 : 100)
    .animation(.spring(duration: 0.4, bounce: 0.3), value: isExpanded)

// Explicit
Button("Toggle") {
    withAnimation(.snappy) { isExpanded.toggle() }
}
```

**Follow-ups:**
- **Why was `.animation(_:)` without `value` deprecated?** It animated any change in that view, including ones you didn't expect.
- **Which one do you prefer?** Explicit for user actions, because it's clear what triggers the animation; implicit for one view that always animates a specific value.
- **What are `.snappy`, `.smooth`, and `.bouncy`?** Ready-made spring animations added in iOS 17.

### Q80. What are transitions, and why doesn't my transition animate? `[Senior]`
A transition describes how a view appears or disappears, like `.opacity`, `.slide`, or `.move(edge:)`. It only animates if the insert or remove happens inside an animation, such as `withAnimation` or an `.animation` on a parent that stays on screen.

```swift
ZStack(alignment: .bottom) {
    Button("Show toast") {
        withAnimation(.spring) { showToast.toggle() }     // ✅ animation drives the transition
    }
    if showToast {
        ToastView(message: "Saved!")
            .transition(.move(edge: .bottom).combined(with: .opacity))
    }
}
```

**Follow-ups:**
- **What is the most common mistake?** Putting `.animation` on the view being removed; it disappears along with its own modifier.
- **How do you use different transitions for appear and disappear?** `.transition(.asymmetric(insertion: .scale, removal: .opacity))`.
- **Why does a view inside a `ZStack` sometimes not animate out?** Its z-order can change during removal; giving it a `.zIndex(1)` keeps it on top.

### Q81. What is `matchedGeometryEffect`? `[Senior]`
`matchedGeometryEffect` animates a view smoothly between two positions and sizes in different parts of the hierarchy, as if it were the same view, which is how you build hero animations. Both views share an `id` and a `@Namespace`, and only one should be visible at a time.

```swift
@Namespace private var namespace
@State private var isExpanded = false

VStack {
    if isExpanded {
        RoundedRectangle(cornerRadius: 24).fill(.blue)
            .matchedGeometryEffect(id: "card", in: namespace)
            .frame(height: 400)
    } else {
        RoundedRectangle(cornerRadius: 12).fill(.blue)
            .matchedGeometryEffect(id: "card", in: namespace)
            .frame(width: 100, height: 100)
    }
}
.onTapGesture { withAnimation(.spring(duration: 0.5)) { isExpanded.toggle() } }
```

**Follow-ups:**
- **Does modifier order matter with `matchedGeometryEffect`?** Yes. It matches the geometry of the view it's applied to, so putting it before or after `.frame` changes which size gets matched.
- **What if both views are visible at once?** Mark one as the source with `isSource: true`, otherwise the result is unpredictable.
- **What should you use for navigation and sheets on iOS 18+?** The built-in zoom transition (Q70).

### Q82. How do you make a custom shape animatable? `[Lead/Expert]`
SwiftUI animates a shape by interpolating its `animatableData` between the old and new values, so you expose the property you want animated through `animatableData`. For two values you use `AnimatablePair`, and iOS 26 added an `@Animatable` macro that writes this for you.

```swift
struct PieSlice: Shape {
    var progress: Double   // 0...1

    var animatableData: Double {
        get { progress }
        set { progress = newValue }
    }

    func path(in rect: CGRect) -> Path {
        let center = CGPoint(x: rect.midX, y: rect.midY)
        var path = Path()
        path.move(to: center)
        path.addArc(center: center, radius: min(rect.width, rect.height) / 2,
                    startAngle: .degrees(-90), endAngle: .degrees(-90 + 360 * progress),
                    clockwise: false)
        path.closeSubpath()
        return path
    }
}
```

**Follow-ups:**
- **What happens without `animatableData`?** The shape jumps straight from the old value to the new one.
- **How do you animate two values, like start and end angles?** Use `AnimatablePair<Double, Double>` and map `first` and `second` to your properties.
- **Can a `ViewModifier` be animatable too?** Yes, conform it to `Animatable` (or `AnimatableModifier` on older OS versions) and expose `animatableData`.

### Q83. What are `PhaseAnimator` and `KeyframeAnimator`? `[Senior]`
Both were added in iOS 17. `phaseAnimator` steps through a list of phases, each with its own animation, which is good for multi-step effects like a pulse. `keyframeAnimator` runs separate tracks of keyframes for different properties over time, which is good for complex choreographed motion.

```swift
// Pulse each time likeCount changes
Image(systemName: "heart.fill")
    .phaseAnimator([false, true], trigger: likeCount) { content, isUp in
        content.scaleEffect(isUp ? 1.3 : 1.0)
    } animation: { _ in .spring(duration: 0.25, bounce: 0.5) }

// Bounce a bell with two tracks
Image(systemName: "bell.fill")
    .keyframeAnimator(initialValue: BellValues(), trigger: notificationCount) { content, value in
        content.scaleEffect(value.scale).offset(y: value.verticalOffset)
    } keyframes: { _ in
        KeyframeTrack(\.scale) { SpringKeyframe(1.3, duration: 0.15); SpringKeyframe(1.0, duration: 0.3) }
        KeyframeTrack(\.verticalOffset) { LinearKeyframe(-10, duration: 0.15); SpringKeyframe(0, duration: 0.3) }
    }
```

**Follow-ups:**
- **What happens without a `trigger`?** The phase animator loops through its phases continuously.
- **What kinds of keyframes are there?** `LinearKeyframe`, `SpringKeyframe`, `CubicKeyframe`, and `MoveKeyframe`.
- **When would you pick keyframes over phases?** When different properties need different timing at the same time.

### Q84. What is a `Transaction`? `[Lead/Expert]`
Every state change happens inside a transaction that carries its animation; `withAnimation` simply sets the transaction's animation. With `.transaction { }` or `withTransaction` you can inspect or override the animation for part of the view tree, for example to turn it off for one view.

```swift
// Disable animation for this subtree even if the parent change is animated
BadgeView(count: count)
    .transaction { $0.animation = nil }

// Scoped animation (iOS 17): only modifiers inside the closure animate
Rectangle()
    .animation(.smooth) { content in
        content.opacity(isVisible ? 1 : 0)
    }
    .frame(width: isWide ? 300 : 100)      // not animated
```

**Follow-ups:**
- **How do you turn off all animations for one change?** `var t = Transaction(); t.disablesAnimations = true; withTransaction(t) { state = newValue }`.
- **Why is the scoped `.animation(_:body:)` useful?** It limits the animation to exactly the modifiers inside the closure, avoiding surprises.
- **Can you pass custom data through a transaction?** Yes, with custom `TransactionKey` values in iOS 17.

### Q85. How do you run code when an animation completes? `[Fundamental]`
Since iOS 17, `withAnimation` takes a `completion` closure that runs when the animation finishes.

```swift
withAnimation(.easeOut(duration: 0.3)) {
    isCardVisible = false
} completion: {
    removeCard()
}
```

**Follow-ups:**
- **How did people do this before iOS 17?** With `DispatchQueue.main.asyncAfter` using the same duration, which was fragile.
- **When does completion run for a spring animation?** By default when it is "logically complete," which can be before the spring fully stops; you can pass `completionCriteria: .removed` to wait until it's fully finished.
- **Is there a completion for implicit animations?** Not directly; use a `Transaction` with `addAnimationCompletion`.

### Q86. How do you animate text and SF Symbols? `[Fundamental]`
For numbers I use `.contentTransition(.numericText(...))`, which rolls the digits. For SF Symbols I use `.symbolEffect` for effects like bounce or variable color, and `.contentTransition(.symbolEffect(.replace))` to animate swapping one symbol for another.

```swift
Text("\(score)")
    .contentTransition(.numericText(value: Double(score)))   // rolling digits
    .animation(.snappy, value: score)

Image(systemName: "wifi")
    .symbolEffect(.variableColor.iterative, isActive: isSearching)

Image(systemName: isMuted ? "speaker.slash" : "speaker.wave.2")
    .contentTransition(.symbolEffect(.replace))
```

**Follow-ups:**
- **Why does `.numericText` need an animation?** The content transition only plays when the change happens inside an animation.
- **How do you play a one-time bounce?** `.symbolEffect(.bounce, value: count)` bounces each time `count` changes.
- **Do symbol effects respect Reduce Motion?** Yes, system symbol effects adapt automatically.

### Q87. How do you add haptic feedback? `[Fundamental]`
Since iOS 17, `.sensoryFeedback` plays a haptic whenever a trigger value changes, with feedback types like `.success`, `.selection`, or `.impact`.

```swift
Button("Add to cart") { cartCount += 1 }
    .sensoryFeedback(.success, trigger: cartCount)
```

**Follow-ups:**
- **How do you play feedback only for some changes?** Use the version with a condition closure: `.sensoryFeedback(.success, trigger: value) { old, new in new > old }`.
- **What did you use before iOS 17?** `UIImpactFeedbackGenerator` and `UINotificationFeedbackGenerator` from UIKit.
- **Should every tap have a haptic?** No. Use haptics for meaningful moments, or they lose their value.

## 11. Custom Views, Modifiers, Styles & Containers

### Q88. How do you create a custom `ViewModifier`? `[Fundamental]`
You create a struct that conforms to `ViewModifier` and implements `body(content:)`, then add a `View` extension so it reads like a built-in modifier. Unlike a plain extension function, a `ViewModifier` can hold its own `@State` and read the environment.

```swift
struct CardStyle: ViewModifier {
    var cornerRadius: CGFloat = 16

    func body(content: Content) -> some View {
        content
            .padding()
            .background(.background, in: RoundedRectangle(cornerRadius: cornerRadius))
            .shadow(color: .black.opacity(0.1), radius: 8, y: 4)
    }
}

extension View {
    func cardStyle(cornerRadius: CGFloat = 16) -> some View {
        modifier(CardStyle(cornerRadius: cornerRadius))
    }
}

Text("Hello").cardStyle()
```

**Follow-ups:**
- **When is a plain `View` extension enough?** When it only chains existing modifiers and needs no state or environment.
- **Can a modifier hold `@State`?** Yes, for example a shake modifier that tracks its own animation progress.
- **What is `Content` inside a modifier?** A stand-in for whatever view the modifier is applied to.

### Q89. How do you create a custom `ButtonStyle`? `[Senior]`
You conform to `ButtonStyle` and build the look in `makeBody(configuration:)`, using `configuration.label` and `configuration.isPressed`. Applying `.buttonStyle(...)` to a container styles every button inside it, and you keep the system's accessibility and press handling.

```swift
struct PrimaryButtonStyle: ButtonStyle {
    @Environment(\.isEnabled) private var isEnabled

    func makeBody(configuration: Configuration) -> some View {
        configuration.label
            .font(.headline)
            .frame(maxWidth: .infinity)
            .padding()
            .background(isEnabled ? Color.accentColor : .gray, in: RoundedRectangle(cornerRadius: 12))
            .foregroundStyle(.white)
            .scaleEffect(configuration.isPressed ? 0.97 : 1)
    }
}

extension ButtonStyle where Self == PrimaryButtonStyle {
    static var primary: PrimaryButtonStyle { PrimaryButtonStyle() }
}

VStack { Button("Continue") {}; Button("Skip") {}.disabled(true) }
    .buttonStyle(.primary)
```

**Follow-ups:**
- **Why use a `ButtonStyle` instead of `onTapGesture` on a custom view?** You keep VoiceOver support, keyboard and pointer handling, and the pressed state for free.
- **What is the difference between `ButtonStyle` and `PrimitiveButtonStyle`?** `PrimitiveButtonStyle` lets you control when the action fires, like on a long press, while `ButtonStyle` only changes the look.
- **Which other style protocols exist?** `LabelStyle`, `ToggleStyle`, `TextFieldStyle`, and `ProgressViewStyle`, among others.

### Q90. How do you build a generic container view that accepts content? `[Senior]`
I make the view generic over `Content: View` and store the content marked with `@ViewBuilder`, so callers can pass any views in a trailing closure, just like with `VStack`.

```swift
struct Card<Content: View>: View {
    let title: String
    @ViewBuilder let content: Content

    var body: some View {
        VStack(alignment: .leading, spacing: 8) {
            Text(title).font(.headline)
            content
        }
        .frame(maxWidth: .infinity, alignment: .leading)
        .cardStyle()
    }
}

Card(title: "Shipping") {
    Text("Arrives Tuesday")
    Text("Free delivery").foregroundStyle(.secondary)
}
```

**Follow-ups:**
- **Why store `Content` instead of a closure?** SwiftUI can compare a stored value, and the closure doesn't have to run again in every `body`.
- **How do you accept two content areas, like a header and a body?** Add a second generic type, for example `Card<Header: View, Content: View>`, with two view-builder parameters.
- **How do you make the content optional?** Add an extension initializer where `Content == EmptyView`.

### Q91. How do you build custom containers that inspect their subviews? `[Lead/Expert]`
Since iOS 18, `ForEach(subviews:)` and `Group(subviews:)` give you the individual subviews of a content parameter, even ones produced by a `ForEach`. That lets you build containers that behave like `List` or `VStack`, for example adding a divider between each child.

```swift
struct DividedStack<Content: View>: View {
    @ViewBuilder var content: Content

    var body: some View {
        VStack(spacing: 12) {
            Group(subviews: content) { subviews in
                ForEach(subviews) { subview in
                    subview
                    if subview.id != subviews.last?.id { Divider() }
                }
            }
        }
    }
}

DividedStack {
    Text("First")
    ForEach(["Second", "Third"], id: \.self) { Text($0) }
}
```

**Follow-ups:**
- **What is the difference between `ForEach(subviews:)` and `Group(subviews:)`?** `ForEach` visits each subview one by one, while `Group` gives you the whole collection, so you can count or index it.
- **How do you handle `Section`s?** Use `ForEach(sections:)`, which gives you each section's header, footer, and content.
- **How can children pass extra data to the container?** Through container values, defined with `@Entry` in `ContainerValues`.

### Q92. When should you extract a subview vs a computed property vs a function? `[Senior]`
A separate `View` struct has its own identity and dependency tracking, so SwiftUI can skip its `body` when its inputs don't change. A computed property or `@ViewBuilder` function is only code organization: it is still part of the parent's `body` and re-runs every time the parent does.

```swift
// Organization only: re-runs with the parent
private var header: some View { Text(title).font(.largeTitle) }

// Separate struct: can be skipped when `title` is unchanged
struct Header: View {
    let title: String
    var body: some View { Text(title).font(.largeTitle) }
}
```

**Follow-ups:**
- **When do you extract a struct?** When the part has its own state, reads frequently changing data, or is reused.
- **Is a computed property ever the better choice?** Yes, for small pieces that depend on the same data as the parent, to keep the file readable.
- **Does extracting many small structs slow SwiftUI down?** No, view structs are cheap, and smaller views usually mean fewer updates.

### Q93. How do you create a reusable style system / theme? `[Lead/Expert]`
I define design tokens for colors, fonts, and spacing in a package, use asset catalog colors so Dark Mode works, and expose styles and modifiers instead of components with many parameters. The theme is passed through the environment, and static members like `.buttonStyle(.primary)` make it easy to discover.

```swift
enum Spacing { static let small: CGFloat = 8; static let medium: CGFloat = 16 }

extension Color {
    static let brandPrimary = Color("BrandPrimary")   // asset catalog, light + dark
}

extension EnvironmentValues {
    @Entry var theme: Theme = .standard
}

Button("Continue") {}
    .buttonStyle(.primary)
    .padding(Spacing.medium)
```

**Follow-ups:**
- **Why prefer styles over big configurable components?** Styles keep the system behavior and accessibility, and are easier to combine.
- **How do you make fonts scale with Dynamic Type?** Map tokens to text styles, like `.font(.custom("Brand", size: 17, relativeTo: .body))`.
- **How do you keep the system consistent?** A catalog app with previews of every component, plus snapshot tests.

## 12. Gestures

### Q94. How do you implement a draggable view? What is `@GestureState`? `[Senior]`
You attach a `DragGesture` and offset the view by the drag's translation. `@GestureState` holds temporary values during the gesture and resets automatically when it ends or is cancelled, while `onEnded` saves the final position into normal `@State`.

```swift
struct DraggableCard: View {
    @State private var position: CGSize = .zero
    @GestureState private var dragOffset: CGSize = .zero

    var body: some View {
        RoundedRectangle(cornerRadius: 16).fill(.blue)
            .frame(width: 200, height: 120)
            .offset(x: position.width + dragOffset.width,
                    y: position.height + dragOffset.height)
            .gesture(
                DragGesture()
                    .updating($dragOffset) { value, state, _ in state = value.translation }
                    .onEnded { value in
                        position.width += value.translation.width
                        position.height += value.translation.height
                    }
            )
    }
}
```

**Follow-ups:**
- **Why not use `@State` for the drag offset?** If the gesture is cancelled, `@State` wouldn't reset, but `@GestureState` does automatically.
- **How do you make a swipe-to-dismiss card?** In `onEnded`, check if the translation or `predictedEndTranslation` passes a threshold, then animate it away.
- **How do you make the card spring back?** Add `.animation(.spring, value: dragOffset)`, so the reset animates.

### Q95. How do you combine gestures? `[Senior]`
`.simultaneously(with:)` runs two gestures at the same time, like pinch and rotate; `.sequenced(before:)` requires one to finish before the next starts, like long press then drag; and `.exclusively(before:)` lets only one win, like double tap over single tap.

```swift
// Pinch and rotate together
Image("photo")
    .scaleEffect(scale)
    .rotationEffect(angle)
    .gesture(
        MagnifyGesture().onChanged { scale = $0.magnification }
            .simultaneously(with: RotateGesture().onChanged { angle = $0.rotation })
    )

// Double tap wins over single tap
let taps = TapGesture(count: 2).onEnded { zoom() }
    .exclusively(before: TapGesture().onEnded { toggleControls() })
```

**Follow-ups:**
- **What do `.highPriorityGesture` and `.simultaneousGesture` do?** The first makes your gesture win over child gestures; the second lets it run alongside them, for example inside a `ScrollView`.
- **What replaced `MagnificationGesture` and `RotationGesture`?** `MagnifyGesture` and `RotateGesture` in iOS 17.
- **Why does a drag inside a `ScrollView` block scrolling?** The drag takes priority; use `.simultaneousGesture` or a minimum distance.

### Q96. Why isn't my tap gesture firing on empty areas of a view? `[Fundamental]`
By default only visible content can be tapped, so the empty space in a stack, like a `Spacer`, isn't hit-testable. `.contentShape(Rectangle())` makes the whole area tappable.

```swift
HStack {
    Text("Settings")
    Spacer()
    Image(systemName: "chevron.right")
}
.contentShape(Rectangle())      // the Spacer area becomes tappable
.onTapGesture { openSettings() }
```

**Follow-ups:**
- **Should this be a `Button` instead?** Usually yes, because a `Button` is accessible to VoiceOver and keyboards by default.
- **Does `contentShape` also help `Button`s with plain style?** Yes, the same rule applies to buttons with `.plain` style.
- **How do you make a view ignore taps?** `.allowsHitTesting(false)`, so taps pass through to views behind it.

## 13. Performance

### Q97. What are the most common causes of poor SwiftUI performance? `[Senior]`
The usual causes are views that depend on more data than they need, unstable identity, expensive work in `body` or `init`, `AnyView` everywhere, non-lazy stacks for long content, too much `GeometryReader`, and state that changes far too often, like a scroll offset.

```swift
// ❌ Sorting and formatting in body, on every update
var body: some View {
    List(events.sorted { $0.date < $1.date }) { event in
        Text(DateFormatter().string(from: event.date))
    }
}
```

**Follow-ups:**
- **Which one do you check first?** Over-broad dependencies, because they multiply every other cost.
- **How does a big `ObservableObject` hurt?** Any `@Published` change updates every view observing it, even views that don't use that property.
- **Where should you test performance?** In a Release build on an older real device, not in the simulator.

### Q98. How do you find out why a view's `body` re-ran? `[Senior]`
In debug builds, I call `Self._printChanges()` inside `body`, which prints which dependency changed. For a broader picture, I use the SwiftUI instrument in Instruments, plus the Time Profiler and Hangs.

```swift
var body: some View {
    let _ = Self._printChanges()   // debug only
    Text(model.title)
}
// Prints e.g. "ProductRow: @self, _model changed."
```

**Follow-ups:**
- **What does `@self` in the output mean?** The view's own struct inputs changed, meaning the parent passed new values.
- **Should `_printChanges` ship to production?** No, it's a private debugging API; remove it or wrap it in `#if DEBUG`.
- **What did Xcode 26 add?** A redesigned SwiftUI instrument that shows long body updates and why views updated.

### Q99. How do you reduce unnecessary view updates? `[Senior]`
I split large views into smaller structs, pass each child only the values it shows, use `@Observable` for fine-grained tracking, compute derived data in the model instead of in `body`, and keep fast-changing values out of state that big views read.

```swift
// ❌ Every row depends on the whole store
struct Row: View {
    let store: Store
    let id: Item.ID
    var body: some View { Text(store.items[id]?.title ?? "") }
}

// ✅ Row depends only on what it shows
struct Row: View {
    let title: String
    var body: some View { Text(title) }
}
```

**Follow-ups:**
- **How do you handle a value like a timer that changes every second?** Read it only in a small leaf view, so only that view updates.
- **Is passing a whole `@Observable` model to a row bad?** Less so than with `ObservableObject`, because the row only tracks the properties it reads.
- **How do you confirm the change helped?** Count body updates with `_printChanges` or the SwiftUI instrument before and after.

### Q100. Why is `AnyView` bad for performance? `[Senior]`
`AnyView` erases the view's type, so SwiftUI can't use structural identity; when the wrapped type changes, SwiftUI has to tear down and rebuild that part, losing state and animations, and diffing is less efficient. I use `@ViewBuilder`, `Group`, generics, or `some View` instead.

```swift
// ❌
func icon(for status: Status) -> AnyView {
    status == .done ? AnyView(Image(systemName: "checkmark")) : AnyView(ProgressView())
}

// ✅
@ViewBuilder
func icon(for status: Status) -> some View {
    if status == .done { Image(systemName: "checkmark") } else { ProgressView() }
}
```

**Follow-ups:**
- **When is `AnyView` acceptable?** Rarely, for example in a plugin system where view types truly aren't known at compile time.
- **Is one `AnyView` at the root a big problem?** Usually not; the cost grows when it's used in many rows or changes type often.
- **What about storing views of different types in an array?** Store data instead, and map it to views with `ForEach` and a `switch`.

### Q101. How do you avoid expensive work in `body`? `[Senior]`
I move sorting, filtering, and formatting out of `body` into the model, where they're computed once when the data changes. For display I use `FormatStyle`, like `.dateTime`, which the system caches, instead of creating formatters.

```swift
// ✅ Precomputed in the model, cached FormatStyle
var body: some View {
    List(model.sortedEvents) { event in
        Text(event.date, format: .dateTime.day().month().year())
    }
}
```

**Follow-ups:**
- **Why is creating a `DateFormatter` in `body` expensive?** Formatters are slow to create, and `body` can run many times per second.
- **What if the derived data depends on user input like a filter?** Recompute it in the model when the input changes, not on every `body` run.
- **Is `view.init` a good place for heavy work?** No. Like `body`, it can run many times; use `.task` or the model.

### Q102. How does `Equatable` conformance help view performance? `[Lead/Expert]`
If a view conforms to `Equatable`, SwiftUI can use your `==` to decide whether to re-run its `body` when the parent updates. This helps when a view has inputs SwiftUI can't compare, like closures, but you know which fields really matter.

```swift
struct ChartView: View, Equatable {
    let points: [Double]
    let onSelect: (Int) -> Void           // closures can't be compared

    static func == (lhs: Self, rhs: Self) -> Bool {
        lhs.points == rhs.points          // ignore the closure
    }

    var body: some View { Text("\(points.count) points") }
}

// ChartView(points: data, onSelect: select).equatable()
```

**Follow-ups:**
- **What does `.equatable()` add?** It wraps the view so SwiftUI is told explicitly to use your `==`.
- **What is the risk?** If `==` ignores a field that affects the UI, the view won't update when it should.
- **Is this needed with `@Observable` models?** Less often, because observation already limits updates to what the view reads.

### Q103. How do you optimize long lists and image-heavy feeds? `[Lead/Expert]`
I use `List` or lazy stacks with stable IDs, keep rows small and cheap with precomputed text, load images with downsampling and a memory cache, avoid heavy per-row effects like large blurs, prefetch the next page early, and profile in Release on an older device. Before iOS 27, `AsyncImage` had no cache, so feeds needed a custom loader; in iOS 27 it uses standard HTTP caching by default.

```swift
// iOS 27: control AsyncImage caching with your own session
AsyncImage(url: post.imageURL) { image in
    image.resizable().scaledToFill()
} placeholder: {
    Color.gray.opacity(0.2)
}
.asyncImageURLSession(imageSession)     // session configured with a URLCache
```

**Follow-ups:**
- **What is downsampling?** Decoding an image at the size it's shown, not at its full resolution, which saves a lot of memory.
- **Which libraries do teams use for image loading?** Nuke or Kingfisher, or a small custom loader using `NSCache`.
- **Why are big shadows expensive in rows?** They need extra offscreen rendering for every row; simpler effects or pre-rendered images are cheaper.

### Q104. What does `drawingGroup()` do? `[Lead/Expert]`
`drawingGroup()` flattens a complex view subtree into one offscreen image rendered with Metal before it's shown. It helps when you have many overlapping shapes or gradients, like charts or particles, but hurts for simple views or text, so I measure before using it.

```swift
ZStack {
    ForEach(0..<300) { i in
        Circle()
            .fill(.blue.opacity(0.1))
            .frame(width: 20, height: 20)
            .offset(x: CGFloat(i % 20) * 12, y: CGFloat(i / 20) * 12)
    }
}
.drawingGroup()      // render all circles in one Metal pass
```

**Follow-ups:**
- **Why can it make text look worse?** It turns text into a bitmap, so it may lose sharpness and accessibility benefits.
- **What is the alternative for very custom drawing?** `Canvas`, which draws many shapes efficiently in one view.
- **How do you know if it helped?** Compare frame times in Instruments with and without it.

## 14. Accessibility, Dynamic Type & Localization

### Q105. How do you make SwiftUI views accessible? `[Senior]`
Standard controls like `Button`, `Toggle`, and `Label` are accessible by default. For custom views I combine related elements into one with `.accessibilityElement(children: .combine)`, give clear labels, hide decorative images, and add custom actions where a swipe or long press would be hard to find.

```swift
HStack {
    Image(systemName: "star.fill")
    Text("4.5")
    Text("(120 reviews)")
}
.accessibilityElement(children: .combine)
.accessibilityLabel("Rated 4.5 stars from 120 reviews")

Image("decorative-wave").accessibilityHidden(true)

ProductCard(product: product)
    .accessibilityAction(named: "Add to cart") { addToCart(product) }
```

**Follow-ups:**
- **What if you use `onTapGesture` on a custom view?** VoiceOver won't treat it as a button unless you add `.accessibilityAddTraits(.isButton)`; a `Button` is better.
- **What is the difference between `.combine` and `.ignore`?** `.combine` merges the children's labels into one element; `.ignore` hides them so you provide the label yourself.
- **How do you label an icon-only button?** Add `.accessibilityLabel("Add to favorites")`, describing the action, not the icon.

### Q106. How do you support Dynamic Type? `[Senior]`
I use system text styles like `.body`, which scale automatically, scale custom sizes with `@ScaledMetric`, and switch layouts with `AnyLayout` at accessibility sizes. I limit scaling with `.dynamicTypeSize(...)` only where the layout truly can't adapt.

```swift
struct ProfileRow: View {
    @ScaledMetric(relativeTo: .body) private var avatarSize: CGFloat = 40
    @Environment(\.dynamicTypeSize) private var dynamicTypeSize

    var body: some View {
        let layout = dynamicTypeSize.isAccessibilitySize
            ? AnyLayout(VStackLayout(alignment: .leading))
            : AnyLayout(HStackLayout())
        layout {
            Image(systemName: "person.circle").resizable()
                .frame(width: avatarSize, height: avatarSize)
            Text("Taylor").font(.body)
        }
    }
}
```

**Follow-ups:**
- **How do you scale a custom font?** `.font(.custom("Avenir", size: 17, relativeTo: .body))`.
- **When is limiting the size acceptable?** For small, fixed UI like a tab label: `.dynamicTypeSize(...DynamicTypeSize.accessibility2)`.
- **What else should change at large sizes?** Long text should wrap instead of truncating, and horizontal rows often become vertical.

### Q107. How does localization work in SwiftUI? `[Senior]`
`Text("Hello")` with a string literal uses `LocalizedStringKey` and is looked up in the String Catalog. `Text(someStringVariable)` is not localized, so I localize variables with `String(localized:)`; interpolations become format arguments that support plurals, and `FormatStyle` formats dates, numbers, and currency for the user's locale.

```swift
Text("Welcome back, \(user.name)!")                     // localized, with argument
Text(price, format: .currency(code: "EUR"))
let title = String(localized: "settings.title", comment: "Settings screen title")
Text(verbatim: "v1.2.3")                                // never localized
```

**Follow-ups:**
- **What is a String Catalog?** The `.xcstrings` file from Xcode 15 that collects all strings and their translations, including plural rules.
- **How do you handle "1 item" vs "2 items"?** Write `Text("\(count) items")` and add plural variations in the String Catalog.
- **How do you localize strings in a Swift package?** Pass `bundle: .module`, for example `String(localized: "title", bundle: .module)`.

### Q108. How do you test accessibility and localization in previews? `[Fundamental]`
I create previews that set a large Dynamic Type size, dark mode, right-to-left layout, and another locale through the environment. I also use the Accessibility Inspector and the canvas Variants mode.

```swift
#Preview("Large text, dark, RTL") {
    ProfileRow()
        .environment(\.dynamicTypeSize, .accessibility3)
        .preferredColorScheme(.dark)
        .environment(\.layoutDirection, .rightToLeft)
        .environment(\.locale, Locale(identifier: "ar"))

```

**Follow-ups:**
- **What does the Variants mode show?** The same preview across Dynamic Type sizes, color schemes, or orientations side by side.
- **How do you test long translations without real ones?** Use the "Double-Length Pseudolanguage" option in the scheme to find truncation.
- **Does setting `locale` in a preview change the translations?** Yes for `Text` with string literals, as long as the translations exist; strings made earlier with `String(localized:)` follow the app's language instead.

## 15. Previews & Tooling

### Q109. How do you write previews effectively? `[Fundamental]`
I write one `#Preview` per important state, like loaded, empty, and error, with sample data and mock services. In iOS 18, `@Previewable` lets me use `@State` directly in a preview.

```swift
#Preview("Loaded") {
    ProductListView(model: .preview(products: Product.samples))
}

#Preview("Empty") {
    ProductListView(model: .preview(products: []))
}

#Preview {
    @Previewable @State var isOn = true
    Toggle("Wi-Fi", isOn: $isOn)
}
```

**Follow-ups:**
- **What makes a view easy to preview?** Injected dependencies through protocols or the environment, plus ready-made sample data.
- **How do you preview just a row at its natural size?** `#Preview(traits: .sizeThatFitsLayout) { ProductRow(product: .sample) }`.
- **Can previews show UIKit views?** Yes, `#Preview` can return a `UIView` or `UIViewController` directly.

### Q110. How do you share setup (like a SwiftData container) across previews? `[Senior]`
In iOS 18 I create a `PreviewModifier` whose `makeSharedContext` builds the setup once, like an in-memory SwiftData container with sample data, and expose it as a preview trait that any preview can use.

```swift
struct SampleData: PreviewModifier {
    static func makeSharedContext() async throws -> ModelContainer {
        let container = try ModelContainer(for: Trip.self,
            configurations: ModelConfiguration(isStoredInMemoryOnly: true))
        Trip.samples.forEach { container.mainContext.insert($0) }
        return container
    }

    func body(content: Content, context: ModelContainer) -> some View {
        content.modelContainer(context)
    }
}

extension PreviewTrait where T == Preview.ViewTraits {
    @MainActor static var sampleData: Self = .modifier(SampleData())
}

#Preview(traits: .sampleData) { TripListView() }
```

**Follow-ups:**
- **Why "shared" context?** It's created once and cached across previews, so each preview doesn't rebuild the container.
- **Why in-memory storage?** Previews start clean every time and never touch real user data.
- **How did people do this before iOS 18?** A static `previewContainer` property created manually and passed to each preview.

### Q111. Why do previews crash or become slow, and how do you fix it? `[Senior]`
Previews usually crash or slow down because they run real network or database calls, singletons, heavy app startup code, or miss a required environment object. I fix it by injecting mock services, providing every environment object, and keeping preview targets small in modular packages.

```swift
#Preview {
    CartView()
        .environment(Cart.preview)                              // required object provided
        .environment(\.productAPI, MockProductAPI(products: .samples))   // no real network
}
```

**Follow-ups:**
- **How do you see why a preview crashed?** Open the preview diagnostics in Xcode, which show the crash log.
- **Why do modular packages preview faster?** Xcode builds only the small package instead of the whole app.
- **How do you stop app startup code from running in previews?** Move it out of view initializers, or check the `XCODE_RUNNING_FOR_PREVIEWS` environment variable as a last resort.

## 16. Architecture & Dependency Injection

### Q112. Do you need MVVM in SwiftUI? `[Lead/Expert]`
It depends on complexity. The "MV" argument says SwiftUI views already act like view models, so a view model per screen can duplicate state; the MVVM argument says a separate model keeps presentation logic testable without UI and gives large teams a consistent structure. My answer: simple screens can bind directly to models, complex screens get a dedicated `@Observable` screen model, and either way business logic stays out of views.

```swift
// Simple screen: bind directly to a shared model
struct CartBadge: View {
    @Environment(Cart.self) private var cart
    var body: some View { Text("\(cart.items.count)") }
}

// Complex screen: dedicated, testable screen model
@MainActor @Observable
final class CheckoutViewModel {
    var state: CheckoutState = .editing
    func placeOrder() async { /* validation, API call, error mapping */ }
}
```

**Follow-ups:**
- **What does Apple's own sample code tend to use?** `@Observable` models shared through the environment, without a view model per screen.
- **What goes in a view model?** Formatting, validation, loading states, and calls to services; not layout.
- **What matters most for a team?** Consistency, so everyone writes screens the same way.

### Q113. Show an MVVM screen with `@Observable` and dependency injection. `[Senior]`
The view model is a `@MainActor @Observable` class that receives a protocol-typed API in its initializer and exposes a state enum. The view owns it with `@State`, starts loading in `.task`, and switches over the state.

```swift
protocol ProductAPI: Sendable { func fetchProducts() async throws -> [Product] }

@MainActor @Observable
final class ProductListViewModel {
    enum State { case idle, loading, loaded([Product]), failed(String) }
    private(set) var state: State = .idle
    private let api: ProductAPI
    init(api: ProductAPI) { self.api = api }

    func loadIfNeeded() async {
        guard case .idle = state else { return }    // .task re-runs on each appearance
        await load()
    }

    func load() async {
        state = .loading
        do { state = .loaded(try await api.fetchProducts()) }
        catch { state = .failed(error.localizedDescription) }
    }
}

struct ProductListView: View {
    @State private var viewModel: ProductListViewModel
    init(api: ProductAPI) { _viewModel = State(initialValue: ProductListViewModel(api: api)) }

    var body: some View {
        content
            .task { await viewModel.loadIfNeeded() }
            .refreshable { await viewModel.load() }
    }
    // content switches over viewModel.state (see Q77)
}
```

**Follow-ups:**
- **Why `loadIfNeeded` instead of calling `load` in `.task`?** `.task` runs on every appearance, so without the guard the list reloads each time you come back.
- **Why is the API a protocol?** So tests and previews can inject a mock.
- **Why must `ProductListViewModel.init` stay cheap?** On toolchains before Xcode 27, the `@State` initial value can be created many times (Q31).

### Q114. How do you inject services through the environment? `[Senior]`
I add an `@Entry` environment value with the live service as the default, read it with `@Environment` where it's needed, and override it with a mock in previews and tests.

```swift
extension EnvironmentValues {
    @Entry var productAPI: any ProductAPI = LiveProductAPI()
}

struct ProductsScreen: View {
    @Environment(\.productAPI) private var api
    var body: some View { ProductListView(api: api) }
}

#Preview {
    ProductsScreen()
        .environment(\.productAPI, MockProductAPI(products: Product.samples))
}
```

**Follow-ups:**
- **What are the pros?** No passing through every layer, and previews can swap in mocks easily.
- **What are the cons?** Dependencies are less visible than with initializer injection.
- **Can a view model read the environment directly?** No, only views can; the view reads the service and passes it to the view model.

### Q115. What is The Composable Architecture (TCA), and what are its trade-offs? `[Lead/Expert]`
TCA is a third-party architecture from Point-Free built on State, Action, Reducer, and Store, with built-in dependency management and very thorough testing. Its strengths are predictable state changes, testing every state change and effect, and consistent patterns for big teams; its costs are a learning curve, boilerplate, dependence on a third-party library, and compile time.

```swift
@Reducer
struct Counter {
    @ObservableState
    struct State: Equatable { var count = 0 }
    enum Action { case incrementTapped }

    var body: some ReducerOf<Self> {
        Reduce { state, action in
            switch action {
            case .incrementTapped:
                state.count += 1
                return .none
            }
        }
    }
}
```

**Follow-ups:**
- **When would you choose TCA over plain `@Observable` models?** For a large team that values strict, testable state changes and is willing to invest in learning it.
- **What is an "effect" in TCA?** Async work, like a network call, returned from the reducer that can send new actions later.
- **What is the risk of adopting it?** You depend on the library's release schedule and API changes, and new hires need time to learn it.

### Q116. How do you structure a large SwiftUI app into modules? `[Lead/Expert]`
I use one Swift package per feature, like `ProfileFeature` and `CheckoutFeature`, plus shared packages like `DesignSystem`, `Networking`, and `Models`. Features depend on interfaces instead of each other, and the app target composes them, which gives faster builds and previews and clear boundaries.

```swift
// Package.swift (excerpt)
.target(name: "CheckoutFeature", dependencies: ["DesignSystem", "Models", "NetworkingInterface"]),
.target(name: "ProfileFeature",  dependencies: ["DesignSystem", "Models"]),

// App target composes features
NavigationStack(path: $router.path) {
    HomeView()
        .navigationDestination(for: AppRoute.self) { route in
            switch route {
            case .checkout: CheckoutFeature.RootView()
            case .profile:  ProfileFeature.RootView()
            }
        }
}
```

**Follow-ups:**
- **How do features navigate to each other without importing each other?** Through route enums that the app layer maps to views.
- **What goes in an "interface" package?** Protocols and models only, so features can depend on them without the heavy implementation.
- **What is a sign a module is too big?** Long incremental builds and slow previews for small changes.

### Q117. Where should navigation logic live in SwiftUI? `[Lead/Expert]`
For simple apps, inside views with `NavigationLink(value:)`. For bigger apps, in a `Router` object that owns the path (Q61), or per-flow coordinators, which makes deep links, login gating, and analytics testable without UI.

```swift
@Test @MainActor func checkoutFlowPushesConfirmation() {
    let router = Router()
    router.push(.cart)
    router.push(.orderConfirmation(orderID: "A123"))
    #expect(router.path == [.cart, .orderConfirmation(orderID: "A123")])
}
```

**Follow-ups:**
- **What is the downside of `NavigationLink` everywhere?** Navigation logic is spread across many views and is hard to test or drive from deep links.
- **Where does TCA keep navigation?** In the feature's state, as a stack of child feature states.
- **How do you handle sheets in a router?** Add an optional `sheet` property with an enum of sheet destinations and use `.sheet(item:)`.

## 17. SwiftData & UIKit Integration (Quick Reference)

> SwiftData and UIKit have their own detailed files. These are the SwiftUI-side essentials.

### Q118. How do you use SwiftData in a SwiftUI view? `[Fundamental]`
You mark model classes with `@Model`, add a container with `.modelContainer(for:)`, fetch with `@Query`, and insert or delete through the `modelContext` from the environment. `@Query` keeps the results in sync automatically.

```swift
@Model
final class Trip {
    var name: String
    var startDate: Date
    init(name: String, startDate: Date) { self.name = name; self.startDate = startDate }
}

struct TripListView: View {
    @Query(sort: \Trip.startDate, order: .reverse) private var trips: [Trip]
    @Environment(\.modelContext) private var modelContext

    var body: some View {
        List {
            ForEach(trips) { Text($0.name) }
                .onDelete { $0.forEach { modelContext.delete(trips[$0]) } }
        }
        .toolbar {
            Button("Add") { modelContext.insert(Trip(name: "New Trip", startDate: .now)) }
        }
    }
}
// App: WindowGroup { TripListView() }.modelContainer(for: Trip.self)
```

**Follow-ups:**
- **How do you filter with a value from the user?** Create the query in the view's `init` with a `#Predicate`, like `_trips = Query(filter: #Predicate { $0.name.contains(search) })`.
- **Do you have to call `save()`?** Usually not; SwiftData autosaves the main context, but you can call `try modelContext.save()` for important changes.
- **Is `@Query` usable in a view model?** No, it only works inside views; a view model uses `ModelContext.fetch` instead.

### Q119. How do you wrap a UIKit view controller for SwiftUI? `[Senior]`
You conform to `UIViewControllerRepresentable`: `makeUIViewController` creates the controller once, and `updateUIViewController` copies SwiftUI state into it when inputs change. A `Coordinator` handles delegates.

```swift
import SafariServices

struct SafariView: UIViewControllerRepresentable {
    let url: URL

    func makeUIViewController(context: Context) -> SFSafariViewController {
        SFSafariViewController(url: url)
    }

    func updateUIViewController(_ controller: SFSafariViewController, context: Context) { }
}

// .sheet(item: $link) { SafariView(url: $0.url).ignoresSafeArea() }
```

**Follow-ups:**
- **What is the `Coordinator` for?** It is an object that acts as the UIKit delegate and sends changes back to SwiftUI, often through a binding.
- **How do you go the other way, SwiftUI inside UIKit?** Use `UIHostingController`, or `UIHostingConfiguration` for table and collection view cells.
- **Why not create the view in `update`?** `update` can run many times; creating the view there would rebuild it on every change.

### Q120. When would you drop down to UIKit inside a SwiftUI app? `[Lead/Expert]`
When SwiftUI is missing an API on my deployment target, like advanced text editing before iOS 26's rich `TextEditor` or some camera and scanner flows; when a screen is very performance-critical and needs precise control; or when I can reuse a mature, well-tested UIKit component. I keep the bridge thin so it can be replaced later.

```swift
// Thin wrapper: SwiftUI-friendly API, UIKit inside
struct RichTextView: UIViewRepresentable {
    @Binding var text: NSAttributedString

    func makeUIView(context: Context) -> UITextView { UITextView() }

    func updateUIView(_ view: UITextView, context: Context) {
        if view.attributedText != text { view.attributedText = text }
    }
}
```

**Follow-ups:**
- **Why compare before setting in `updateUIView`?** Setting it again would reset the cursor and could cause update loops.
- **How do you send UIKit changes back to SwiftUI?** Through a `Coordinator` that is the `UITextView` delegate and writes to the binding.
- **How do you decide it's time to remove the bridge?** When the minimum iOS version supports a SwiftUI equivalent that meets the requirements.

## 18. Testing SwiftUI

### Q121. How do you test SwiftUI code? `[Senior]`
I unit test the logic, not the views: models, view models, routers, and formatters, because that's where most bugs are and those tests are fast. I add snapshot tests for visual regressions and a few UI tests for critical flows; view-inspection libraries exist but are brittle.

```swift
import Testing
@testable import Shop

struct MockProductAPI: ProductAPI {
    var result: Result<[Product], Error>
    func fetchProducts() async throws -> [Product] { try result.get() }
}

@MainActor
struct ProductListViewModelTests {
    @Test func loadSuccessShowsProducts() async {
        let viewModel = ProductListViewModel(api: MockProductAPI(result: .success([.sample])))
        await viewModel.load()
        guard case .loaded(let products) = viewModel.state else {
            Issue.record("Expected loaded state"); return
        }
        #expect(products.count == 1)
    }
}
```

**Follow-ups:**
- **Why put `@MainActor` on the test suite?** The view model is main-actor isolated, so the tests must run there too.
- **How do you test the error path?** Inject a mock that returns `.failure(...)` and assert the state is `.failed`.
- **What makes view models testable?** Injected protocol dependencies and state exposed as plain values.

### Q122. How do you write UI tests for SwiftUI views? `[Fundamental]`
I give important elements an `.accessibilityIdentifier`, launch the app with a test flag, find elements by those identifiers, and wait for results with `waitForExistence`.

```swift
// App
Button("Add to cart") { model.add(product) }
    .accessibilityIdentifier("product.addToCart")

// UI test
@MainActor
func testAddToCartUpdatesBadge() {
    let app = XCUIApplication()
    app.launchArguments = ["-uiTesting"]
    app.launch()

    app.buttons["product.addToCart"].tap()
    XCTAssertTrue(app.staticTexts["cart.badge"].waitForExistence(timeout: 2))
    XCTAssertEqual(app.staticTexts["cart.badge"].label, "1")
}
```

**Follow-ups:**
- **Why use identifiers instead of visible text?** Text changes with localization and copy updates; identifiers stay stable.
- **What does the `-uiTesting` argument do?** The app checks it at launch and switches to mock services and a clean state.
- **Why are UI tests kept few?** They are slow and flaky compared to unit tests, so they cover only critical flows.

### Q123. How do you snapshot test SwiftUI views? `[Senior]`
I use a library like SnapshotTesting to render the view to an image and compare it with a saved reference, in several variants like large text and dark mode.

```swift
import SnapshotTesting
import XCTest

final class ProductRowSnapshotTests: XCTestCase {
    @MainActor
    func testProductRowVariants() {
        let view = ProductRow(product: .sample).frame(width: 375)

        assertSnapshot(of: view.environment(\.dynamicTypeSize, .accessibility3),
                       as: .image(layout: .sizeThatFits), named: "a11y-large")
        assertSnapshot(of: view.preferredColorScheme(.dark),
                       as: .image(layout: .sizeThatFits), named: "dark")
    }
}
```

**Follow-ups:**
- **Why do snapshot tests fail falsely on CI?** Different simulator models or OS versions render slightly differently; pin both in CI.
- **How do you update a reference image on purpose?** Run the test in record mode, review the new image, and commit it.
- **What do snapshot tests not catch?** Behavior, like what happens on tap; that needs unit or UI tests.

## 19. Modern SwiftUI (iOS 17 → iOS 27)

### Q124. What were the key SwiftUI additions in iOS 17? `[Senior]`
iOS 17 brought the Observation framework (`@Observable`, `@Bindable`) and SwiftData, plus `ContentUnavailableView`, phase and keyframe animators, animation completions, and new scroll APIs like `scrollTargetBehavior`, `scrollPosition(id:)`, and `containerRelativeFrame`. It also added the two-value `onChange`, `sensoryFeedback`, and the `#Preview` macro.

```swift
@Observable final class Store { var items: [Item] = [] }

ScrollView(.horizontal) {
    LazyHStack { ForEach(items) { CardView(item: $0).containerRelativeFrame(.horizontal) } }
        .scrollTargetLayout()
}
.scrollTargetBehavior(.viewAligned)
```

**Follow-ups:**
- **Which iOS 17 feature had the biggest architecture impact?** `@Observable`, because it changed how models are owned, shared, and tracked.
- **What did `scrollTransition` add?** Effects like scale or opacity based on a view's position as it scrolls in and out.
- **What replaced `MagnificationGesture`?** `MagnifyGesture`, along with `RotateGesture`.

### Q125. What were the key SwiftUI additions in iOS 18? `[Senior]`
iOS 18 added the new `Tab` API with sidebar-adaptable tabs, zoom navigation transitions, custom containers with `ForEach(subviews:)`, the `@Entry` and `@Previewable` macros, `PreviewModifier`, and new scroll APIs like `onScrollGeometryChange` and `onScrollVisibilityChange`. The `View` protocol also became `@MainActor`.

```swift
TabView {
    Tab("Home", systemImage: "house") { HomeView() }
    Tab(role: .search) { SearchView() }
}
.tabViewStyle(.sidebarAdaptable)

extension EnvironmentValues { @Entry var theme: Theme = .standard }
```

**Follow-ups:**
- **What else arrived for graphics?** `MeshGradient` and `TextRenderer` for custom text drawing.
- **Which iOS 18 API was back-deployed?** `onGeometryChange`, back to iOS 16.
- **Why did `View` becoming `@MainActor` matter?** View code is now checked as main-actor code by the compiler, which affects Swift 6 migrations.

### Q126. What changed in SwiftUI with iOS 26? `[Senior]`
iOS 26 introduced the Liquid Glass design: system bars, tab bars, toolbars, and sheets adopt it automatically, and `.glassEffect()`, `GlassEffectContainer`, and `.buttonStyle(.glass)` bring it to custom UI. It also added a native `WebView`, rich text editing with `TextEditor` and `AttributedString`, the `@Animatable` macro, and a new SwiftUI performance instrument in Xcode 26.

```swift
GlassEffectContainer {
    HStack(spacing: 12) {
        Button("Edit", systemImage: "pencil") { edit() }
            .buttonStyle(.glass)
        Image(systemName: "star.fill")
            .padding()
            .glassEffect()
    }
}
```

**Follow-ups:**
- **Why use `GlassEffectContainer`?** Glass shapes inside one container render together and can blend and morph into each other.
- **Do apps get Liquid Glass without code changes?** Yes, standard bars, toolbars, and sheets adopt it automatically when built with the new SDK.
- **What did iOS 27 add on top?** `@State` became a macro that creates classes lazily once per view lifetime, `ViewBuilder` became `ContentBuilder` for faster builds, alerts and confirmation dialogs got item bindings, swipe actions and drag reordering work outside `List`, `AsyncImage` caches by default, and toolbars gained overflow and pinning controls.

### Q127. How do you adopt new APIs while supporting older iOS versions? `[Lead/Expert]`
I wrap availability checks in small modifiers, so call sites stay clean and the fallback can be deleted when the deployment target rises. The `if #available` inside a builder creates two identities, but that's fine because the OS version never changes at runtime.

```swift
extension View {
    @ViewBuilder
    func cardBackground() -> some View {
        if #available(iOS 26, *) {
            self.glassEffect(in: .rect(cornerRadius: 16))
        } else {
            self.background(.ultraThinMaterial, in: RoundedRectangle(cornerRadius: 16))
        }
    }
}
```

**Follow-ups:**
- **How do you decide the minimum iOS version?** With data: OS adoption among your users and the cost of supporting each old version.
- **What is the risk of many scattered `#available` checks?** Two code paths everywhere, which doubles testing and makes cleanup hard.
- **What does Swift 6.4 add for availability?** An `anyAppleOS` shorthand that covers all Apple platforms in one `@available` or `#if` check.

### Q129. `if/else` and state `[Senior]`

```swift
struct CounterView: View {

struct Parent: View {
```

**Question:** You tap the counter to 5, then flip the toggle. What does the counter show?

```swift
}
```
**Question:** Tap the child to 3, then tap the parent button. What does the child show?

**Answer:** `Child: 0`.
The parent's `body` re-runs and creates a new `Child` struct with a new `CounterModel`; fix it with `@StateObject`, or `@State` with `@Observable`.

**Follow-ups:**
- **Why doesn't the bug show up until the parent updates?** The model is only recreated when the parent re-runs `body` and builds a new `Child`.
- **Is `@ObservedObject` ever right with a default value?** No. A default value means the view creates the object, so it should own it with `@StateObject`.

### Q131. `@State` initialized from an input `[Senior]`
```swift
struct Greeting: View {
    @State private var name: String
    init(name: String) { _name = State(initialValue: name) }
    var body: some View { Text("Hello, \(name)") }
}

// Parent shows Greeting(name: selectedUser.name), then selectedUser changes from "Ana" to "Ben"
```
**Answer:** It still shows `Hello, Ana`.
`@State`'s initial value is used only the first time the view's identity is created; use a plain `let name: String`, a binding, or `.id(selectedUser.id)`.

**Follow-ups:**
- **Which fix would you choose here?** A plain `let`, because `Greeting` never changes the name.
- **When is `.id(selectedUser.id)` the better fix?** When the view has other local state that should also reset for a new user.

### Q132. How often does `init` run? `[Senior]`
```swift
struct Row: View {
    let title: String
    init(title: String) {
        self.title = title
        print("Row init")
    }
    var body: some View { Text(title) }
}
// Row is inside a parent whose body re-runs every time a @State timer ticks each second.
```
**Answer:** `Row init` prints every second.
View structs are recreated every time the parent's `body` runs, so initializers must stay trivial.

**Follow-ups:**
- **Does `Row`'s `body` also run every second?** Not necessarily; if `title` didn't change, SwiftUI can skip it.
- **How would you stop `Row` from being recreated?** Move the timer into a small separate view, so the parent's `body` no longer re-runs each second.

### Q133. Animation placement `[Lead/Expert]`
```swift
Circle()
    .fill(isOn ? .green : .red)
    .animation(.easeInOut, value: isOn)
    .scaleEffect(isOn ? 1.5 : 1.0)
```
**Question:** When `isOn` toggles (without `withAnimation`), what animates?

**Answer:** The color animates, but the scale jumps.
`.animation` only affects the modifiers above it in the chain, and `scaleEffect` comes after it.

**Follow-ups:**
- **How do you animate both?** Move `.animation(...)` below `.scaleEffect`, or toggle `isOn` inside `withAnimation`.
- **What if you wrap the change in `withAnimation(.spring)` too?** Both animate; the color uses `.easeInOut` from the closer modifier and the scale uses the spring.

### Q134. Localization surprise `[Senior]`
```swift
let key = "welcome_message"
Text("welcome_message")   // A
Text(key)                 // B
```
**Answer:** A is localized; B shows the raw text `welcome_message`.
A string literal becomes a `LocalizedStringKey`, but a `String` variable uses the initializer that doesn't localize.

**Follow-ups:**
- **How do you localize B?** `Text(LocalizedStringKey(key))`, or create the string with `String(localized:)`.
- **How do you show a literal that must never be translated?** `Text(verbatim: "welcome_message")`.

### Q135. Binding to an `@Observable` property `[Senior]`
```swift
@Observable final class Profile { var name = "" }

struct Editor: View {
    let profile: Profile
    var body: some View {
        TextField("Name", text: $profile.name)
    }
}
```
**Answer:** Compile error.
`$profile` doesn't exist for a plain property; declare it as `@Bindable var profile: Profile`.

**Follow-ups:**
- **Would the view still update if you only displayed `profile.name`?** Yes, a plain property is enough for reading and tracking.
- **What if `Editor` owned the profile?** Use `@State private var profile = Profile()`, which already provides `$profile.name`.

### Q136. Duplicate IDs `[Senior]`
```swift
let tags = ["swift", "ios", "swift"]
ForEach(tags, id: \.self) { Text($0) }
```
**Answer:** Undefined behavior.
SwiftUI logs a warning, and rows may show or update incorrectly because two rows share the identity `"swift"`.

**Follow-ups:**
- **How do you fix it if duplicates are valid data?** Wrap each tag in an `Identifiable` struct with its own stable ID.
- **Would `ForEach(tags.indices, id: \.self)` fix it?** It removes duplicates, but index identity breaks animations and state when the array changes.

### Q137. `onChange` on first appearance `[Fundamental]`
```swift
Text(filter)
    .onChange(of: filter) { print("changed") }
```
**Question:** Does it print when the view first appears?

**Answer:** No.
It only fires on later changes; use `.onChange(of: filter, initial: true)` to also run on appear.

**Follow-ups:**
- **Does it fire if `filter` is set to the same value?** No, the value must actually be different.
- **How do you get the old and new values?** Use the two-parameter closure: `{ oldValue, newValue in ... }`.

### Q138. `.task` and navigation `[Senior]`
```swift
List(model.items) { item in NavigationLink(item.name, value: item) }
    .task { await model.load() }
```
**Question:** The user opens a detail screen and goes back. What happens?

**Answer:** `load()` runs again.
`.task` runs on every appearance; guard with a "load if needed" check, or use `.task(id:)` with a meaningful value.

**Follow-ups:**
- **Is the first load cancelled when the user pushes the detail screen?** It can be, because the list disappears; handle `CancellationError` quietly.
- **When is reloading on return actually desirable?** When the detail screen can change the data, like editing an item.

### Q139. `GeometryReader` in a stack `[Senior]`
```swift
VStack {
    GeometryReader { proxy in
        Text("Width: \(proxy.size.width)")
    }
    Text("Footer")
}
```
**Answer:** The first text appears in the top-leading corner, and the footer is pushed to the bottom.
`GeometryReader` takes all available space and places its children at the top-leading corner; constrain it with `.frame(height:)` or use `onGeometryChange`.

**Follow-ups:**
- **How would you center the text inside the reader?** Add `.frame(maxWidth: .infinity, maxHeight: .infinity)` to the text.
- **How do you read the width without changing the layout?** Use `onGeometryChange`, or a `GeometryReader` in a `.background`.

### Q140. Fine-grained observation `[Lead/Expert]`
```swift
@Observable final class Cart {
    var items: [Item] = []
    var couponCode = ""
}

struct CartBadge: View {
    let cart: Cart
    var body: some View { Text("\(cart.items.count)") }
}
```
**Question:** Does `CartBadge`'s `body` re-run when `couponCode` changes?

**Answer:** No.
It only reads `items`; with `ObservableObject` and `@Published`, it would re-run, because any published change notifies every observer.

**Follow-ups:**
- **Does it re-run when an item is appended?** Yes, appending changes the `items` array, which the view reads.
- **What if the view read `couponCode` inside a button action?** Still no; reads inside actions aren't tracked as dependencies.

## 22. Senior / Lead Scenario Questions

> These have no single correct answer. Interviewers look at your reasoning, trade-offs, and communication, so start with the short answer, then explain the "why."

### Q141. A SwiftUI screen feels sluggish. Walk through how you'd fix it. `[Lead/Expert]`
First I reproduce and measure in a Release build on an older device with the SwiftUI instrument, Time Profiler, and Hitches. Then I find excess updates with `Self._printChanges()`, fix them by splitting views, narrowing inputs, moving to `@Observable`, stabilizing IDs, and moving work out of `body`, and finally I measure again and add a check so it doesn't regress.

```swift
// Before: one big view reads the whole store
struct FeedScreen: View {
    @ObservedObject var store: FeedStore
    var body: some View {
        let _ = Self._printChanges()          // step 2: find the cause
        List(store.posts) { PostRow(post: $0, store: store) }
    }
}

// After: rows get only what they show
List(store.posts) { PostRow(title: $0.title, likes: $0.likes) }
```

**Follow-ups:**
- **Why measure on an older device?** Problems that are invisible on the newest iPhone are often obvious on older hardware.
- **What do you look for in the SwiftUI instrument?** Views with many body updates or long update durations.
- **How do you prevent the problem from coming back?** Add performance tests or monitoring, and include performance in code review.

### Q142. Should a new app in 2026 be SwiftUI-first or UIKit-first? `[Lead/Expert]`
SwiftUI-first, with UIKit where needed, because most new Apple APIs like Observation, widgets, visionOS, and Liquid Glass are SwiftUI-centric. The deciding factors are the minimum iOS version, the team's skills, very custom or performance-critical screens, and existing UIKit code to reuse, and I plan clean interop from day one.

```swift
// SwiftUI app shell, with a UIKit screen where it earns its place
@main
struct ShopApp: App {
    var body: some Scene {
        WindowGroup {
            TabView {
                Tab("Home", systemImage: "house") { HomeView() }               // SwiftUI
                Tab("Scan", systemImage: "barcode") { ScannerView() }          // UIKit via representable
            }
        }
    }
}
```

**Follow-ups:**
- **What minimum iOS version makes SwiftUI-first comfortable?** iOS 17 or later, because Observation and the newer scroll and navigation APIs remove many old gaps.
- **When would you still go UIKit-first?** A team with deep UIKit expertise building very custom, performance-critical UI on an old deployment target.
- **How do you share design between both?** Design tokens in a package that both SwiftUI and UIKit code can use.

### Q143. Design the navigation for a large app with tabs, deep links, and authentication. `[Lead/Expert]`
A root view switches between the logged-out and logged-in flows based on session state. Inside, a `TabView` has one `NavigationStack` per tab, each with its own router and route enum, and a central deep link handler turns URLs into a tab plus a path, selecting the tab, dismissing sheets, and setting the path, or saving the link until after login.

```swift
struct RootView: View {
    @Environment(Session.self) private var session
    @State private var appRouter = AppRouter()   // owns selected tab + one router per tab

    var body: some View {
        Group {
            if session.isLoggedIn { MainTabView() } else { LoginView() }
        }
        .environment(appRouter)
        .onOpenURL { appRouter.handle($0, isLoggedIn: session.isLoggedIn) }
    }
}
```

**Follow-ups:**
- **How do you handle a deep link while logged out?** Store it as a pending link and replay it after login succeeds.
- **How are sheets handled?** With `sheet(item:)` bound to an enum of sheet destinations in the router.
- **How do you test it?** Unit test `AppRouter.handle` with URLs and assert the selected tab and paths, without UI.

### Q144. How would you choose a state management approach for a team of 10 engineers? `[Lead/Expert]`
I compare options like `@Observable` models with optional per-screen view models, TCA, or a small custom store, against criteria like app complexity, team experience, testability, deployment target, and onboarding speed. Then I run a short spike on one real feature, compare the results, record the decision in an ADR, and provide templates so everyone follows the same pattern.

```swift
// Template every new screen follows
@MainActor @Observable
final class <#Feature#>ViewModel {
    enum State { case idle, loading, loaded(<#Value#>), failed(String) }
    private(set) var state: State = .idle
    private let service: <#Service#>
    init(service: <#Service#>) { self.service = service }
}
```

**Follow-ups:**
- **What do you measure during the spike?** Readability, test coverage and effort, build times, and how fast someone new understands it.
- **How do you handle disagreement?** Decide on data from the spike, write it down, and agree to revisit after a set time.
- **How do you keep it consistent later?** Xcode templates, examples, and code review checklists.

### Q145. Your app supports iOS 16, but you want Observation and new APIs. What's your plan? `[Lead/Expert]`
First I check the data: how many users are on iOS 16 and what dropping it would cost the business. If iOS 16 must stay, I keep `ObservableObject` in shared code and put iOS 17+ features behind `#available` with fallbacks, avoiding two architectures long-term; then I set a clear date to raise the minimum and migrate to `@Observable` step by step (Q35).

```swift
if #available(iOS 17, *) {
    ContentUnavailableView("No Results", systemImage: "magnifyingglass")
} else {
    LegacyEmptyStateView(title: "No Results")
}
```

**Follow-ups:**
- **Why not maintain both `ObservableObject` and `@Observable` models?** It doubles the code and the bugs, and the team has to learn two patterns.
- **What data convinces stakeholders?** The share of active users and revenue on iOS 16, compared with the engineering time it costs.
- **What do you do on the day you raise the minimum?** Remove the `#available` fallbacks and start the planned `@Observable` migration.

### Q146. How would you build a design system in SwiftUI? `[Lead/Expert]`
I build a `DesignSystem` package with tokens for colors with Dark Mode, typography mapped to Dynamic Type text styles, spacing, and radii. I prefer styles like `ButtonStyle` over many components, add a few shared components like cards and empty states, pass the theme through `@Entry` environment values, and support it with a catalog app, snapshot tests, and DocC.

```swift
public enum DS {
    public enum Spacing { public static let s: CGFloat = 8; public static let m: CGFloat = 16 }
    public enum Font { public static let title = SwiftUI.Font.system(.title2, weight: .semibold) }
}

public extension ButtonStyle where Self == DSPrimaryButtonStyle {
    static var dsPrimary: DSPrimaryButtonStyle { .init() }
}

// Usage in a feature
Button("Continue") {}.buttonStyle(.dsPrimary).padding(DS.Spacing.m)
```

**Follow-ups:**
- **How do you make sure it's accessible?** Use scalable fonts and `@ScaledMetric`, check contrast, and include accessibility labels in components.
- **How do teams know which components exist?** A catalog app with previews of every component and state.
- **How do you support a hybrid UIKit app?** Expose the same tokens to UIKit, like `UIColor` and `UIFont` versions.

### Q147. How can memory leaks happen in SwiftUI, and how do you find them? `[Senior]`
Views are structs and can't leak, but reference types can: `@Observable` models storing closures that capture `self`, unstructured `Task`s that loop forever, timers, notification observers, Combine `sink`s, and singletons holding screen models. I find them with the Memory Graph Debugger, Instruments, `deinit` logs, and tests that check deallocation, and I prefer `.task` because it cancels automatically.

```swift
@MainActor @Observable
final class ChatModel {
    var messages: [Message] = []

    // ❌ Leaks: the loop never ends, and the task keeps the model alive
    func start() {
        Task {
            for await message in MessageStream.shared.messages {
                messages.append(message)
            }
        }
    }

    // ✅ Let the view own the lifetime instead
    func listen() async {
        for await message in MessageStream.shared.messages {
            messages.append(message)
        }
    }
}

// In the view: .task { await model.listen() }   // cancelled when the view disappears
```

**Follow-ups:**
- **Why is `.task` safer than starting a `Task` in `onAppear`?** `.task` is cancelled when the view disappears; a manual task keeps running until you cancel it.
- **Does `[weak self]` alone stop the loop above?** No. The loop keeps waiting on the stream; you must cancel the task.
- **How do you test that a model is freed?** Hold it in a weak variable, release the strong reference, and assert the weak one is `nil`.

### Q148. What do you look for when reviewing SwiftUI code? `[Lead/Expert]`
I check state ownership (the right wrappers, private `@State`, no inline `@ObservedObject`), identity (stable IDs, no `UUID()` in `body`), performance (no heavy work in `body` or `init`, small views, little `AnyView`), async code (`.task`, cancellation, `@MainActor` models), accessibility and localization, and testability (logic outside views, injectable dependencies, previews for each state).

```swift
// Review comments in practice
ForEach(items, id: \.self) { ... }           // ❓ are items unique? prefer Identifiable
@ObservedObject var model = Model()          // ❌ should be @StateObject or @State
.onAppear { Task { await load() } }          // ❌ use .task for auto-cancellation
Text(someString)                             // ❓ should this be localized?
```

**Follow-ups:**
- **Which issue do you treat as most serious?** Wrong state ownership, because it causes data loss and bugs that are hard to reproduce.
- **How do you avoid nitpicking?** Leave formatting to tools and focus comments on behavior, design, and correctness.
- **How do you teach these rules?** A written checklist, examples in the codebase, and short explanations in review comments.

### Q149. How would you explain SwiftUI view identity to a junior engineer? `[Senior]`
I'd say identity is like a seat number in a theater: if the same person stays in seat 12, SwiftUI updates them in place and they keep their memory, but if an `if/else` swaps them for a different person, the old one leaves with their state and a new one arrives. Then I'd show the counter-reset example (Q129) live and fix it with a ternary.

```swift
// "Different seats": state resets
if isHighlighted { CounterView().background(.yellow) } else { CounterView() }

// "Same seat": state kept
CounterView().background(isHighlighted ? Color.yellow : .clear)
```

**Follow-ups:**
- **What would you explain next?** `ForEach` IDs and `.id()` as explicit seat numbers you assign yourself.
- **How would you check they understood?** Ask them to predict what happens in a new example before running it.
- **What is the interviewer evaluating here?** Your ability to teach and communicate, not just your knowledge.

### Q150. How would you build an offline-first feed screen in SwiftUI? `[Lead/Expert]`
The UI reads only from a local store, like SwiftData, which is the single source of truth, while a repository syncs with the server in the background. The screen shows cached data immediately with a small refreshing indicator, sync uses cursor pagination, retries with backoff, and a conflict policy, and errors never wipe the cached content.

```swift
struct FeedView: View {
    @Query(sort: \Post.createdAt, order: .reverse) private var posts: [Post]   // local store only
    @Environment(FeedSync.self) private var sync

    var body: some View {
        List(posts) { PostRow(post: $0) }
            .overlay(alignment: .top) { if sync.isSyncing { ProgressView() } }
            .task { await sync.refresh() }        // writes into SwiftData, UI updates automatically
            .refreshable { await sync.refresh() }
    }
}
```

**Follow-ups:**
- **How do you handle changes the user makes while offline?** Save them locally and queue them in an outbox that syncs when the network returns.
- **How do you show that data might be old?** A "last updated" label or a subtle banner when the last sync failed.
- **How do you refresh in the background?** Schedule a `BGAppRefreshTask` that runs the same sync code.
