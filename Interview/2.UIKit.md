## 1. App Lifecycle & Scenes

### Q1. What are the possible app states? `[Fundamental]`
**Key points:**
- **Not running**: not launched or terminated.
- **Inactive**: in the foreground but not receiving events (e.g. incoming call overlay, Control Center, app switcher).
- **Active**: foreground and receiving events.
- **Background**: executing code but not visible (limited time unless using background modes).
- **Suspended**: in memory but not executing code; the system can terminate it silently to reclaim memory.

### Q2. What happens when an app launches? `[Senior]`
**Key points:**
1. The system creates the process and calls `main` (synthesized by `@main` on the app delegate).
2. `UIApplicationMain` creates the `UIApplication` singleton and the app delegate.
3. `application(_:willFinishLaunchingWithOptions:)` then `application(_:didFinishLaunchingWithOptions:)`.
4. With scenes: `application(_:configurationForConnecting:options:)`, then the scene delegate's `scene(_:willConnectTo:options:)` creates the window and root view controller.
5. The main run loop starts processing events.
- Launch-time tip: keep `didFinishLaunching` light; defer SDK initialization and heavy work.

### Q3. What is the difference between `AppDelegate` and `SceneDelegate`? `[Fundamental]`
**Key points:**
- **AppDelegate**: process-level events: launch, push notification registration, background URL sessions, scene configuration.
- **SceneDelegate** (iOS 13+): UI lifecycle per scene (window). An iPad app can have multiple scenes of the same app at once.
- When scenes are adopted, UI lifecycle callbacks like `applicationDidBecomeActive` are **not** called on the app delegate; the scene equivalents are.
- Apple has announced that the UIScene lifecycle will be required for apps built with SDKs after iOS 26, so legacy app-delegate-only apps need to migrate.

### Q4. Walk through the scene lifecycle callbacks. `[Fundamental]`
| Callback | When |
|---|---|
| `scene(_:willConnectTo:options:)` | Scene created; set up window and root VC; handle launch URLs/activities |
| `sceneWillEnterForeground(_:)` | Moving from background to foreground |
| `sceneDidBecomeActive(_:)` | Ready for interaction; restart paused tasks |
| `sceneWillResignActive(_:)` | About to become inactive; pause ongoing work |
| `sceneDidEnterBackground(_:)` | Now in background; save state, release shared resources |
| `sceneDidDisconnect(_:)` | Scene released by the system (may reconnect later); free resources |

### Q5. How do you set up a window programmatically without a storyboard? `[Fundamental]`
```swift
final class SceneDelegate: UIResponder, UIWindowSceneDelegate {
    var window: UIWindow?

    func scene(_ scene: UIScene,
               willConnectTo session: UISceneSession,
               options connectionOptions: UIScene.ConnectionOptions) {
        guard let windowScene = scene as? UIWindowScene else { return }
        let window = UIWindow(windowScene: windowScene)
        window.rootViewController = UINavigationController(rootViewController: HomeViewController())
        window.makeKeyAndVisible()
        self.window = window
    }
}
```
- Also remove `UIMainStoryboardFile` / the storyboard entry under `UISceneConfigurations` in Info.plist.

### Q6. How do you handle deep links and universal links with scenes? `[Senior]`
**Key points:**
- **Cold launch**: links arrive in `connectionOptions.urlContexts` / `connectionOptions.userActivities` inside `scene(_:willConnectTo:options:)`.
- **Warm (app running)**: `scene(_:openURLContexts:)` for custom URL schemes and `scene(_:continue:)` for universal links (`NSUserActivityTypeBrowsingWeb`).
- A common bug is handling only the warm path, so links do nothing on cold launch.

```swift
func scene(_ scene: UIScene, openURLContexts URLContexts: Set<UIOpenURLContext>) {
    guard let url = URLContexts.first?.url else { return }
    appCoordinator.handle(deepLink: DeepLink(url: url))
}

func scene(_ scene: UIScene, continue userActivity: NSUserActivity) {
    guard userActivity.activityType == NSUserActivityTypeBrowsingWeb,
          let url = userActivity.webpageURL else { return }
    appCoordinator.handle(deepLink: DeepLink(url: url))
}
```

### Q7. How do you get the key window now that `UIApplication.shared.windows` is deprecated? `[Senior]`
```swift
let keyWindow = UIApplication.shared.connectedScenes
    .compactMap { $0 as? UIWindowScene }
    .flatMap(\.windows)
    .first(where: \.isKeyWindow)
```
- Senior note: reaching for the global key window is often a smell. Prefer `view.window` or `view.window?.windowScene` from the current context, especially with multiple scenes on iPad.

### Q8. How do you restore UI state when a scene is recreated? `[Senior]`
**Key points:**
- Return an `NSUserActivity` from `stateRestorationActivity(for:)` in the scene delegate describing the current screen.
- On reconnect, read `session.stateRestorationActivity` in `scene(_:willConnectTo:options:)` and rebuild navigation.
- Keep the activity small (identifiers, not full models).

## 2. View Controller Lifecycle

### Q9. List the view controller lifecycle methods in order. `[Fundamental]`
| Method | Called | Typical use |
|---|---|---|
| `init` | Once | Inject dependencies |
| `loadView()` | Once, when `view` is first accessed | Create the root view programmatically |
| `viewDidLoad()` | Once | One-time setup: subviews, constraints, bindings |
| `viewWillAppear(_:)` | Every time it's about to appear | Refresh data, start observers |
| `viewIsAppearing(_:)` | Each appearance, after view is in hierarchy with correct traits and size | Geometry/trait-dependent updates, scrolling to a position |
| `viewWillLayoutSubviews()` | Possibly many times | Before subviews are laid out |
| `viewDidLayoutSubviews()` | Possibly many times | After layout; frames are final for this pass |
| `viewDidAppear(_:)` | After appearance animation | Start animations, analytics, video playback |
| `viewWillDisappear(_:)` | Before disappearing | Save edits, stop observers |
| `viewDidDisappear(_:)` | After disappearing | Stop expensive work |
| `deinit` | When deallocated | Final cleanup |

```swift
final class LifecycleViewController: UIViewController {
    override func loadView()                     { super.loadView(); print("loadView") }
    override func viewDidLoad()                  { super.viewDidLoad(); print("viewDidLoad") }
    override func viewWillAppear(_ a: Bool)      { super.viewWillAppear(a); print("viewWillAppear") }
    override func viewIsAppearing(_ a: Bool)     { super.viewIsAppearing(a); print("viewIsAppearing") }
    override func viewWillLayoutSubviews()       { super.viewWillLayoutSubviews(); print("viewWillLayoutSubviews") }
    override func viewDidLayoutSubviews()        { super.viewDidLayoutSubviews(); print("viewDidLayoutSubviews") }
    override func viewDidAppear(_ a: Bool)       { super.viewDidAppear(a); print("viewDidAppear") }
    override func viewWillDisappear(_ a: Bool)   { super.viewWillDisappear(a); print("viewWillDisappear") }
    override func viewDidDisappear(_ a: Bool)    { super.viewDidDisappear(a); print("viewDidDisappear") }
    deinit { print("deinit") }
}
```

### Q10. What is `viewIsAppearing(_:)` and why was it added? `[Senior]`
**Key points:**
- Added with the iOS 17 SDK and **back-deployed to iOS 13**.
- Called between `viewWillAppear` and `viewDidAppear`. At this point the view is in the window hierarchy, and its **trait collection and size are accurate**.
- In `viewWillAppear`, the view may not yet be in the hierarchy and traits/geometry may be stale, which caused subtle bugs. Apple recommends moving most `viewWillAppear` work here.

### Q11. When should you override `loadView()`? `[Senior]`
**Key points:**
- When you want a custom root view class (common in programmatic UI to move view code out of the controller).
- Assign `view` and do **not** call `super.loadView()` (super would try to load from a nib or create a plain view).
- Never call `loadView()` yourself.

```swift
final class ProfileView: UIView {
    let nameLabel = UILabel()
    // layout code lives here, not in the controller
}

final class ProfileViewController: UIViewController {
    private let contentView = ProfileView()

    override func loadView() {
        view = contentView
    }

    override func viewDidLoad() {
        super.viewDidLoad()
        contentView.nameLabel.text = "Taylor"
    }
}
```

### Q12. Why shouldn't you rely on view frames in `viewDidLoad`? `[Fundamental]`
**Key points:**
- The view hasn't been added to the window or laid out yet. With storyboards, frames reflect the storyboard's design device.
- Use Auto Layout so sizes don't matter, or do frame-dependent work in `viewDidLayoutSubviews` or `viewIsAppearing`.

### Q13. Which lifecycle methods can be called multiple times? `[Fundamental]`
**Key points:**
- `viewDidLoad` and `loadView`: once per view load.
- `viewWillAppear`, `viewIsAppearing`, `viewDidAppear`, and the disappear methods: every appearance.
- `viewWillLayoutSubviews` / `viewDidLayoutSubviews`: many times (rotation, size changes, any layout pass). Avoid adding subviews or constraints there, or you'll duplicate them.

### Q14. What does `isViewLoaded` do, and why does it matter? `[Senior]`
**Key points:**
- Returns whether the view has been loaded **without** triggering a load.
- Accessing `viewController.view` triggers `loadView` + `viewDidLoad` immediately, which can happen accidentally (e.g. setting a property whose `didSet` touches `view`).
- In tests, use `loadViewIfNeeded()` to deliberately trigger loading.

```swift
var user: User? {
    didSet {
        guard isViewLoaded else { return } // avoid loading the view too early
        nameLabel.text = user?.name
    }
}
```

### Q15. What is view controller containment? Show how to add and remove a child. `[Senior]`
**Key points:**
- Lets you compose screens from smaller view controllers, each with its own lifecycle (fights Massive View Controller).
- The correct sequence forwards lifecycle and trait events to the child.

```swift
extension UIViewController {
    func embed(_ child: UIViewController, in container: UIView) {
        addChild(child)                          // calls child.willMove(toParent: self)
        container.addSubview(child.view)
        child.view.translatesAutoresizingMaskIntoConstraints = false
        NSLayoutConstraint.activate([
            child.view.topAnchor.constraint(equalTo: container.topAnchor),
            child.view.bottomAnchor.constraint(equalTo: container.bottomAnchor),
            child.view.leadingAnchor.constraint(equalTo: container.leadingAnchor),
            child.view.trailingAnchor.constraint(equalTo: container.trailingAnchor)
        ])
        child.didMove(toParent: self)            // must be called manually
    }

    func detachFromParent() {
        willMove(toParent: nil)                  // must be called manually
        view.removeFromSuperview()
        removeFromParent()                       // calls didMove(toParent: nil)
    }
}
```

### Q16. How do you tell whether a view controller is being dismissed or popped vs just covered? `[Senior]`
```swift
override func viewDidDisappear(_ animated: Bool) {
    super.viewDidDisappear(animated)
    if isMovingFromParent || isBeingDismissed {
        // popped or dismissed: clean up, notify coordinator
    }
}
```
- `isMovingToParent` / `isBeingPresented` are the appearance equivalents.
- Coordinators often rely on this (or on `UINavigationControllerDelegate.didShow`) to remove child coordinators after a back-swipe.

### Q17. What happens with `didReceiveMemoryWarning` today? `[Fundamental]`
**Key points:**
- Since iOS 6, view controllers **don't unload their views** on memory warnings.
- Override it (or observe `UIApplication.didReceiveMemoryWarningNotification`) to purge caches. `NSCache` also evicts automatically under memory pressure.

### Q18. How do you check if a view controller's view is currently on screen? `[Fundamental]`
```swift
let isVisible = viewController.isViewLoaded && viewController.view.window != nil
```

## 3. UIView Fundamentals & the Update Cycle

### Q19. What is the difference between `frame`, `bounds`, and `center`? `[Fundamental]`
**Key points:**
- `frame`: position and size in the **superview's** coordinate system.
- `bounds`: position and size in the view's **own** coordinate system (origin usually `(0,0)`).
- `center`: the view's center in the superview's coordinates.
- If a `transform` is applied (rotation/scale), `frame` becomes the bounding box and shouldn't be set; use `bounds` and `center`.
- Changing `bounds.origin` shifts how subviews are drawn. This is exactly how `UIScrollView` scrolls (`contentOffset` == `bounds.origin`).

```swift
let v = UIView(frame: CGRect(x: 0, y: 0, width: 100, height: 100))
v.transform = CGAffineTransform(rotationAngle: .pi / 4)
print(v.bounds.size) // (100.0, 100.0)
print(v.frame.size)  // ≈ (141.4, 141.4): bounding box of the rotated view
```

### Q20. What is the relationship between `UIView` and `CALayer`? `[Senior]`
**Key points:**
- Every `UIView` is backed by a `CALayer` (`view.layer`) and acts as its delegate.
- The **layer** handles rendering, compositing, and animation (Core Animation). The **view** adds event handling, the responder chain, Auto Layout, and accessibility.
- Lightweight visual-only elements (e.g. many decorative shapes) can be plain `CALayer`s/`CAShapeLayer`s to avoid view overhead.
- Override `layerClass` to back a view with a specialized layer:

```swift
final class GradientView: UIView {
    override class var layerClass: AnyClass { CAGradientLayer.self }
    var gradientLayer: CAGradientLayer { layer as! CAGradientLayer }
}
```

### Q21. Describe the UIKit update cycle. `[Senior]`
**Key points:**
After event handling on each run loop iteration, UIKit performs three passes:
1. **Constraints pass** (bottom-up): `updateConstraints()` for views that called `setNeedsUpdateConstraints()`.
2. **Layout pass** (top-down): `layoutSubviews()` for views that called `setNeedsLayout()`; frames are set from constraints.
3. **Display pass**: `draw(_:)` for views that called `setNeedsDisplay()`.
Then Core Animation commits the layer tree to the render server.

| Mark dirty (deferred) | Force now (if dirty) | Override point |
|---|---|---|
| `setNeedsUpdateConstraints()` | `updateConstraintsIfNeeded()` | `updateConstraints()` |
| `setNeedsLayout()` | `layoutIfNeeded()` | `layoutSubviews()` |
| `setNeedsDisplay()` | (none; happens next cycle) | `draw(_:)` |

- Never call `layoutSubviews()`, `updateConstraints()`, or `draw(_:)` directly.

### Q22. What is the difference between `setNeedsLayout()` and `layoutIfNeeded()`? `[Fundamental]`
**Key points:**
- `setNeedsLayout()`: marks the view as needing layout; it happens on the next update cycle. Cheap and batches multiple changes.
- `layoutIfNeeded()`: performs any pending layout **immediately**, synchronously.
- Classic use of `layoutIfNeeded()`: animating constraint changes, or reading correct frames right after changing constraints.

### Q23. When would you override `layoutSubviews()`? `[Senior]`
**Key points:**
- Manual frame-based layout for performance-critical views, or to update things that depend on the final size (e.g. `shadowPath`, gradient layer frames, corner radius for circular views).
- Always call `super.layoutSubviews()`.
- Don't trigger another layout on the same view inside it (infinite layout loop).

```swift
final class AvatarView: UIImageView {
    override func layoutSubviews() {
        super.layoutSubviews()
        layer.cornerRadius = bounds.width / 2   // stays circular at any size
    }
}
```

### Q24. When should you override `draw(_:)`? `[Senior]`
**Key points:**
- For custom Core Graphics drawing (charts, custom shapes) that can't be done with subviews or layers.
- Drawing creates a backing bitmap the size of the view, which costs memory and CPU. Prefer `CAShapeLayer` for shapes that animate or change often.
- Trigger redraws with `setNeedsDisplay()`; set `contentMode = .redraw` if the view must redraw on bounds changes.

```swift
final class ProgressRingView: UIView {
    var progress: CGFloat = 0 { didSet { setNeedsDisplay() } }

    override func draw(_ rect: CGRect) {
        let center = CGPoint(x: bounds.midX, y: bounds.midY)
        let radius = min(bounds.width, bounds.height) / 2 - 4
        let path = UIBezierPath(arcCenter: center, radius: radius,
                                startAngle: -.pi / 2,
                                endAngle: -.pi / 2 + 2 * .pi * progress,
                                clockwise: true)
        path.lineWidth = 8
        UIColor.systemBlue.setStroke()
        path.stroke()
    }
}
```

### Q25. What is the difference between `isHidden`, `alpha = 0`, and `layer.opacity`? `[Fundamental]`
**Key points:**
- `isHidden = true`: not drawn, doesn't receive touches. Not animatable with `UIView.animate`. Still participates in Auto Layout (except inside `UIStackView`, which removes hidden arranged subviews from layout).
- `alpha = 0`: not visible and not hit-testable (alpha < 0.01), but **animatable**. Still in layout.
- `layer.opacity`: the layer equivalent of alpha.
- Common pattern: animate `alpha` to 0, then set `isHidden = true` in the completion.

### Q26. What do `clipsToBounds` and `masksToBounds` do? `[Fundamental]`
**Key points:**
- Same behavior (`clipsToBounds` is the view-level wrapper for `layer.masksToBounds`): subviews/content outside the bounds aren't drawn.
- Clipping also cuts off the layer's shadow, so a view can't easily have rounded clipped content and an outer shadow; use a container view for the shadow (see Q98).

### Q27. What is `contentMode`? `[Fundamental]`
**Key points:**
- Controls how a view's content (most often a `UIImageView` image) is laid out when the view's size differs from the content: `.scaleAspectFit`, `.scaleAspectFill` (usually with `clipsToBounds = true`), `.scaleToFill`, `.center`, `.redraw`, etc.

### Q28. How do you convert points and rects between coordinate spaces? `[Senior]`
```swift
// Where is the button in the view controller's root view?
let frameInRoot = button.convert(button.bounds, to: view)

// Convert a window-space rect (e.g. keyboard frame) into this view
let localRect = view.convert(keyboardFrameInScreen, from: nil) // nil = window
```

### Q29. What are `tintColor` and tint adjustment mode? `[Fundamental]`
**Key points:**
- `tintColor` is inherited down the view hierarchy unless overridden. System controls and template images use it.
- When a modal is presented, tint dims (`tintAdjustmentMode = .dimmed`). Override `tintColorDidChange()` in custom views to react.

### Q30. Why should you avoid using `tag` to find views? `[Fundamental]`
**Key points:**
- Tags are untyped integers, fragile, and `viewWithTag` searches the hierarchy at runtime.
- Prefer typed properties (stored references, outlets) or custom subclasses.

## 4. Auto Layout

### Q31. What is Auto Layout and how does it work internally? `[Senior]`
**Key points:**
- A constraint-based layout system: you describe relationships as linear equations (`item1.attribute = multiplier × item2.attribute + constant`) with priorities.
- An incremental solver (based on the Cassowary algorithm) computes frames. iOS 12 made common cases scale roughly linearly.
- Performance tips: create constraints once, change `constant` or toggle `isActive` instead of removing/recreating many constraints, and avoid needless constraint churn during scrolling.

### Q32. Why set `translatesAutoresizingMaskIntoConstraints = false`? `[Fundamental]`
**Key points:**
- By default UIKit converts a view's autoresizing mask into constraints. When you add your own constraints, these conflict and cause unsatisfiable layouts.
- Set it to `false` for views you position with constraints in code. Interface Builder does this automatically.

### Q33. Show programmatic constraints using anchors. `[Fundamental]`
```swift
let card = UIView()
card.translatesAutoresizingMaskIntoConstraints = false
view.addSubview(card)

NSLayoutConstraint.activate([
    card.leadingAnchor.constraint(equalTo: view.layoutMarginsGuide.leadingAnchor),
    card.trailingAnchor.constraint(equalTo: view.layoutMarginsGuide.trailingAnchor),
    card.topAnchor.constraint(equalTo: view.safeAreaLayoutGuide.topAnchor, constant: 16),
    card.heightAnchor.constraint(equalTo: card.widthAnchor, multiplier: 0.6)
])
```
- `NSLayoutConstraint.activate` is more efficient than setting `isActive` one by one, and it adds constraints to the correct common ancestor automatically.

### Q34. What is intrinsic content size? `[Fundamental]`
**Key points:**
- The natural size of a view based on its content: `UILabel` (text), `UIButton` (title + insets), `UIImageView` (image), `UISwitch` (fixed).
- With intrinsic content size, you only need position constraints; Auto Layout derives size.
- Custom views can override `intrinsicContentSize` and call `invalidateIntrinsicContentSize()` when content changes.

```swift
final class TagView: UIView {
    private let label = UILabel()

    var text: String = "" {
        didSet {
            label.text = text
            invalidateIntrinsicContentSize()
        }
    }

    override var intrinsicContentSize: CGSize {
        let labelSize = label.intrinsicContentSize
        return CGSize(width: labelSize.width + 16, height: labelSize.height + 8)
    }
}
```

### Q35. Explain content hugging and compression resistance. `[Senior]`
**Key points:**
- **Content hugging**: resistance to growing **larger** than intrinsic size. Higher = stays tight.
- **Compression resistance**: resistance to shrinking **smaller** than intrinsic size. Higher = less likely to truncate.
- Defaults: hugging `250` (`.defaultLow`), compression resistance `750` (`.defaultHigh`). Labels created in Interface Builder get hugging `251`.

**Example:** a row with a title (should truncate) and a date (must stay fully visible):
```swift
dateLabel.setContentHuggingPriority(.required, for: .horizontal)
dateLabel.setContentCompressionResistancePriority(.required, for: .horizontal)
titleLabel.setContentCompressionResistancePriority(.defaultLow, for: .horizontal)
```

### Q36. What are constraint priorities and how are they used? `[Senior]`
**Key points:**
- Range 1–1000. `1000` (`.required`) must be satisfied; lower priorities are optional and satisfied as closely as possible.
- You can't change a constraint between required and non-required while it's installed (it throws); choose priorities up front.
- Common pattern: a preferred size that yields to other constraints:

```swift
let preferredWidth = button.widthAnchor.constraint(equalToConstant: 320)
preferredWidth.priority = .defaultHigh          // try 320...
NSLayoutConstraint.activate([
    preferredWidth,
    button.widthAnchor.constraint(lessThanOrEqualTo: view.widthAnchor, constant: -32) // ...but never overflow
])
```

### Q37. What are ambiguous and unsatisfiable layouts? How do you debug them? `[Senior]`
**Key points:**
- **Ambiguous**: more than one solution (missing constraints), so views may jump or have zero size.
- **Unsatisfiable**: constraints conflict; UIKit breaks one at runtime and logs it.
- Debugging tools:
  - Xcode **View Debugger** (purple warnings, constraint inspection).
  - Symbolic breakpoint on `UIViewAlertForUnsatisfiableConstraints`.
  - Give constraints `identifier`s and views `accessibilityIdentifier`s so logs are readable.
  - `view.hasAmbiguousLayout` and `exerciseAmbiguityInLayout()` in the debugger.
  - Paste logs into tools like WTF Auto Layout to visualize.

### Q38. How do you animate constraint changes? `[Fundamental]`
```swift
heightConstraint.constant = isExpanded ? 300 : 100
UIView.animate(withDuration: 0.3) {
    self.view.layoutIfNeeded() // call on a common superview so all affected views animate
}
```
- Changing the constant schedules layout; `layoutIfNeeded()` inside the block performs it within the animation.
- Calling `layoutIfNeeded()` on the changed view itself rather than its superview is a common mistake that animates nothing.

### Q39. What are safe area, layout margins, and readable content guide? `[Fundamental]`
**Key points:**
- **`safeAreaLayoutGuide`**: area not covered by bars, notch/Dynamic Island, home indicator.
- **`layoutMarginsGuide`**: inset from edges for content spacing; use `directionalLayoutMargins` for RTL support.
- **`readableContentGuide`**: comfortable line length for text on wide screens (iPad).
- **`keyboardLayoutGuide`** (iOS 15): tracks the keyboard (see Section 15).

### Q40. How does `UIStackView` work? `[Fundamental]`
**Key points:**
- A non-rendering container that generates constraints for its `arrangedSubviews` based on `axis`, `distribution`, `alignment`, and `spacing`.
- Hidden arranged subviews are removed from layout, making show/hide animations easy.
- Use `addArrangedSubview` (not `addSubview`) and `setCustomSpacing(_:after:)`.
- Since iOS 14 a stack view can display a background color.

```swift
let stack = UIStackView(arrangedSubviews: [iconView, titleLabel, chevronView])
stack.axis = .horizontal
stack.alignment = .center
stack.spacing = 12
stack.setCustomSpacing(4, after: iconView)

UIView.animate(withDuration: 0.25) {
    self.detailLabel.isHidden.toggle()   // stack view animates the collapse
    self.stack.layoutIfNeeded()
}
```

### Q41. How do you make a self-sizing table or collection view cell? `[Senior]`
**Key points:**
- Constrain content to `contentView` with an unbroken chain from top to bottom.
- Table view: `rowHeight = UITableView.automaticDimension` (default since iOS 11) and a reasonable `estimatedRowHeight`.
- Collection view: compositional layout with `.estimated(...)` dimensions.
- Labels need `numberOfLines = 0`.

```swift
final class CommentCell: UITableViewCell {
    let bodyLabel = UILabel()

    override init(style: UITableViewCell.CellStyle, reuseIdentifier: String?) {
        super.init(style: style, reuseIdentifier: reuseIdentifier)
        bodyLabel.numberOfLines = 0
        bodyLabel.translatesAutoresizingMaskIntoConstraints = false
        contentView.addSubview(bodyLabel)
        NSLayoutConstraint.activate([
            bodyLabel.topAnchor.constraint(equalTo: contentView.layoutMarginsGuide.topAnchor),
            bodyLabel.bottomAnchor.constraint(equalTo: contentView.layoutMarginsGuide.bottomAnchor),
            bodyLabel.leadingAnchor.constraint(equalTo: contentView.layoutMarginsGuide.leadingAnchor),
            bodyLabel.trailingAnchor.constraint(equalTo: contentView.layoutMarginsGuide.trailingAnchor)
        ])
    }

    required init?(coder: NSCoder) { fatalError("init(coder:) has not been implemented") }
}
```

### Q43. When do you use `updateConstraints()`? `[Lead/Expert]`

### Q44. Auto Layout vs manual frames: when would you choose frames? `[Lead/Expert]`

## 6. UITableView & UICollectionView

### Q50. How does cell reuse work, and why does it exist? `[Fundamental]`
**Key points:**
- Creating views is expensive. Table/collection views keep a pool of off-screen cells per reuse identifier and recycle them as you scroll, so only roughly a screenful of cells exist.
- `dequeueReusableCell(withIdentifier:for:)` returns a recycled cell or creates one (after `register`).
- Consequence: a cell may still contain state from a previous item. **Every** `cellForRow` call must set all visible state.

### Q51. What should you do in `prepareForReuse()`? `[Senior]`
**Key points:**
- Reset **transient, non-content** state: cancel in-flight image requests, stop animations, reset selection/highlight effects.
- Apple's guidance: configure **content** in `cellForRow`/cell provider, not in `prepareForReuse`.
- Always call `super.prepareForReuse()`.

```swift
final class PhotoCell: UICollectionViewCell {
    private let imageView = UIImageView()
    private var loadTask: Task<Void, Never>?

    func configure(with url: URL, loader: ImageLoader) {
        loadTask = Task { [weak self] in
            let image = await loader.image(for: url)
            guard !Task.isCancelled else { return }
            self?.imageView.image = image
        }
    }

    override func prepareForReuse() {
        super.prepareForReuse()
        loadTask?.cancel()
        loadTask = nil
        imageView.image = nil
    }
}
```

### Q52. Why do images sometimes appear in the wrong cells, and how do you fix it? `[Senior]`
**Key points:**
- An async image request started for item A completes after the cell has been reused for item B, so A's image lands in B's cell.
- Fixes (combine them): cancel the request in `prepareForReuse`; check that the cell still represents the same item (compare an ID or URL) before setting the image; reset the image to a placeholder immediately when configuring.

### Q53. What is the difference between `dataSource` and `delegate` in table views? `[Fundamental]`
**Key points:**
- **Data source**: provides data: number of sections/rows, cells, headers titles, editing/moving support.
- **Delegate**: handles appearance and behavior: selection, row heights, header views, swipe actions, display callbacks.

### Q54. What is a diffable data source, and what problems does it solve? `[Senior]`
**Key points:**
- iOS 13 API: `UITableViewDiffableDataSource` / `UICollectionViewDiffableDataSource` with `NSDiffableDataSourceSnapshot<Section, Item>`.
- You describe the **desired state** with a snapshot; UIKit computes and animates the differences.
- Eliminates `NSInternalInconsistencyException` crashes from mismatched `insertRows`/`deleteRows` calls and counts.
- Items and sections must be `Hashable` and **unique** (duplicates crash).

### Q55. Show a diffable data source with cell registration. Should items be models or IDs? `[Lead/Expert]`
**Key points:**
- Apple recommends using **stable identifiers** (e.g. `UUID`) as item identifiers and looking up the model separately.
- If you use whole models, any property change makes the item look like a delete + insert, losing animations and cell state.
- With IDs, use `reconfigureItems` (iOS 15) to refresh changed content efficiently while reusing the existing cell.
- Create `CellRegistration` **outside** the cell provider closure (creating it inside throws on iOS 15+).

```swift
enum Section { case main }

struct Contact: Identifiable {
    let id: UUID
    var name: String
}

final class ContactsViewController: UIViewController {
    private var collectionView: UICollectionView!
    private var dataSource: UICollectionViewDiffableDataSource<Section, Contact.ID>!
    private var contactsByID: [Contact.ID: Contact] = [:]
    private var order: [Contact.ID] = []

    override func viewDidLoad() {
        super.viewDidLoad()
        let layout = UICollectionViewCompositionalLayout.list(
            using: UICollectionLayoutListConfiguration(appearance: .insetGrouped))
        collectionView = UICollectionView(frame: view.bounds, collectionViewLayout: layout)
        collectionView.autoresizingMask = [.flexibleWidth, .flexibleHeight]
        view.addSubview(collectionView)
        configureDataSource()
    }

    private func configureDataSource() {
        let registration = UICollectionView.CellRegistration<UICollectionViewListCell, Contact.ID> {
            [weak self] cell, _, id in
            guard let contact = self?.contactsByID[id] else { return }
            var content = cell.defaultContentConfiguration()
            content.text = contact.name
            cell.contentConfiguration = content
        }

        dataSource = UICollectionViewDiffableDataSource(collectionView: collectionView) {
            collectionView, indexPath, id in
            collectionView.dequeueConfiguredReusableCell(using: registration, for: indexPath, item: id)
        }
    }

    func show(_ contacts: [Contact]) {
        contactsByID = Dictionary(uniqueKeysWithValues: contacts.map { ($0.id, $0) })
        order = contacts.map(\.id)

        var snapshot = NSDiffableDataSourceSnapshot<Section, Contact.ID>()
        snapshot.appendSections([.main])
        snapshot.appendItems(order)
        dataSource.apply(snapshot, animatingDifferences: true)
    }

    func rename(id: Contact.ID, to name: String) {
        contactsByID[id]?.name = name
        var snapshot = dataSource.snapshot()
        snapshot.reconfigureItems([id])   // updates content, keeps the same cell
        dataSource.apply(snapshot, animatingDifferences: true)
    }
}
```

### Q56. What is the difference between `reloadItems` and `reconfigureItems`? `[Senior]`
**Key points:**
- `reloadItems`: dequeues a **new** cell for the item (and can lose state like text field focus or running animations).
- `reconfigureItems` (iOS 15): re-runs configuration on the **existing** cell. Faster and preserves cell state. Prefer it for content updates.

### Q57. What is compositional layout? Build a simple grid. `[Senior]`
**Key points:**
- iOS 13 layout built from **items → groups → sections**, each with size dimensions: `.fractionalWidth/Height`, `.absolute`, `.estimated`.
- Supports per-section layouts, orthogonal (horizontal) scrolling sections, supplementary views (headers), decoration views (section backgrounds), and list layouts.
- Replaces most custom `UICollectionViewFlowLayout` subclasses.

```swift
func makeGridLayout() -> UICollectionViewLayout {

        layoutSize: .init(widthDimension: .fractionalWidth(1.0), heightDimension: .absolute(180)),
        subitems: [item])
```

### Q71. How do you build a custom view controller transition? `[Lead/Expert]`
**Key points:**
- Provide an animator conforming to `UIViewControllerAnimatedTransitioning` via a `transitioningDelegate` (modal) or `UINavigationControllerDelegate` (push/pop).
- For interactive transitions, add `UIPercentDrivenInteractiveTransition` (or a custom `UIViewControllerInteractiveTransitioning`).
- **Always** call `completeTransition(_:)`, otherwise the UI freezes.
- `transitioningDelegate` is `weak`, so keep a strong reference to it.

```swift
final class FadeAnimator: NSObject, UIViewControllerAnimatedTransitioning {
    private let isPresenting: Bool
    init(isPresenting: Bool) { self.isPresenting = isPresenting }

    func transitionDuration(using context: UIViewControllerContextTransitioning?) -> TimeInterval { 0.3 }

    func animateTransition(using context: UIViewControllerContextTransitioning) {
        let duration = transitionDuration(using: context)

        if isPresenting, let toView = context.view(forKey: .to) {
            toView.alpha = 0
            context.containerView.addSubview(toView)
            UIView.animate(withDuration: duration, animations: { toView.alpha = 1 }) { _ in
                context.completeTransition(!context.transitionWasCancelled)
            }
        } else if let fromView = context.view(forKey: .from) {
            UIView.animate(withDuration: duration, animations: { fromView.alpha = 0 }) { _ in
                context.completeTransition(!context.transitionWasCancelled)
            }
        } else {
            context.completeTransition(false)
        }
    }
}

final class FadeTransitionDelegate: NSObject, UIViewControllerTransitioningDelegate {
    func animationController(forPresented presented: UIViewController,
                             presenting: UIViewController,
                             source: UIViewController) -> UIViewControllerAnimatedTransitioning? {
        FadeAnimator(isPresenting: true)
    }

    func animationController(forDismissed dismissed: UIViewController) -> UIViewControllerAnimatedTransitioning? {
        FadeAnimator(isPresenting: false)
    }
}

// Usage (keep transitionDelegate as a stored property)
let detail = DetailViewController()
detail.modalPresentationStyle = .custom
detail.transitioningDelegate = transitionDelegate
present(detail, animated: true)
```

### Q73. What is the Coordinator pattern? Implement a basic one. `[Senior]`
**Key points:**
- Moves navigation logic out of view controllers, so VCs don't know about each other. Improves reuse, testability, and deep-link handling.
- VCs/view models expose events (closures or delegates); the coordinator decides where to go.
- Child coordinators handle sub-flows (login, checkout) and must be removed when finished to avoid leaks.

```swift
protocol Coordinator: AnyObject {
    var childCoordinators: [Coordinator] { get set }
    func start()
}

final class ShopCoordinator: Coordinator {
    var childCoordinators: [Coordinator] = []
    private let navigationController: UINavigationController

    init(navigationController: UINavigationController) {
        self.navigationController = navigationController
    }

    func start() {
        let viewModel = ProductListViewModel()
        viewModel.onSelectProduct = { [weak self] product in
            self?.showDetail(for: product)
        }
        let list = ProductListViewController(viewModel: viewModel)
        navigationController.pushViewController(list, animated: false)
    }

    private func showDetail(for product: Product) {
        let detail = ProductDetailViewController(product: product)
        detail.onCheckout = { [weak self] in self?.startCheckout(for: product) }
        navigationController.pushViewController(detail, animated: true)
    }

    private func startCheckout(for product: Product) {
        let checkout = CheckoutCoordinator(navigationController: navigationController, product: product)
        checkout.onFinish = { [weak self, weak checkout] in
            self?.childCoordinators.removeAll { $0 === checkout }
        }
        childCoordinators.append(checkout)
        checkout.start()
    }
}
```

## 8. Touches, Gestures & the Responder Chain

### Q78. What is the responder chain? `[Fundamental]`
**Key points:**
- A chain of `UIResponder` objects (`UIView`, `UIViewController`, `UIWindow`, `UIApplication`, and the app delegate if it subclasses `UIResponder`) that events travel through.
- Typical path: view → superview → … → view controller (for its root view) → its view's superview → … → window → application → app delegate.
- Used for touches, motion events, remote control events, keyboard shortcuts, edit menu actions, and nil-targeted actions.

### Q79. How does hit-testing work? `[Senior]`
**Key points:**
- Hit-testing finds **which view** receives a touch (top-down). Then events and nil-targeted actions travel **up** the responder chain (bottom-up).
- `hitTest(_:with:)` ignores views that are hidden, have `isUserInteractionEnabled = false`, or alpha < 0.01; checks `point(inside:with:)`; then asks subviews in **reverse** order (frontmost first).

```swift
// Simplified version of UIView's default implementation
override func hitTest(_ point: CGPoint, with event: UIEvent?) -> UIView? {
    guard isUserInteractionEnabled, !isHidden, alpha > 0.01,
          self.point(inside: point, with: event) else { return nil }

    for subview in subviews.reversed() {
        let converted = subview.convert(point, from: self)
        if let hit = subview.hitTest(converted, with: event) {
            return hit
        }
    }
    return self
}
```

### Q80. How do you increase a button's tap area without changing its visual size? `[Senior]`
```swift
final class ExpandedHitButton: UIButton {
    var hitInset: CGFloat = -12

    override func point(inside point: CGPoint, with event: UIEvent?) -> Bool {
        bounds.insetBy(dx: hitInset, dy: hitInset).contains(point)
    }
}
```
- Apple's Human Interface Guidelines recommend at least 44×44 pt touch targets.

### Q81. How do you let touches pass through an overlay view to views below it? `[Senior]`
```swift
final class PassthroughView: UIView {
    override func hitTest(_ point: CGPoint, with event: UIEvent?) -> UIView? {

        return hit == self ? nil : hit   // subviews stay tappable; empty areas pass through
    }
```

### Q82. How do you tap a subview that extends outside its superview's bounds? `[Lead/Expert]`
**Key points:**
- The default hit test stops at the superview because the point is outside its bounds. Override the superview's `hitTest` (or `point(inside:)`) to also check that subview.

```swift
    let pointInBadge = badgeView.convert(point, from: self)
    if !badgeView.isHidden, badgeView.point(inside: pointInBadge, with: event) {
        return badgeView
    }
```

### Q83. How do gesture recognizers interact with touches and each other? `[Senior]`
**Key points:**
- Recognizers receive touches **before** the view. When one recognizes, it cancels the view's touches by default (`cancelsTouchesInView = true`).
- Discrete gestures (tap) go to `.ended`; continuous ones (pan, pinch) move through `.began`, `.changed`, `.ended`/`.cancelled`.
- Conflicts: `require(toFail:)` (single vs double tap), or the delegate method `gestureRecognizer(_:shouldRecognizeSimultaneouslyWith:)`.

```swift
let doubleTap = UITapGestureRecognizer(target: self, action: #selector(handleDoubleTap))
doubleTap.numberOfTapsRequired = 2

singleTap.require(toFail: doubleTap)   // wait to confirm it's not a double tap
imageView.addGestureRecognizer(doubleTap)
imageView.addGestureRecognizer(singleTap)
imageView.isUserInteractionEnabled = true   // UIImageView and UILabel default to false
```

### Q89. What is `UIViewPropertyAnimator`, and when would you use it over `UIView.animate`? `[Senior]`
**Key points:**
- An object-based animator that can be **paused, scrubbed (`fractionComplete`), reversed, and interrupted**, and lets you add animations or completions dynamically.
- Ideal for gesture-driven, interactive animations (e.g. a draggable panel or custom interactive transitions).

```swift
private var animator: UIViewPropertyAnimator?

@objc private func handlePan(_ gesture: UIPanGestureRecognizer) {
    switch gesture.state {
    case .began:
        animator = UIViewPropertyAnimator(duration: 0.4, curve: .easeOut) {
            self.panel.transform = CGAffineTransform(translationX: 0, y: -300)
        }
        animator?.pauseAnimation()
    case .changed:
        let progress = -gesture.translation(in: view).y / 300
        animator?.fractionComplete = max(0, min(1, progress))
    case .ended, .cancelled:
        let shouldReverse = (animator?.fractionComplete ?? 0) < 0.5
        animator?.isReversed = shouldReverse
        animator?.continueAnimation(withTimingParameters: nil, durationFactor: 0)
    default:
        break
    }
}
```

### Q90. What is the difference between a layer's model layer and presentation layer? `[Lead/Expert]`
**Key points:**
- The **model layer** holds the target values you set. The **presentation layer** (`layer.presentation()`) reflects what's currently on screen during an animation.
- A `CABasicAnimation` only changes the presentation; when it's removed, the layer snaps back to the model value.
- Correct approach: set the model value, then add the animation. Avoid the `fillMode = .forwards` + `isRemovedOnCompletion = false` hack, which leaves model and screen out of sync.
- Hit-testing a moving view uses the model frame, so to tap a moving view, hit-test against `layer.presentation()?.frame`.

```swift
let fade = CABasicAnimation(keyPath: "opacity")
fade.fromValue = 1
fade.toValue = 0
fade.duration = 0.3
layer.opacity = 0                // update the model first
layer.add(fade, forKey: "fade")  // then animate the presentation
```

### Q91. What are implicit and explicit animations in Core Animation? `[Lead/Expert]`
**Key points:**
- **Implicit**: changing an animatable property on a standalone `CALayer` animates automatically (0.25s).
- A `UIView`'s backing layer has implicit animations disabled outside `UIView.animate` blocks (the view returns `NSNull` as the action).
- **Explicit**: `CABasicAnimation`, `CAKeyframeAnimation`, `CASpringAnimation`, `CAAnimationGroup`.
- Disable implicit animations with `CATransaction.setDisableActions(true)`.

## 10. Core Animation & Rendering Performance

### Q95. Describe the rendering pipeline on iOS. `[Lead/Expert]`
**Key points:**
1. **Event**: your app handles touches, timers, network callbacks.
2. **Commit** (in your app, main thread): layout, display (drawing), prepare (image decoding), and committing the layer tree to the render server.
3. **Render** (render server process, GPU): render prepare and render execute produce the frame.
4. **Display**: the frame is shown at the next refresh (60 Hz, or up to 120 Hz on ProMotion devices).
- If any stage misses its deadline (≈16.7 ms at 60 Hz, ≈8.3 ms at 120 Hz), a **hitch** occurs: the previous frame stays on screen.
- **Commit hitches** come from your main-thread work; **render hitches** come from expensive layer trees (offscreen passes, many blended layers).

### Q96. What is offscreen rendering, and what causes it? `[Lead/Expert]`
**Key points:**
- The GPU must render a layer into a separate buffer before compositing it, which adds extra passes and can cause render hitches.
- Common causes:
  - Shadows **without** `shadowPath` (the GPU must work out the shape from content).
  - Masks (`layer.mask`) and `cornerRadius` with `masksToBounds` on layers with content/sublayers.
  - Group opacity (`allowsGroupOpacity`) on layers with sublayers and alpha < 1.
  - `shouldRasterize` (an intentional offscreen pass, cached).
  - Visual effect views (blur) are inherently expensive.
- Debug: Simulator **Debug → Color Off-screen Rendered**, Xcode View Debugger optimization hints, Instruments **Animation Hitches**.

### Q97. How do you add a shadow efficiently? `[Senior]`
```swift
card.layer.shadowColor = UIColor.black.cgColor
card.layer.shadowOpacity = 0.15
card.layer.shadowRadius = 8
card.layer.shadowOffset = CGSize(width: 0, height: 4)

// In layoutSubviews (so it follows size changes)
override func layoutSubviews() {
    super.layoutSubviews()
    layer.shadowPath = UIBezierPath(roundedRect: bounds, cornerRadius: 12).cgPath
}
```
- `shadowPath` tells Core Animation the shape upfront, avoiding offscreen work.

### Q98. How do you have rounded, clipped corners and a shadow on the same card? `[Senior]`
**Key points:**
- `masksToBounds = true` clips the shadow. Use two layers: an outer container with the shadow (no clipping), and an inner view with `cornerRadius` + `clipsToBounds`.
- `layer.cornerCurve = .continuous` gives Apple's smooth "squircle" corners.

```swift
let shadowContainer = UIView()
shadowContainer.layer.shadowOpacity = 0.15
shadowContainer.layer.shadowRadius = 8
shadowContainer.layer.shadowOffset = CGSize(width: 0, height: 4)

let contentView = UIView()
contentView.layer.cornerRadius = 16
contentView.layer.cornerCurve = .continuous
contentView.clipsToBounds = true
shadowContainer.addSubview(contentView)
```

### Q99. What does `shouldRasterize` do, and when is it useful? `[Lead/Expert]`
**Key points:**
- Renders the layer subtree once into a cached bitmap and reuses it.
- Helpful for complex but **static** content that moves around (e.g. translating a complex view).
- Harmful if the content changes often (re-rasterizes every frame) or for many layers (cache size is limited).
- Always set `layer.rasterizationScale = traitCollection.displayScale`, otherwise it looks blurry on Retina screens.

### Q100. What are blended layers, and why do they matter? `[Lead/Expert]`
**Key points:**
- Non-opaque layers require the GPU to blend pixels with what's beneath.
- Reduce blending by using opaque background colors where possible (e.g. labels on solid cell backgrounds) and avoiding unnecessary transparency.
- Visualize with **Color Blended Layers** in the Simulator's Debug menu.

### Q101. How would you diagnose a UI hang or hitch? `[Lead/Expert]`
**Key points:**
- Reproduce on a real (ideally older) device in a Release build.
- Instruments: **Time Profiler** (main-thread hot paths), **Animation Hitches**, **Hangs**, **Core Animation**.
- Xcode Organizer: hang rate and hitch rate reports from production; MetricKit for field diagnostics.
- Typical fixes: move work off the main thread, cache formatters and computed layouts, downsample images, reduce view hierarchy depth, remove offscreen rendering triggers.

## 11. Communication Patterns

### Q102. Compare delegation, closures, NotificationCenter, KVO, and Combine. `[Senior]`
| Pattern | Relationship | Best for | Watch out for |
|---|---|---|---|
| Delegation | One-to-one | Multiple related callbacks, data requests (`numberOfRows`) | Must be `weak`; protocol boilerplate |
| Closures | One-to-one | Single callbacks (completion, button tap) | Retain cycles with `self` |
| NotificationCenter | One-to-many, decoupled | App-wide events (keyboard, app lifecycle, logout) | Untyped `userInfo`; hard to trace; overuse |
| KVO | One-to-many | Observing ObjC/`NSObject` properties (`AVPlayer`, `WKWebView`) | Requires `@objc dynamic`; keep the observation token |
| Combine / Observation | One-to-many, streams | Reactive bindings (view model → view) | Memory management of subscriptions |

### Q105. How do you use NotificationCenter safely? `[Senior]`
**Key points:**
- Selector-based observers are automatically removed since iOS 9. Block-based observers return a token you must keep and remove, and their closures commonly capture `self` strongly.
- Prefer typed alternatives: `NotificationCenter.default.publisher(for:)` (Combine) or `notifications(named:)` as an `AsyncSequence`.

```swift
// Async sequence version, cancelled with the task

    for await _ in NotificationCenter.default.notifications(named: UIApplication.didBecomeActiveNotification) {
        self?.refresh()
    }
}
```
- Note: the `[weak self]` here still needs care, since the loop keeps running until the task is cancelled. Cancel `notificationTask` when the screen goes away.

## 12. Threading & the Run Loop

### Q107. Why must UI updates happen on the main thread? `[Fundamental]`
**Key points:**
- UIKit is not thread-safe; the main thread's run loop drives event handling, layout, drawing, and the Core Animation commit.
- Updating UI from a background thread causes undefined behavior: delayed updates, visual corruption, or crashes.
- Xcode's **Main Thread Checker** flags violations at runtime.
- In Swift Concurrency, `UIView` and `UIViewController` are `@MainActor`, so the compiler enforces main-actor access.

```swift
// Callback-based API
URLSession.shared.dataTask(with: url) { data, _, _ in
    let image = data.flatMap(UIImage.init(data:))
    DispatchQueue.main.async {
        self.imageView.image = image
    }
}.resume()

// Swift Concurrency: a Task created in a @MainActor view controller resumes on the main actor
Task {
    let (data, _) = try await URLSession.shared.data(from: url)
    imageView.image = UIImage(data: data)
}
```

### Q108. What is a run loop, and why does a `Timer` stop firing while scrolling? `[Senior]`
**Key points:**
- A run loop waits for and dispatches events (touches, timers, sources) on a thread. The main run loop runs in different **modes**.
- While scrolling, the main run loop switches to `.tracking` mode. Timers scheduled with `scheduledTimer` are added only to `.default` mode, so they pause.
- Fix: add the timer to `.common` modes.

```swift
let timer = Timer(timeInterval: 1, repeats: true) { [weak self] _ in
    self?.updateCountdown()
}
RunLoop.main.add(timer, forMode: .common)
self.timer = timer
```

### Q109. What is `CADisplayLink`, and when would you use it? `[Senior]`
**Key points:**
- A timer synchronized with the display refresh rate, for frame-by-frame updates (custom animations, games, progress tied to playback).
- `preferredFrameRateRange` (iOS 15) controls frame rate on ProMotion displays.
- It **retains its target**, so invalidate it when done (e.g. in `viewDidDisappear`), or use a weak proxy target.

### Q110. How do you keep the main thread responsive during heavy work? `[Senior]`
**Key points:**
- Move work off the main actor: `Task.detached`, a separate actor, a nonisolated async function, or `DispatchQueue.global`.
- Batch UI updates (one snapshot apply instead of many).
- Cache expensive objects (`DateFormatter`, `NumberFormatter`, attributed strings).
- Precompute layout or decode images in the background.

## 13. Memory Management in UIKit

### Q111. What are the most common sources of retain cycles in UIKit apps? `[Senior]`
**Key points:**
- Strong delegate properties.
- Closures stored by `self` that capture `self` (view model callbacks, cell action closures, `lazy var` closures).
- `Timer` with `target: self` or a strong closure, and `CADisplayLink`.
- Block-based `NotificationCenter` observers.
- Combine: `sink { self... }` stored in `self.cancellables`, or `assign(to:on: self)`.
- Child coordinators never removed from `childCoordinators`.
- Unstructured `Task`s with long-running loops capturing `self`.

### Q112. A view controller's `deinit` is never called. How do you debug it? `[Senior]`
**Key points:**
1. Confirm with a `deinit` log or a deallocation test.
2. Open the **Memory Graph Debugger**, find the VC instance, and inspect who holds a strong reference (purple "!" for detected leaks, but many cycles aren't auto-flagged).
3. Check the usual suspects from Q111.
4. Fix and verify with an automated leak test.

```swift
func assertDeallocated(_ object: AnyObject, file: StaticString = #filePath, line: UInt = #line) {
    addTeardownBlock { [weak object] in
        XCTAssertNil(object, "Potential memory leak", file: file, line: line)
    }
}
```

### Q113. How do you fix a Timer retain cycle? `[Senior]`
```swift
final class CountdownViewController: UIViewController {
    private var timer: Timer?

    override func viewDidLoad() {
        super.viewDidLoad()
        // Block-based API with weak self: the timer doesn't keep the VC alive
        timer = Timer.scheduledTimer(withTimeInterval: 1, repeats: true) { [weak self] _ in
            self?.tick()
        }
    }

    deinit {
        timer?.invalidate()   // the run loop still retains the timer until it's invalidated
    }

    private func tick() { /* update UI */ }
}
```

### Q114. Should `@IBOutlet`s be `weak` or `strong`? `[Senior]`
**Key points:**
- Xcode defaults to `weak`, because the view hierarchy already retains subviews.
- `strong` is fine and avoids surprises when you remove a view from the hierarchy and later re-add it.
- Outlets to **`NSLayoutConstraint`s you deactivate** should be strong. Deactivated constraints are released by their view, so a weak outlet becomes `nil`.
- Top-level objects in a nib (not part of the main view) must be strong.

## 16. Images & Scroll Performance

### Q123. Why can a small `UIImageView` showing a large image use lots of memory? `[Senior]`
**Key points:**
- Decoded image memory depends on **pixel dimensions**, not file size: width × height × 4 bytes (RGBA).
- A 4000×3000 JPEG (perhaps 2 MB on disk) takes about **48 MB** decoded, even in a 100×100 pt view.
- Fix: downsample to the display size before showing.

### Q124. How do you downsample an image efficiently? `[Lead/Expert]`
```swift
import ImageIO

func downsampleImage(at url: URL, to pointSize: CGSize, scale: CGFloat) -> UIImage? {
    let sourceOptions = [kCGImageSourceShouldCache: false] as CFDictionary
    guard let source = CGImageSourceCreateWithURL(url as CFURL, sourceOptions) else { return nil }

    let maxPixelSize = max(pointSize.width, pointSize.height) * scale
    let thumbnailOptions = [
        kCGImageSourceCreateThumbnailFromImageAlways: true,
        kCGImageSourceShouldCacheImmediately: true,      // decode now (do this off the main thread)
        kCGImageSourceCreateThumbnailWithTransform: true,
        kCGImageSourceThumbnailMaxPixelSize: maxPixelSize
    ] as CFDictionary

    guard let cgImage = CGImageSourceCreateThumbnailAtIndex(source, 0, thumbnailOptions) else { return nil }
    return UIImage(cgImage: cgImage)
}
```
- iOS 15+: `await image.byPreparingThumbnail(ofSize:)` and `byPreparingForDisplay()` decode in the background.

### Q125. Design an image loading and caching pipeline for a feed. `[Lead/Expert]`
**Key points:**
- **Memory cache**: `NSCache` keyed by URL + target size (auto-evicts on memory pressure).
- **Disk cache**: `URLCache` or a custom file cache with size limits and expiry.
- **Deduplication**: coalesce concurrent requests for the same URL (an actor holding in-flight tasks).
- **Decoding/downsampling** off the main thread; store decoded thumbnails in memory.
- **Cancellation** in `prepareForReuse` and prefetch cancellation.
- **Prefetching** via data source prefetching APIs.
- Mention trade-offs vs third-party libraries (Kingfisher, Nuke, SDWebImage).

```swift
actor ImageLoader {
    private let cache = NSCache<NSURL, UIImage>()
    private var inFlight: [URL: Task<UIImage?, Never>] = [:]

    func image(for url: URL) async -> UIImage? {
        if let cached = cache.object(forKey: url as NSURL) { return cached }
        if let existing = inFlight[url] { return await existing.value }

        let task = Task<UIImage?, Never> {
            guard let (data, _) = try? await URLSession.shared.data(from: url) else { return nil }
            return await UIImage(data: data)?.byPreparingForDisplay()
        }
        inFlight[url] = task
        let image = await task.value
        inFlight[url] = nil
        if let image { cache.setObject(image, forKey: url as NSURL) }
        return image
    }
}
```

### Q127. How do you react to trait changes in iOS 17+? `[Senior]`

### Q135. How does UIKit integrate with the Observation framework? `[Lead/Expert]`
**Key points:**
- UIKit can automatically track `@Observable` properties read inside update methods (`layoutSubviews`, `viewWillLayoutSubviews`, `updateConfiguration`, etc.) and re-run those methods when the properties change. No manual bindings or Combine needed.
- Introduced in iOS 18 behind the `UIObservationTrackingEnabled` Info.plist key; **enabled by default in iOS 26**.
- iOS 26 added `updateProperties()` on `UIView` and `UIViewController`. It runs before layout, and it's the recommended place to apply model values to views (trigger manually with `setNeedsUpdateProperties()`).

```swift
@Observable
final class CartModel {
    var itemCount = 0
}

final class CartBadgeViewController: UIViewController {
    private let model: CartModel
    private let badgeLabel = UILabel()

    init(model: CartModel) {
        self.model = model
        super.init(nibName: nil, bundle: nil)
    }

    @available(*, unavailable)
    required init?(coder: NSCoder) { fatalError() }

    override func updateProperties() {        // iOS 26
        super.updateProperties()
        badgeLabel.text = "\(model.itemCount)"  // tracked: changing itemCount re-runs this method
        badgeLabel.isHidden = model.itemCount == 0
    }
}
```

**Key points:**
- iOS 18: set `preferredTransition = .zoom` on the destination view controller to zoom from a source view (e.g. a photo cell) on push or present. It's interactive and interruptible.

```swift

    self?.thumbnailView(for: photo)   // return the view to zoom from
}
navigationController?.pushViewController(detail, animated: true)
```

### Q137. What changed in UIKit with iOS 26's design refresh? `[Senior]`
**Key points:**
- **Liquid Glass** material: navigation bars, tab bars, toolbars, and sheets adopt it automatically when built with the iOS 26 SDK.
- `UIGlassEffect` for custom glass surfaces via `UIVisualEffectView`; glass button configurations.
- Tab bars can minimize on scroll; scroll edge effects replace hard bar backgrounds.
- Practical impact: audit custom bar appearances and backgrounds that may now look wrong, and test both the new design and any compatibility mode.

### Q139. How do you embed a SwiftUI view in UIKit? `[Fundamental]`

### Q140. How do you use a UIKit view inside SwiftUI? `[Senior]`
**Key points:**
- `UIViewRepresentable` (views) / `UIViewControllerRepresentable` (view controllers).
- `makeUIView` creates once; `updateUIView` syncs SwiftUI state into UIKit (called often, keep it cheap and idempotent); `makeCoordinator` creates an object for delegates and target-action back into SwiftUI.

```swift
struct TextView: UIViewRepresentable {
    @Binding var text: String

    func makeUIView(context: Context) -> UITextView {
        let textView = UITextView()
        textView.font = .preferredFont(forTextStyle: .body)
        textView.adjustsFontForContentSizeCategory = true
        textView.delegate = context.coordinator
        return textView
    }

    func updateUIView(_ uiView: UITextView, context: Context) {
        if uiView.text != text {   // avoid resetting cursor position on every update
            uiView.text = text
        }
    }

    func makeCoordinator() -> Coordinator { Coordinator(text: $text) }

    final class Coordinator: NSObject, UITextViewDelegate {
        private var text: Binding<String>
        init(text: Binding<String>) { self.text = text }

        func textViewDidChange(_ textView: UITextView) {
            text.wrappedValue = textView.text
        }
    }
}
```


- Lighter than embedding a `UIHostingController` per cell, and it supports self-sizing and swipe actions.

### Q142. What is your strategy for migrating a large UIKit app to SwiftUI? `[Lead/Expert]`
**Talking points:**
- Incremental, not a rewrite: start with leaf screens and new features (settings, detail screens, onboarding) via `UIHostingController`.

- Watch for: hosting controller sizing, safe area handling, keyboard behavior, performance in long lists, and team upskilling.
- Define success metrics (crash rate, development speed) and the minimum iOS version that makes SwiftUI viable for your app.

## 20. Architecture & Testing in UIKit

### Q143. What is "Massive View Controller" and how do you avoid it? `[Senior]`
**Key points:**
- MVC in UIKit often puts networking, persistence, formatting, layout, navigation, and delegates all in one view controller.
- Cures (combine as needed):
  - **Custom root view** via `loadView` for layout code.
  - **View models / presenters** for state and formatting logic.
  - **Coordinators** for navigation.
  - **Child view controllers** for distinct screen regions.
  - Separate **data source** objects and **services** (networking, storage) injected via init.

### Q144. How do you bind a view model to a UIKit view controller? `[Senior]`
**Options:** closures, delegates, Combine, `AsyncSequence`, or Observation tracking (iOS 18/26, see Q135).

**Combine example:**
```swift
import Combine

final class LoginViewModel {
    @Published var email = ""
    @Published var password = ""

    var isLoginEnabled: AnyPublisher<Bool, Never> {
        Publishers.CombineLatest($email, $password)
            .map { email, password in email.contains("@") && password.count >= 8 }
            .removeDuplicates()
            .eraseToAnyPublisher()
    }
}

final class LoginViewController: UIViewController {
    private let viewModel = LoginViewModel()
    private var cancellables = Set<AnyCancellable>()
    private let emailField = UITextField()
    private let passwordField = UITextField()
    private let loginButton = UIButton(configuration: .filled())

    override func viewDidLoad() {
        super.viewDidLoad()

        emailField.addAction(UIAction { [weak self] _ in
            self?.viewModel.email = self?.emailField.text ?? ""
        }, for: .editingChanged)

        passwordField.addAction(UIAction { [weak self] _ in
            self?.viewModel.password = self?.passwordField.text ?? ""
        }, for: .editingChanged)

        viewModel.isLoginEnabled
            .receive(on: DispatchQueue.main)
            .assign(to: \.isEnabled, on: loginButton)   // OK: retains the button, not self
            .store(in: &cancellables)
    }
}
```
- Pitfall: `assign(to:on: self)` creates a retain cycle when the cancellable is stored on `self`. Use `assign(to: &$property)` or `sink` with `[weak self]`.

### Q145. How do you unit test a view controller? `[Senior]`
**Key points:**
- Inject dependencies (view model, services) through `init`.
- Call `loadViewIfNeeded()` to trigger `viewDidLoad`.

### Q147. What is snapshot testing, and when is it useful? `[Senior]`
**Key points:**
- Renders a view/view controller and compares it pixel-by-pixel (or as text) to a saved reference image. Popular library: `swift-snapshot-testing`.
- Great for catching visual regressions across Dynamic Type sizes, Dark Mode, RTL, and device sizes.
- Downsides: brittle across OS/simulator versions; pin the simulator and OS in CI.

### Q153. Constraint animation that doesn't animate `[Fundamental]`
```swift
UIView.animate(withDuration: 0.3) {
    self.heightConstraint.constant = 300
}
```
**Answer:** The view jumps to 300 with no animation. Changing a constant only marks layout as needed; layout happens later, outside the animation block. Change the constant before the block and call `view.layoutIfNeeded()` inside it.

### Q154. Changing `bounds.origin` `[Senior]`
```swift
let parent = UIView(frame: CGRect(x: 0, y: 0, width: 200, height: 200))
let child = UIView(frame: CGRect(x: 50, y: 50, width: 50, height: 50))
parent.addSubview(child)
parent.bounds.origin = CGPoint(x: 50, y: 50)
print(child.frame)
```
**Output:** `(50.0, 50.0, 50.0, 50.0)`. The child's frame doesn't change, but it now **appears** at the parent's top-left corner, because the parent's visible region starts at (50, 50). This is how scrolling works.

### Q155. Cell reuse bug `[Fundamental]`
```swift
func tableView(_ tableView: UITableView, cellForRowAt indexPath: IndexPath) -> UITableViewCell {
    let cell = tableView.dequeueReusableCell(withIdentifier: "Cell", for: indexPath)
    let item = items[indexPath.row]

    content.text = item.title
    cell.contentConfiguration = content
    if item.isFavorite {
        cell.backgroundColor = .systemYellow
    }
    return cell

```
**Answer:** After scrolling, non-favorite rows randomly appear yellow because reused cells keep the old color. Always set both branches: `cell.backgroundColor = item.isFavorite ? .systemYellow : .systemBackground`.

### Q156. Button inside an image view `[Senior]`
```swift
let imageView = UIImageView(image: banner)
```

### Q157. Hidden views: stack view vs plain view `[Fundamental]`
**Question:** You set `isHidden = true` on a view inside a `UIStackView`, and on a view pinned with constraints in a plain `UIView`. What happens to the layout?

**Answer:** In the stack view, the space collapses (hidden arranged subviews are removed from layout). In the plain view, the view is invisible but **still takes up space**, since its constraints remain active.

### Q158. Timer during scrolling `[Senior]`
```swift
timer = Timer.scheduledTimer(withTimeInterval: 1, repeats: true) { [weak self] _ in
    self?.secondsLabel.text = "\(self?.elapsed ?? 0)"
    self?.elapsed += 1
}
```
**Question:** What happens to the label while the user is scrolling a table view?

**Answer:** It freezes until scrolling stops, because the run loop is in `.tracking` mode and the timer is only scheduled in `.default`. Add the timer to `.common` modes.

### Q159. UI update from a background thread `[Fundamental]`

**Answer:** Undefined behavior. The update may appear late, not at all, or crash. The Main Thread Checker reports it, and in Swift 6 mode the compiler rejects it because `UILabel` is main-actor isolated.

### Q160. Users report the feed scrolls poorly on older devices. Walk through your approach. `[Lead/Expert]`

**Talking points:**
- Design tokens (colors, typography, spacing, radii) as a Swift package, with Dark Mode and Dynamic Type built in.
- Components configured with value types (like `UIButton.Configuration`): a `PrimaryButton`, `Card`, `EmptyStateView`.
- Accessibility by default (labels, traits, minimum touch sizes, scalable fonts).
- A gallery/catalog app and snapshot tests for every component state.
- Versioning, documentation (DocC), and a contribution process; SwiftUI counterparts sharing the same tokens.

### Q163. How do you support iPad multitasking and multiple windows? `[Senior]`
**Talking points:**
- Adopt scenes; support multiple scenes (`UIApplicationSupportsMultipleScenes`).
- Don't rely on `UIScreen.main` or global key windows; derive from `view.window?.windowScene`.
- Respond to size class and size changes (Split View, Slide Over, Stage Manager, resizable windows).
- Keep per-scene state separate; share data via a model layer, not view controllers.
- State restoration per scene with `NSUserActivity`.

### Q164. Your team of 10 is debating storyboards vs programmatic UI. How do you decide? `[Lead/Expert]`
**Talking points:**
- Gather the pain points: merge conflicts, review difficulty, DI needs, onboarding speed, design iteration speed.
- Consider a hybrid: programmatic for screens and navigation, XIBs for complex reusable views.
- Run a short pilot on one feature, compare, then write an architecture decision record (ADR).
- Plan migration gradually; don't stop feature work for a rewrite.

### Q165. Crash reports show "Invalid update: invalid number of items in section." How do you investigate? `[Lead/Expert]`
**Talking points:**
- Read the full exception: counts before and after, inserted and deleted.
- Look for updates to the data array without matching batch updates, updates from multiple async sources racing, or updates while the collection view isn't visible.
- Check threading: are model mutations happening off the main thread?
- Long-term fix: diffable data source with a single source of truth applied from the main actor.

### Q166. How would you reduce app launch time? `[Lead/Expert]`
**Talking points:**
- Measure: Instruments App Launch template, Xcode Organizer launch metrics, MetricKit.
- Pre-main: reduce dynamic frameworks (merge or make static; mergeable libraries in Xcode 15), remove unused code, avoid heavy `+load`/static initializers.
- Post-main: defer SDK setup and non-essential work until after the first frame; lazy-load services; keep the first screen simple; avoid synchronous disk/network on launch.
- Track launch time in CI to prevent regressions.

### Q167. What do you look for when reviewing UIKit code in a pull request? `[Lead/Expert]`
**Talking points:**
- Memory: weak delegates, capture lists in stored closures, timers and observers cleaned up.
- Threading: UI updates on the main actor; no blocking work on the main thread.
- Lifecycle correctness: no subviews added in `viewDidLayoutSubviews`, correct child VC containment.
- Reuse: cells fully configured; async work cancelled on reuse.
- Layout: no conflicting constraints, Dynamic Type and RTL friendly, safe areas respected.
- Accessibility: labels, traits, identifiers for tests.
- Testability and separation of concerns: logic outside the VC; dependencies injected.

### Q168. How would you explain the responder chain to a junior engineer? `[Senior]`
**Talking points:**
- Analogy: an office escalation path. A question goes to your direct manager first; if they can't answer, it goes up the chain until someone handles it.
- Show `UIApplication.shared.sendAction(... to: nil ...)` dismissing the keyboard from anywhere as a concrete example.
- Interviewers assess mentoring ability: clear analogy, small code example, then the "why it matters" (decoupling).

### Final Tips
- UIKit interviews for senior roles focus on **lifecycle edge cases, performance, memory, and architecture**, not just API names.
- Prepare **two or three war stories**: a nasty retain cycle, a scrolling performance fix, a crash you diagnosed. Explain the investigation, not just the fix.
- Be ready to **build a screen live, programmatically**, with Auto Layout anchors and a diffable collection view, without autocomplete.
- Know where UIKit and SwiftUI fit together; most companies hiring leads today have **hybrid codebases**.
